Cloudflare 发布了 Clef 和 Clef-flash 两款决策模型，直接对标 TypeSafe AI 的 Jev。这类模型不生成文本、只对预定义的答案选项输出概率，下游系统拿到分数就能自动执行。Cloudflare 在发布说明里说，对于 agent 的决策，人类不一定还需要留在环里。

决策模型填的是大语言模型和传统分类器之间的空档。大模型能推理也能调用工具，但输出不稳定、速度也慢；传统分类器够快，可每新增一个类别都要重新训练。决策模型一次调用就能回答关于同一段输入的多个预定义问题，给每个选项配上概率。拿客服工单举例，Clef 判断这单有多紧急、该交给哪个团队，下游代码据此派单或触发升级，拿不准时再转人工。

速度是这次发布主打的差异点。Cloudflare 自报在 43 项基准上都快过所有相关竞品，中位响应 Clef-flash 约 39 毫秒，Clef 约 209 毫秒，Jev 则刚过 524 毫秒。两个模型都直接跑在 Cloudflare 自家基础设施上，公司称靠近边缘数据中心带来了额外优势。基准分数同样来自官方自测，API Bank 上 Clef 得 91.93、Clef-flash 得 93.11、Jev 得 88.19；When2Call 上领先的仍是 Jev 的 80.97；PhishNChips 排第一的是 DiffusionGemma Jev 的 85.35。Cloudflare 还称 Clef 在自家排的 Jev Decision Index 上领先。

威胁情报团队已经在内测用 Clef 做网站分类。官方举的例子给一个域名打分，时尚网站 95%、网店 85%，钓鱼站的可能性不到 1%。抓取、渲染加分类全程 2.2 秒，而公司最快的通用语言模型跑完同样流程要 4.7 秒，还只给出两个类别。

规格方面，Clef 基于 Qwen3.8-27B，Clef-flash 基于更小的 Qwen3.5-9B。训练时基座保持冻结，Cloudflare 用自有合成数据训练额外组件，由这些组件从模型内部计算中导出答案选项和概率。训练方法采用自研版本的 RLCD，也就是 TypeSafe 训练 Jev 时用的校准决策强化学习，目标是让输出概率与答案实际正确的频率对齐。输入输出上，Clef 支持文本和图像，Jev 目前只吃文本；64K token 的上下文窗口能装下 Jev 两倍的输入。API 与 Jev 完全兼容，客户可以低成本切换。两款模型跑在 Workers AI 平台，权重以 Apache-2.0 许可挂在 Hugging Face。

配套的强化学习微调服务一同推出。客户先用 AI Gateway 记录线上请求来积累数据集，再放进充当 RL 沙箱的容器里评估，新的 trainer 组件负责把微调后的模型部署回 Workers AI，底层用到了 Cloudflare 在 2025 年底收购的 Replicate 的技术。前期由前置部署工程师团队带着客户做，自助平台在后续规划中。

Cloudflare 计划先在内部把 Clef 用起来，比如审核滥用报告和分拣支持请求，区分有用机器人和有害机器人也在这份清单上。对一家靠内容分发和安全服务起家的公司来说，这次因为自研 AI 模型站到了台前。

AI 代理读私信风波后，苹果收紧 Mac 完全磁盘访问

这是什么：苹果在周五面向开发者的更新中宣布，将为 macOS 的完全磁盘访问权限增加新控制，让用户只能以非常明确的主动操作授予这一权限，原话表述是 “very explicit user action”。TechCrunch 最先报道，The Verge 随后跟进并补充了 Meta 方面的回应细节。苹果没有公布控制的具体形式，也没有给出上线时间。
🔥 为什么今天值得看：这是苹果第一次把 AI 代理的能力增长写进收紧系统权限的官方理由。完全磁盘访问能触及文件、邮件乃至消息与浏览记录这类最私人的数据，接近 macOS 权限体系的顶层。桌面 AI 代理兴起后，这条原本服务备份工具的通道被越来越多的应用当作标配入口，操作系统层开始重新为 agent 时代设闸。

TechCrunch 与 The Verge 先后报道了同一条消息，苹果宣布将收紧 macOS 上的“完全磁盘访问”（Full Disk Access）权限。这份更新在周五发出，面向开发者。苹果在文中表示将推出新的控制，用来 “ensure that users who genuinely wish to grant an app this extraordinary level of access can only do so with very explicit user action”，翻译过来是，真正想把这种极高权限交给某个应用的用户，今后只能通过非常明确的主动操作完成授权。

声明的直接背景是 Meta 的 Muse 读私信风波。几周前，Inc. 专栏作家 Jason Aten 发现 Meta 的 Muse AI 知道他私信的内容，而他声称从未在 iPhone 或 Mac 上给这个助手授予过读取消息的权限。Meta 发言人 Andy Stone 随后两次回应该指控，先称对 Messages 的访问 “entirely opt-in”（完全出于用户自愿），接着补充说明，必须同时开启完全磁盘访问和 Messages 连接器，Muse 才可能读到消息内容。两方说法的差距恰好落在同一个问题上，即用户点下授权时究竟明白自己交出了什么。

苹果在更新中把矛头对准了开发者的用法。苹果写道：“Some developers are using Full Disk Access in ways that could put users at risk, exposing everything on their systems…without users’ full knowledge and understanding…”，并进一步判断 “As AI agents become increasingly capable and autonomous, the risks associated with this level of access will grow substantially.”。TechCrunch 拿到的完整声明里还有一句承诺，让用户在授予此类权限前清楚理解风险，以便对自己的数据和隐私做出知情决定。

完全磁盘访问并不是新东西。按苹果自己的说明，这项权限 “largely sidesteps”（基本绕过）了系统提供给用户的隐私控制，设计初衷只是让备份应用能在 Mac 上正常工作。这样一条为备份工具留出的通道，如今被越来越多需要在本地读文件、读消息的 AI 代理类应用当作常规入口来申请。TechCrunch 的报道还提到，此前 Wired 曾披露 ChatGPT 的 Mac 应用存在一个可能让攻击者接触到敏感数据的漏洞，桌面 AI 应用的权限问题在几周内被反复推上风口。

也要看清这次声明的边界。苹果没有说明新的控制会以什么形式呈现，没有给出时间表，The Verge 与 TechCrunch 的置评请求也都未获回应。从表态到真正落进 macOS 的设置界面，中间还有相当一段距离。对在 Mac 上做 AI 代理与备份工具的开发者来说，授权链路变长已是可预期的方向，剩下的悬念在于确认流程会被做到多强。

OpenAI 出 GPT-6 选型指南，缓存最高省 95%

这是什么：OpenAI 于 10 月 2 日发布 GPT-6 家族官方模型指南，距 9 月 29 日 DevDay 推出 GPT-6.1 Sol 仅三天，属于配套工程文档。首次成文披露的细节包括缓存输入 token 最高 95% 的折扣与 stable-first 写法、推理强度四档可在对话中途调整且不破坏缓存、仅对 Astra 开放的 Ultrafast 速度档、GPT-6.1 Sol 在 Responses API 中的多智能体 beta、经 Responses WebSocket API 实现的 mid-turn steering，以及 Harvey、Cognition、Hex、Invideo 的 Astra 落地案例。
🔥 为什么今天值得看：本期日报的主线是 agent 的信任与成本基础设施，这篇稿件承担开发者实用主菜的角色。GPT-6 三档模型把智能与价格的权衡显性化，选错档位的浪费会随调用量成倍放大，指南里的模型匹配、推理强度调节与缓存写法都是即取即用的手段，输入 token 最高 95% 的折扣直接决定大规模重复任务的经济性。mid-turn steering、异步工具调用与多智能体委派回应的则是 agent 从分钟级走向小时天级之后的可控性问题，和本期其他稿件关心的「agent 自主性变强之后谁来把关」形成呼应。
展开正文

从 9 月下旬 GPT-6 Sol 与 Luna 上市补齐档位，到 DevDay 发布 GPT-6.1 Sol，模型货架摆满之后，开发者面前的问题换了模样。三档模型摆在货架上，什么任务该用哪一档，账单怎么压下来，官方一直没有系统的说法。10 月 2 日 OpenAI 在博客放出 GPT-6 家族模型指南，从选型、调参一路写到长任务管理和生产准备，通篇是给动手的人看的工程手册。

选型的第一层是挑模型。指南给三档模型划了分工。GPT-6 Astra 承担最难的推理工作，需要最高智能的任务交给它。GPT-6.1 Sol 面向复杂编码、研究和计算机操作。GPT-6 Luna 干的是目标明确的规模化重复活，比如提取发票字段、给请求分类、生成结构化摘要。官方把模型选择连同推理强度一起称作智能与价格的权衡，核心思路是按任务难度花钱，而按任务定价的第一步，就是别拿 Astra 去跑发票提取。

第二层旋钮是推理强度。API 里这一参数从 Low 到顶格的 Extra high 与 Max 共四档。Low 档对付提取事实、小改小补这类常规活。Medium 往上走一层，规划一个功能、比较几个方案这类需要判断力的工作归它。High 档留给难缠的调试、深度分析和仔细审查。顶上的 Extra high 与 Max，官方态度克制，建议只在 High 不够用且模型支持的场合试验，确认提升配得上多花的时间和成本再保留。指南还标注了一个容易被忽略的工程细节，推理强度允许在对话中途调整，缓存不受影响。

速度是第三层。API 的 Fast mode 用更高的每 token 单价换取更快更稳的响应，适合聊天应用和编码工具这类对延迟敏感的场景。Ultrafast 走得更远，加速的是 token 生成本身，与推理强度互不影响，在 Codex 和 API 里都能用，眼下只对 GPT-6 Astra 开放，适合愿意为快速编码迭代支付溢价的团队。

三层选完，账单上还有后手，缓存是最大的一个。官方数字是缓存命中的输入 token 最多比未缓存便宜 95%，具体幅度随模型而异。写法上有讲究，稳定的指令和参考资料要放在易变的任务细节前面，工具定义保持一致，前缀对得上缓存才吃得着。指南同时提醒，估算整个工作流的成本时要把缓存写入和长上下文费率一并计入，缓存面板和诊断工具能看出复用在哪里断掉。更长的对话则交给 compaction 处理，在保留继续任务所需状态的前提下压缩上下文。

GPT-6 家族把任务时长拉到了小时甚至天级，配套的管理手段里 mid-turn steering 最抓眼球。它允许你在模型干活时通过 Responses WebSocket API 发送修正，更新排队生效，既不取消正在运行的工具，也不撤销已完成的动作。异步工具调用解决等待问题，应用去跑测试这类慢任务时，模型接着做不依赖结果的工作，结果回来后再启动依赖它的部分。GPT-6.1 Sol 在 Responses API 里支持多智能体工作流，目前处于 beta，可以把相互独立的子任务分给子代理，比如让它们分别调查代码库的不同部分，最后汇成一份结论。在 Codex 里配 GPT-6 Astra，模型还能在干活中途向你提问，你不在时也可以事先说明哪些任务能继续、哪些要停下来等答复。

提示词的写法也在换思路。OpenAI 开发者体验工程师 Eric Provencher 在指南里的原话是：“Models have gotten much better at understanding nuance and ambiguity, so overly specific guidance can now hinder results where it previously helped.” 模型对含糊和细微语义的理解已经大幅变强，过去管用的过度具体指令，现在反而可能拖累效果。指南建议把力气花在交代结果给谁、约束是什么、什么算完成，并划清决策边界，用明确的授权范围替换一刀切的「总是先问」，AGENTS.md 也值得同步更新，写清哪些文档和测试在什么时机相关。

三个模型都支持 computer use，可以直接操作没有 API 的网站和桌面应用，比如让模型查一个 bug、改完代码，再打开浏览器验证修复是否生效。官方建议每一步选最简单可靠的路，能走 API 或现成工具就别碰屏幕，需要读屏、点按钮、填表单时才动用 computer use。自己搭建的话，浏览器场景配 Playwright，桌面应用配 PyAutoGUI。

生产侧指南给出一串检查项，先跑代表性任务，量任务成功率、延迟和每成功任务成本，监控和数据处理策略也要提前想好。落地样本里，Harvey 把法院信息、判例、律所文档和律师偏好一起喂给模型来定制草稿，联合创始人 Gabe Pereyra 的说法是：“We can give more context to the model and produce better and better structured outputs.” Cognition、Hex 和 Invideo 也在基于 Astra 做各自的生产验证。

这份指南透露的真实信号，是模型能力层面的差距在收敛，工程纪律开始决定一套 agent 系统的性价比。模型档位、推理强度和缓存写法这几层旋钮都拧到位，同一套 GPT-6 在不同团队手里会跑出完全不同的成本结构。

MIT 与 Sakana AI 用 LLM 评审压低自改进代理的评估成本

这是什么：MIT 与 Sakana AI 研究者提出 SIFT（Recursive Self-Improvement via Fast Tree Search）框架，10 月 2 日经 VentureBeat 报道公开，论文图源 arXiv。它在昂贵的基准评估前插入 LLM 成对评审加 Bradley-Terry 排名，并以异步树搜索让补丁生成、评审和评估并行推进。Polyglot 基准上 o3-mini 运行达 35.1% 准确率（DGM 为 30.7%，去掉评审降至 29.8%），单次运行 5 小时内完成，耗费 42 CPU 小时和约 150 美元 API 费用。论文未提供独立开源实现。
🔥 为什么今天值得看：评估成本是自改进循环的真正瓶颈。按论文拆解，提出一个补丁约 12 美分，50 个 Polyglot 任务的完整评估约 6 美元加 2.6 CPU 小时，全量搜索动辄数千 CPU 小时，小任务集则信号容易被运气污染。SIFT 证明便宜的代码级评审信号配合异步搜索，可以少花钱多探索，对在明确任务上调编码代理 harness 的团队是可直接借鉴的路线，也是本期 agent 成本线的研究侧证据。前提同样要记住，评审只是启发式排序信号，与真实表现的对齐是方法成立的前提，下游基准确认不可省略。

让编码代理自己改自己，想法诱人，账单吓人。候选改动每一个都要上基准测试，在候选之间搜一遍，动辄消耗几千个 CPU 小时和几千美元。MIT 与 Sakana AI 研究者提出的新框架 SIFT（Recursive Self-Improvement via Fast Tree Search）冲着这笔评估开销去，思路是在昂贵的基准测试前面加一道便宜的筛选，让一个独立的大语言模型先比较候选代理的优劣，再决定哪几个值得花真金白银去测。在 Polyglot 编码基准上，使用 o3-mini 的一次 SIFT 运行在 5 小时内跑到 35.1% 的准确率，总共只花了 42 个 CPU 小时和约 150 美元的 API 费用。

先补一点背景。递归自我改进指代理检查自己的失败，给自己的 harness 打补丁，改完再跑任务，用得分决定哪个版本成为下一轮修改的起点。因为补丁改的是之后提出和执行修改的系统本身，改进可以层层叠加。问题出在测试上。按论文的成本拆解，提出一个补丁约 12 美分，在 50 个 Polyglot 任务上完整评估一个代理约 6 美元加 2.6 个 CPU 小时。在几个任务上快速测一把很便宜，但分数容易被运气污染，候选可能刚好抽到特别容易或特别难的题；把测试集加大，信号更可靠，时间和钱也跟着涨。论文作者的判断是：“瓶颈在于现有评估方法糟糕的信号成本比。”

此前的两条路线都在任务集上做渐进文章。Darwin Gödel Machine（DGM）维护一个代理档案，先在 10 个任务上筛候选，再扩到 50 个，完整 Polyglot 留到最后评估。Huxley-Gödel Machine（HGM）在选搜索方向时会考虑一个代理连同它后代的表现，评估用的随机任务数也在变。SIFT 换了个位置下手，把便宜的判断信号直接插进搜索过程。

SIFT 沿用 DGM 的 harness。生成一个改动后的代理后，先让它跑 4 个编码任务，把会让代理崩溃、连基本题都做不动的改动提前拦下。接下来轮到 LLM 评审出场，这种做法通常叫 LLM-as-a-judge，也就是让一个语言模型以裁判身份比较两份实现，判断哪个更可能表现更好。评审只看代理的代码，看不到基准任务和结果。它把新代理与档案里最多 10 个高排名代理两两对比，每次比较约 4.4 美分，一个候选最多四毛钱上下。论文拿招聘作类比，这接近让招聘经理在终面候选人里挑人，比打一个百分制的绝对分容易下手。这些成对胜负再用 Bradley-Terry 模型汇总成排名，这个统计方法的用途就是从胜负记录里估计各方的相对强弱，棋类和电竞天梯常用它。排名不替代测试，它决定的是昂贵测试排队时的优先级，优先级同时参考评审排名和基准准确率排名。

异步是提速的另一半。补丁生成、评审和基准评估并行推进，有点像 CI 流水线里长测试挂在后台跑，有前景的候选不必等自己的昂贵评估结束就能派生子代。选父节点时综合评审排名、搜索任务集上的准确率排名和历史被选次数，还在排队等评估的候选暂时继承父代的准确率，被选过多次的分支会降权，给其他分支留出探索空间。

实验结果撑住了这个赌注。Polyglot 上无论用开源的 Qwen3-Coder-30B 还是闭源的 o3-mini，SIFT 都以更少算力拿到更高准确率，前者小胜 HGM 且 CPU 小时省下约三分之一，后者跑到 35.1%，DGM 是 30.7%。把 LLM 评审拿掉的对照只有 29.8%，说明增益确实来自这道筛选。TerminalBench 2.1 上的案例更能说明评审看到了搜索得分看不到的东西。搜索阶段评审的首选解了 50 题中的 18 题，得分最高的那个解了 19 题，换到完整基准的多次运行里，评审首选平均 36.7%，得分最高者只有 28.1%。评审从代码里看出，后者的新验证器默认处于禁用状态，重写的 shell 工具还有运行时风险。SWE-bench Verified 的 60 任务子集上方向一致但差距没那么干净，评审选出的两个代理四轮平均 50.4% 和 53.8%，无评审版本选出的两个是 44.6% 和 50.4%，起点代理为 40.0%。还有个耐人寻味的案例，候选 Node 9 只加了一句“编辑后运行测试”的指令和一个返回结构化失败信息的 test_runner 工具，它的后代堆上更多机制，两个版本在搜索测试里都解了 44% 的任务分不出高下，完整 Polyglot 上简单版 35.6%，复杂版 33.8%，而评审早就把简单版排在了前面。

要交代的前提也写得很清楚。评审是一个启发式信号，这套方法成立的前提是评审的排序与真实基准表现大体对齐，论文也强调下游基准仍然不可省，改动是否真的有效最终要靠它们确认，研究者自己还得封掉那些试图放宽评估 harness 的作弊补丁。实验只在编码代理上做过。论文没有给出独立的 SIFT 实现，好在它建立在 DGM harness 之上，手里有 DGM 实现的团队已经有生成改动、维护候选档案和评估表现这条主干，要补的主要是成对评审、Bradley-Terry 排名和异步化。评审模型本身也有优化空间，研究发现更便宜的评审在 TerminalBench 上保留了大部分全局排序信号，只是在最顶尖的候选之间不如更强的模型可靠，分层配置值得一试，粗筛交给便宜的，决胜留给强的。对在明确任务上调编码代理 harness 的团队，SIFT 给出的启示是把昂贵的评估花得更有选择性。

10 月 2 日，agent-wow 项目的作者在博客上公布了第一次实验记录。他把 Codex 上的 GPT-6 Astra（xhigh 推理档）放进《魔兽世界》，指令只有一句话，「create an orc character and complete all quests in the starting zone」，创建一个兽人角色，完成新手村的全部任务。作者原本估计要跑上几个小时，途中还会多次卡死，结果 agent 用 40 分钟清完全部任务，零死亡，几乎没有波折，全程录像和推理轨迹都已公开。

这次实验跑在用开源 AzerothCore 搭建的本地私服上，版本停在 WoW 3.3.5a，巫妖王之怒的最终版本，与暴雪官方服务器没有任何关系。有信息量的部分在于 agent 自己长出的三套策略，它们比「模型会打游戏」这个结论本身具体得多。

第一套策略是挖私服源码。agent 从 AzerothCore 的 SQL 文件里提取任务要求、发任务和收任务的 NPC、怪物刷新坐标，给自己拼出一张带定位的清单，再据此规划任务顺序。它会先补完前置任务链，卖掉垃圾换上更好的装备，进洞穴前把两个任务一起接了、一起交。作者认为这接近人类玩家泡在 Wowhead 上查攻略的行为，同时划了红线，这次运行没有做沙箱隔离，理论上 agent 能拿到服务器管理员权限去改数据库，那一步越过去就是作弊。

第三套是寻路，这也是启发式机器人二十多年来的老大难。agent 现写了一个 C++ 程序，加载 AzerothCore 本地的导航网格文件，调用 Detour 库在相互连通的可通行表面之间算出路线，把路点以 JSON 返回，再由脚本按点发送移动数据包。录像里能看到这个方案的副产品，角色径直穿过了墙，作者判断是撞上了地图碰撞缺失的老 bug。

平台设计本身同样有来历。agent-wow 把 WoW 网络协议和一套模块系统直接交给 agent，移动、战斗这些游戏机制一概不预设，计算机视觉、键鼠模拟、客户端内存读写都不在方案里。这个取舍是被 1.6 万行失败代码逼出来的，作者最初想做面向 agent 的无头客户端，写出一个满是 bug 的移动原语后推倒重来，转而参考 Mindcraft 的思路让模型自己构建需要的能力。他的终局目标很有画面感，用 agent 填满一整个服务器，看它们能不能打穿英雄难度的冰冠堡垒，失败了也算收获。

限制需要交代得同样清楚。私服意味着这套结果无法外推到官方服务器的反作弊环境，3.3.5a 也是 2010 年的老客户端。下一步作者计划让单个 agent 全程自主冲 80 级，再让多个 agent 组队下副本，并为长时间运行补上观测工具。HN 讨论里最尖锐的质疑也指向这里，一个未定制的通用模型配上一套高度定制的框架，实验的说服力仍要打上问号，作者自己也只把这次运行当作对 agent 能力的一次压力测试的开端。

AI 生成的前端越长越像。模型们训练自同一批 SaaS 模板，交出的页面总带着那几样固定特征，Inter 字体、紫蓝渐变、卡片套卡片。GitHub 上 74.3k star 的 impeccable 就是冲着这股 AI 味来的。它脱胎于 Anthropic 最早为 Claude 做的 frontend-design skill，如今是一套完整的 AI 编码工具设计语言，npx impeccable install 一条命令装进项目，再用 /impeccable 命令集干活。它的底气是 61 条确定性检测规则，CLI 和浏览器扩展跑规则时完全离线，不需要 LLM，也不需要 API key。反模式清单写得直白，Inter、Arial 这类被用滥的字体别碰，纯黑纯灰要加色相，bounce 弹性缓动看着就过时。项目已适配 Claude Code、Cursor、Codex CLI、Gemini CLI、Grok Build 等十余种 AI 编码工具，这次是持续更新把它重新推回了 GitHub Trending。
