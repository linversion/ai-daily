MIT 让 GPT-6 直接改 Qwen 权重，数学成绩翻六倍

这是什么：MIT CSAIL 四人团队 11 月 2 日发布"权重空间编程"研究，让 GPT-6 Astra 不经过梯度训练，直接检查并编辑开源模型 Qwen3.5-0.8B 的权重，MATH-500 从 7.9% 提升到 48.1%，只改动第 15、19 层的 131,072 个参数（0.016%）。实验日志与编辑产物同步公开，当天即出现同行复现与质疑。
🔥 为什么今天值得看：若这条路线被验证可靠，模型维护和审计会多一种比重新训练轻得多的选项，排查小模型的怪异行为、修复缺陷都可能省钱省时。它同时踩在 AI 改进 AI 的敏感线上，PauseAI 已发出加速风险警告，而 Goedecke 当天的复现与质疑也说明社区会立刻检验这类说法的成色。
展开正文

11 月 2 日，MIT 计算机科学与人工智能实验室（CSAIL）的研究者 Rikiya Takehi、Jayden Teoh、Alex Zhang 和 Omar Khattab 发表研究博客，公布了一种叫"权重空间编程"的做法，让 OpenAI 的 GPT-6 Astra 大模型直接检查并修改另一个开源小模型 Qwen3.5-0.8B 的内部参数，全程绕开传统的训练流程。VentureBeat 在报道标题里把它比作给神经网络做基因编辑。

所谓权重，可以理解成神经网络里亿万颗数字零件，它们共同决定模型收到问题后给出什么回答。过去想让模型变好，要用海量算例反复计算误差，一点点调整这些数字，也就是微调或重新训练，算力和时间成本都很高。MIT 团队换了个思路，让一个训练成熟的大模型像工程师读代码那样去读权重，自己判断故障在哪，自己动手打补丁。Takehi 在 X 上表示，未来模型可以把原始权重当作可读、可改的代码来对待，由专门推演权重的 LLM 直接优化。

效果最好的语言模型实验里，Astra 只动了 Qwen 第 15 层和第 19 层的 131,072 个权重，占总参数的 0.016%，MATH-500 数学基准的成绩就从 7.9% 提高到 48.1%，约六倍。同一轮测试，GSM8K 从 13.8% 升至 67.1%，指令遵循测试 IFEval 从 21.0% 升至 62.3%。

这六倍的来路要说清。研究者把增益归因于 Astra 删掉了权重里一个与重复输出挂钩的数值方向。修改之前，Qwen 有 93% 的回答在原地打转，一路重复到撞上输出长度上限，题目根本答不完；修改之后这一比例降到 33.1%，模型原本就会的内容终于写得完。48.1% 是排除故障后考出的真实水平，这次实验展示的是模型修复，论文没有证明 Astra 向模型注入了六倍的新数学知识。修复的成本也写在文档里，最成功的一次尝试花了 158 轮对话、80 次 Python 运行和 20.3 小时，其中 4.7 小时在等一次服务中断恢复。

团队还做了其他实验。面对四个结构完全相同的游戏网络，Astra 不借助任何工具，凭权重认出了 Breakout、Pong、Pac-Man 和 Freeway。一个总在坡道卡死的驾驶控制器，它一次回复就给出补丁，改动 3.5% 的权重后成功率报告为 100%。在简化游戏环境 MinAtar 中，它只看规则和源码、不试运行，就手写出能玩 Breakout 的网络，得分 517.4，约为训练五亿步的 PPO 强化学习基线（25.3 分）的二十倍，不过在 Seaquest 和 Asterix 两款游戏上仍落后于五亿步基线。

这份成果当天就遇到同行拆解。工程师 Sean Goedecke 发文质疑大模型读写权重的能力超出人类的说法，文章随后登上 Hacker News 讨论。关于游戏识别，他指出那些网络的输入通道自带标签（比如智能体、移动物体），用三行 NumPy 代码算出一张热力图，就能看清玩家和移动物体各自待在棋盘的什么位置，肉眼即可认出游戏。关于 Qwen 修复，他说这个模型在超过三万两千个 token 后陷入循环，Astra 实际做的是写几段会循环和不会循环的文本，算出哪些权重在助推循环，再逐个削减，这基本是开源社区已有的 Heretic abliteration 技术路线，合格的人类研究者同样做得出。他打了个比方，LLM 能直接写机器码、修改编译好的二进制固然厉害，但处理二进制的正道仍然是写源码再编译，更新模型权重的正道仍然是正常训练。

论文本身也如实记录了失败。在没有明显重复缺陷的 Gemma 3 270M 上，Astra 未能取得数学提升；只凭权重区分顺着用户说话的模型和认真作答的模型，它一开始也失败了，补上注意力测量数据后才成功。X 用户 @1a3orn 批评发布帖略去了 Gemma 的负面结果，同时肯定团队把失败案例写进了博客。

直接编辑权重在学界早有先例，ROME（NeurIPS 2022）和 MEMIT（ICLR 2023）都做过针对特定事实关联的定点修改。MIT 这次的新意在于操刀者换成了通用大模型，由它跨任务地自主检查权重、设计修改。团队已公开实验日志与编辑产物，并表示正在开发配套的基准测试和框架。

外部反应两极。Databricks 的 Yuchen Jin 与 Voyage AI 的 Chandan Singh 认为，若技术可靠，开发者会多一种维护和排查模型的手段。PauseAI 的 CEO Maxime Fournes 担心这类研究一旦属实会大幅加速危险的能力进展，称其研究方向鲁莽。而研究没有证明直接编辑在速度、成本或效果上稳定胜过传统训练，至于递归自我改进，也就是 AI 的每次改进帮它完成下一次改进，论文既没有演示这样的循环，也没有证明收益会累积。

Mistral ML4 权重开放，中国外开源登顶仍落后六分

这是什么：Mistral 于 10 月 29 日开放 Large 4（ML4）的可下载权重，比原定的 10 月 27 日晚两天。模型总参数 1.05 万亿，激活参数 520 亿，上下文 100 万 token，可用 vLLM 或 SGLang 自行部署，并新增低、中、高三档推理设置。Artificial Analysis 同日发布完整独立评测，Intelligence Index v5 给出 26 分。API 价格约减半，每百万输入 0.70 美元、输出 2.10 美元。
🔥 为什么今天值得看：ML4 成为 Artificial Analysis 评测中中国以外开发的开源权重模型最高分，这对欧洲开源权重阵营是一个里程碑。独立数据同时给宣传降了温，它落后 DeepSeek V4.1 Flash 1017 与 GLM-5.3 六分，全球有七个开源权重模型排在它前面。对想自己运行和定制模型的企业，它提供一个近前沿水平的可下载选项，核心收益是更低的成本与模型自主权。
展开正文

10 月 29 日，Mistral 把旗舰大模型 Large 4（ML4）的可下载权重放上了 Hugging Face，比原计划的 10 月 27 日晚了两天。同一天，独立评测机构 Artificial Analysis 发布了对正式版的完整评测。11 月 2 日到 3 日，海外报道把厂商说法与独立数据放在一起解读，两边各有各的读数。

所谓开放权重，就是把模型学到的全部数值参数公开出来，拿到权重的人可以在自己的设备上运行、修改和继续训练这个模型。ML4 总参数 1.05 万亿，激活参数 520 亿。激活参数指模型处理每段输入时实际动用的那部分参数，这种稀疏激活设计让万亿级模型的推理成本可以接受。模型支持 100 万 token 的上下文，训练用了 3800 块 Nvidia Grace Blackwell GPU，下载后可用 vLLM 或 SGLang 自行部署。正式版还把推理分成低、中、高三档，低档替代以前的关闭模式，高档是困难请求的默认设置。

先看独立评测。Artificial Analysis 在 10 月 29 日的评估中，给 ML4（high 档）的 Intelligence Index v5 打了 26 分，比预览版的 25 分高一分。这让它以一分优势超过 Muse Spark Open，成为该评测中中国以外开发的开源权重模型的最高分。但全球有七个开源权重模型分数更高，DeepSeek V4.1 Flash 1017 和 GLM-5.3 以 32 分并列榜首，ML4 落后六分，MiMo-V2.6-Pro 拿 30 分。评测方认为，编码和代理型知识工作是 ML4 与榜首差距的主要来源。

变化更大的是账本。AA 测得 ML4 完成单个 Intelligence Index 任务的成本从预览版的 5.54 美元降到 2.06 美元，降幅 63%。API 定价大约减半，每百万输入 token 收 0.70 美元，缓存输入 0.07 美元，输出 2.10 美元。输出 token 平均每个任务 8.2 万个，比预览版少 39%，幻觉率从 41% 降到 28%。同一张成本表里，DeepSeek V4.1 Flash 1017 每任务只要 0.60 美元，MiMo-V2.6-Pro 只要 0.26 美元，两者的能力分还更高。省钱的参照系是 Mistral 自家的预览版。

编码是宣传重点。AA 的编码代理指数考察模型配合代理软件完成编程任务的表现，ML4 以 48 分排在现有开源权重模型第二，第一是 49 分的 GLM-5.3，DeepSeek V4.1 Flash 1017 为 46 分。ML4 每个任务消耗 850 万 token，约为 GLM-5.3（1590 万）的一半。这是模型加代理软件整套配置的对比，一分的差距说明不了统计上的显著差别，Mistral 自己也把两者称作实质打平。

厂商自报数据和独立评测的出入也需要对照着看。Terminal-Bench 4.0 上 Mistral 自报 41%，AA 测得 25%；FrontierCode 2.0 的官方图表里，Mistral 以 19.7% 排在 DeepSeek（19.3%）之前，AA 的数字是 15%，落后于 DeepSeek 的 29% 和 GLM-5.3 的 22%。两组数字来自不同的评测环境，引用时要标清口径，不能拿厂商数字顶替独立结果。

网络安全是另一个卖点。AA 的 Cyber Index 给 ML4 51 分，在开源权重模型中排第三，落后于 DeepSeek V4.1 Flash 1017（57 分）和 MiMo-V2.6-Pro（56 分）。分项里 CyberGym-E2E-AA 拿 79%，高于 DeepSeek 的 76%，追平 MiMo；DeepsecBench-AA（15%）和 CWE-Bench-AA（58%）两项落后。Mistral 自报对恶意网络提示的平均拒绝率为 96.6%，官方博客同时承认模型存在被用于真实攻击的可能，正在调整护栏。Orange Cyberdefense 等设计伙伴正在受控条件下测试专用安全变体。谈到护栏，首席营收官 Marjorie Janiewicz 的立场是，客户保护自己的最好方式是拿到这些模型，自己建立并定制其中一部分护栏。

许可证是这次发布里最需要读细的部分。ML4 采用 Mistral Ecosystem Open-Weight License，底层是 MIT 许可证，再加一条商业限制。它授予运行、修改和继续训练等广泛权利，但第 2 条规定，只要被许可方或其关联方经营 model-as-a-service 业务，也就是把模型以服务形式开放给第三方调用或做后训练，商业化使用前就必须另签商业协议。判断依据是业务形态和访问方式，许可证没有设收入门槛。企业内部使用，以及模型能力只嵌在自家产品功能里的终端产品，属于豁免范围。把它简单说成 MIT 开源，会漏掉这个关键条件。

还有一处口径要澄清。预览期报道的激活参数是 490 亿，正式材料写 520 亿。Mistral 在 Hugging Face 页面解释，较小的数字指每个 token 实际参与的参数量，较大的数字把词嵌入层和输出层也算了进去。这只是统计口径的差异，模型没有被临时加大。

对想自己持有模型的公司，ML4 提供了一个近前沿水平的可下载选项。Janiewicz 接受 VentureBeat 采访时把客户的心声归纳为三层，不想被断供、要拥有自己的模型，想通过定制从中获得价值，以及保住业务连续性。定制路径有两条，有技术实力的团队可以自己用 Mistral Forge，其他客户可以借助 Mistral 的部署工程师和应用科学家。Mistral 举的场景包括 BMW 的碰撞测试数据和 HSBC 的客户核验流程，这些属于目标案例，公司没有公布对应的生产环境结果。

AI 编程代理撑爆 Git，OpenAI 重写后端

这是什么：11 月 2 日 OpenAI 工程博客首次公开内部系统 Pando，一个自研的 Git 仓库后端，已支撑公司 monorepo 全部开发。它保持 Git 协议与客户端完全兼容，工程师与 agent 的既有工作流不变，生产环境中位推送延迟较之前降低近 5 倍，每天吞吐接近 1PB 的 Git 数据。
🔥 为什么今天值得看：这是 AI 编程 agent 规模化之后工程代价的第一手数据。Codex 驱动 monorepo 提交量较 2024 年一季度增长约 1378%，9 月日均约 3 万次提交，把传统 Git 服务架构逼到可靠性一度跌破 90%。Cursor、GitHub、Anthropic、GitLab 同期都在攻关同一问题，OpenAI 公开的架构取舍、方案对比和负载数据给行业提供了参照，客户端改进还将回馈 Git 上游社区。
展开正文

OpenAI 昨天（11 月 2 日）发布工程博客 Scaling Git at OpenAI，首次公开了一个叫 Pando 的内部系统。它是 OpenAI 给 Git 仓库重新造的后端，目前公司 monorepo 的全部开发都跑在它上面。monorepo 指把全公司代码放进同一个巨型仓库统一管理，OpenAI 的工程师和 AI 编程代理都在这个仓库里干活。

压力源头是 Codex。一名工程师现在能同时推进多个改动，每个推送又会触发 CI、研究任务和各类开发环境去拉取同一份代码，读写互相叠加。官方数据显示，monorepo 提交量较 2024 年一季度增长约 1378%，今年 9 月日均约 3 万次提交，系统每天要送出接近 1PB 的 Git 数据，1PB 相当于一百万 GB 上下。去年年底老系统明显跟不上了，拉取和推送变慢，合并也偶发失败，可靠性一度跌破 90%。

改造之前，OpenAI 推演过两条常规路线。一条是三阶段提交（3PC），多台持有完整副本的机器先加锁验证，再由协调者收集多数派确认后统一更新分支，每次推送都要多轮往返，不同分支之间也得排队。另一条是写前日志（WAL，先把改动记下来再执行，用来给多台机器排顺序），所有推送都要争抢同一份共享清单的更新权，写入量一大就成了瓶颈，单纯扩容存储也绕不开。

Pando 的做法分两半。写这一侧改用因果一致性，每个分支独立按顺序更新，互不相干的分支并行推送互不阻塞，只有同时推同一个分支才发生冲突，代价是同时读多个分支时可能看到各分支不同时刻的状态。读这一侧复用打包文件（packfile，Git 把大量对象压缩打包的标准格式），服务器把同一份压缩字节发给大量客户端，几乎不用为每个人单独现算一份，下载速率能跑满客户端的网络带宽。团队用 1,000 个客户端并发推送的仿真对比了几种一致性模型，以此支撑这套选型。

效果直接体现在生产环境，中位推送延迟降到原来的约五分之一，相当于优化近 5 倍。使用方式完全没有变化，Pando 保持 Git 协议与客户端兼容，切换期间没有中断任何工程工作。三位作者 Aaron Friel、Taylor Blau、Ted Nyman 均为 Member of Technical Staff，他们计划把客户端侧的改进回馈给 Git 上游项目。要提醒的是，Pando 本身没有开源，这次属于内部系统的一次公开披露，外界能拿走的是架构思路与真实负载数据。

这篇博客在 Hacker News 拿到 227 分。高赞评论整理了一串同类工作，Cursor、GitHub、Anthropic、GitLab 都在同期攻关 agent 时代的 Git 规模化，Entire 和 East River Source Control 等新玩家也入场，评论者好奇这些方案最终会不会收敛成同一种东西。质疑的声音同样不少，有人指出 Meta 六年前就有日均 3 万次提交的量级，也有人追问什么样的开发强度需要每天近 1PB 的代码吞吐，还有用户抱怨 agent 写出的代码能跑但架构越堆越乱。代码版本管理这块二十多年的老基建，正在被 AI 重新改造一遍。

两句提示词能拦住多少事还是未知数。提示词层面的引导可能被绕过，也可能误伤正常请求。The Verge 已经询问 Anthropic 是否会更新其他 Claude 系统提示词，目前没有得到答复。

xAI 部署 Data Bot 实践分享，给每个团队配数据科学家

这是什么：11 月 2 日 xAI 公开部署实践分享，SpaceXSI 数据科学团队在 Grok Bot 里构建了 Data Bot，一个全员可用的 Shared Bot。它连数据仓库，用数据团队沉淀的技能和记忆回答分析问题，结果按每个提问者的偏好格式输出。这是内部部署经验的记录，不是 Grok Bot 的产品功能更新。
🔥 为什么今天值得看：组织级 agent 的完整设计图很少被厂商公开。这份分享把两件关键事情讲透了，技能由专家团队统一维护而不是每人各调各的，记忆写入要过管理员审批才能全员可见。对准备在公司内部推 agent 的团队，这是少数能照着对照的一手参照，也说明 agent 进组织的难点在管理设计而不只在技术。
展开正文

11 月 2 日，xAI 公开了一份部署实践分享，介绍 SpaceXSI 的数据科学团队怎么在 Grok Bot 里搭起了 Data Bot。先说清楚一件事，这不是 Grok Bot 的产品功能更新，而是一家公司把组织级 agent 跑起来之后的经验记录。Data Bot 以 Shared Bot 的形式挂在 Grok Bot 里，加入的同事都能用，它连着数据仓库，按数据团队沉淀的方法论回答分析问题，输出格式会跟着每个提问的人调整。

这支数据科学团队人不多，麻烦在于全公司想查个数都得排队。很多问题本身不难，比如活跃用户怎么定义、某天收入为什么波动，但要答准仍然需要专业知识。团队在发布前几个月开始试 AI agent，想法是把团队的知识持续开放给全公司，自己腾出手来专门维护和改进这个 AI 同事。

具体设计分两块。第一块是共享技能，由数据团队统一维护。指标技能写清活跃用户、收入这些常用指标怎么定义，数据来自哪张表，查询逻辑是什么；遇到指标暴涨暴跌，它会先把变化按人群或地区拆开，排除节假日和埋点改动，再归因给产品变化。实验技能教它搭 A/B 测试，也就是把用户随机分成两组各看一个版本再比较效果，同时做功效分析，即事先算清楚需要多少样本结论才可信，还会检查两组用户分布是否均衡、规划放量节奏，实验攒够样本后整理读数。可视化技能规定看趋势用折线图、比类别用横向条形图，并套用团队自己的主题样式。仪表盘技能更进一步，能把聊天里生成的图变成 Databricks 或 Hex 上的正式仪表盘。数据工程技能管 dbt 模型的编写和审查，dbt 可以理解为把 SQL 写成可测试、可复用的数据加工流程的工具，这一类还约定了管道自动告警的规范，以及给新功能做埋点记录的办法。

第二块是共享记忆，存的是操作层面的经验，比如某条数据管道由哪位同事负责，上个月某次指标下滑其实是某个地区的假期造成的。这类内容不由 bot 自己说了算。Team Bot 的管理员要先审核，批准或拒绝之后，一条记忆才对使用 Data Bot 的所有人可见。相当于给 agent 的共享知识库加了一道组织关卡，错误经验不会悄悄扩散给全公司。

用的人已经分布在各个职能。产品经理 Kevin Niparko 在 Grok Bot 里直接发消息提问，几分钟就能拿到一张带结论标题的图表，还能接着追问而不用重开一个分析，那些现有仪表盘答不了的问题现在有了去处。做生命周期营销的 Jon Brenner 只需给一个 Braze 营销活动的编号，Data Bot 就去仓库里查收到邮件的人后来有没有使用对应功能，Braze 是一家做邮件和消息推送的营销服务商。X Subscription 上线时，Braze 自带的转化指标答不出多少人收到邮件后换了套餐，这个缺口最后由 Data Bot 查仓库补上。负责收入增长的 Katy Abbaszadeh 拿它评估活动对销售管道的贡献，每周盯目标进度，给汇报做图。再往深一层，它能独立完成一整套产品采纳分析，自己查数、自己找解释，最后写成带图表的报告，也能拉进 Slack 频道按时发周报，同事可以在频道里追问或要求它查一处异常。

效果有了第一个数字。按 xAI 自己的估算，发布前一周 Data Bot 替数据科学团队承担了约 70 小时的工作量，这是官方自述口径，还没有第三方验证。边界也划得清楚，需要更多判断的复杂分析仍由人类团队处理，他们还在摸索哪些地方要给 bot 补指引。至于 Data Bot 以后能不能接管那些复杂分析，公告没有给出答案。

编程智能体持续自进化实测，旧任务成绩相对跌 66%

这是什么：THU-Agent 团队 11 月 2 日在 arXiv 发布论文 2611.03219，首次系统研究编码智能体 harness 跨多任务持续自进化时的灾难性遗忘问题，并给出量化证据，全部代码在 GitHub 开源（仓库 THU-Agent/continual-harness-evolution）。
🔥 为什么今天值得看：harness 自进化是当下的热门范式，卖点是不动模型参数就能提升能力，绕开昂贵的重新训练。这篇论文首次量化了它的隐性成本，多任务连续进化时旧任务能力相对下降 66%。对正在部署自进化 agent 的团队，这是直接预警，自我进化必须配遗忘管理。
展开正文

这两年 AI 圈流行一条省钱的自我升级路线。不改大模型的参数，不重新训练，让智能体打磨自己外围的那套工作系统，练完之后单任务成绩确实更好看。11 月 2 日，THU-Agent 团队在 arXiv 挂出论文（编号 2611.03219），首次系统检验这条路线放进多任务连轴转的场景里会发生什么，答案是旧本事被大面积冲掉。

先解释两个词。智能体外围的这套工作系统叫 harness，可以理解成 agent 的工作脚本与工具链，怎么读代码、怎么跑测试都写在里面，模型权重本身不动，升级全靠改这些脚本和工具。灾难性遗忘是持续学习领域的老毛病，指学新任务时把旧任务的本事挤掉。这篇论文第一次把它实锤到 harness 层面。

实验这样设计。团队把 3 个软件工程任务数据集组织成 6 个进化方向，再选 2 种有代表性的 harness 进化方法，让同一个智能体在一个任务上进化完，接着换下一个任务继续进化，然后回头检查旧任务还剩多少能力。

数字相当刺眼。使用 DeepSeek-V4-Flash-0731 时，Meta-Harness 方法在 SWE-Bench 上进化后成绩达到 94.0%。随后转到 FeatureBench 上继续进化，到第五轮回头再测 SWE-Bench，只剩 32.0%，相对下降 66%。这里 66% 是相对降幅的口径，不是某个绝对分数。

病根在覆盖。为任务 A 进化时改写的脚本和工具配置，会把任务 B 依赖的旧能力顶掉。论文据此强调，持续自我进化必须配套遗忘管理，不能只盯着新任务的涨幅。

放在更大的背景里看，harness 自进化正是当下的热门范式，业界看中它绕开训练成本的便宜。本期日报的头条讲另一条路，研究者直接改模型权重。这篇论文提醒的是，改脚本的路线同样有代价，省下的训练费会以遗忘的形式还回来。代码已经开源，仓库为 THU-Agent/continual-harness-evolution，感兴趣的读者可以自己复现这条遗忘曲线。

Vercel CLI 给桌面按钮发编号，AI 操作不靠截图

这是什么：agent-desktop 于 11 月 3 日发布 v1.1.0 并同步更新 README。本次版本固定了 skills 技能文档体系、统一的 JSON 输出契约、ref 与快照绑定的错误处理以及随版本分发的跨平台 C FFI 库。项目用 Rust 编写，Apache-2.0 协议，仓库创建于 2026 年 2 月，已积累 11.5k stars、325 次提交。
🔥 为什么今天值得看：computer use 的主流做法靠截图加视觉模型猜像素位置，猜错就点错。无障碍树路线让 AI 直接拿到结构化的界面清单，不截图、不猜位置、不抢鼠标焦点，把桌面自动化从视觉识别问题变成确定性的接口调用。
展开正文

让 AI 操作电脑上的软件，常见做法是截屏交给视觉模型，让它猜按钮在图片里的位置，再换算成坐标去点。Vercel Labs 的开源项目 agent-desktop 走了另一条路。项目用 Rust 编写，以 Apache-2.0 协议开源，仓库创建于今年 2 月，已积累 11.5k stars，11 月 3 日发布了 v1.1.0。

它直接读操作系统为辅助功能准备的无障碍树。这份树相当于系统自己维护的界面清单，窗口里每个按钮、输入框都登记在册，并标明层级。snapshot 命令把清单整理成 JSON 交给 AI，每个可交互元素带一个 ref 编号。AI 想操作哪个元素，报编号即可，工具通过系统接口替它执行，全程不截图，也不移动鼠标、不抢焦点。操作完再拍一次快照核对结果，观察、行动、验证的循环留在 AI 这一侧。

界面上元素一变，旧编号就作废，命令会返回 STALE_REF 错误，AI 重新拍快照拿新编号再试。v1.1.0 把输出定成统一契约，每条命令返回 ok 或带错误码的 error，只有标记为可安全重试的错误才建议重试；版本还随附 C 库供程序进程内调用，并内置与版本匹配的技能文档，方便接入各类 agent 框架。

工具支持 macOS、Windows、Linux 三个平台，npm install -g agent-desktop 一条命令安装。macOS 需要授予无障碍权限，Windows 在终端同一权限级别下一般免授权，Linux 的部分鼠标与截图功能依赖 X11 或 Wayland 接口。

给 AI 代理各开一间工位，worktrunk 持续更新上榜

这是什么：这不是新项目首发。仓库创建于 2025 年 10 月 17 日，运营约一年，累计 5,479 次提交，10.2k stars，371 forks。v0.81.0 在 2026 年 10 月 20 日发布，README 于 11 月 3 日更新，其中自称是当前最流行的 git worktree 管理器。本次进入 GitHub Trending 属于成熟工具持续迭代带来的热度。
🔥 为什么今天值得看：多代理并行开发正在从技巧变成日常，几个代理挤一个目录迟早互相覆盖。worktrunk 给出低门槛答案，四条命令就能给每个代理分出独立工作副本。同一期里 OpenAI 在重写服务端 Git 后端以扛住代理提交量，这个工具处理的是同一股压力落在开发者本地的部分。
展开正文

同时带五到十个 AI 编码代理干活的人，先要解决一件具体的事，别让代理们踩到彼此的文件。Git 自带的 worktree 功能可以给同一个仓库开出多个并行工作副本，每个副本检出不同分支、各有独立目录，但原生命令繁琐，新建一个要输三次分支名，还要手动 cd 过去。

GitHub Trending 上的 worktrunk 盯上的就是这个痛点。这个用 Rust 写成的工具把命令缩成 wt，wt switch、wt list、wt merge、wt remove 几条命令覆盖日常操作，README 称核心命令让 worktree 用起来和分支一样省心。它明确为 Claude Code、Codex 等代理的并行场景设计，wt switch -x claude 一条命令就能建好工作副本并把 Claude 启动进去，各代理各用各的目录互不冲突。项目 2025 年 10 月创建，运营约一年攒下 10.2k stars，10 月 20 日发布 v0.81.0，README 更新于 11 月 3 日。这次上榜是持续迭代带来的热度，不是新项目亮相。
