据 TechCrunch 10 月 22 日报道，彭博社消息称，DeepSeek 已完成约 150 亿美元（约合 1000 亿元人民币）融资，规模位居中国最大融资轮之列。消息落点在美国政府下令联邦民用机构出于安全考虑移除 DeepSeek 技术仅两天之后，一边是华盛顿的移除令，一边是创纪录的支票，两件事几乎撞在同一个星期。

报道称，本轮潜在投资方包括中国电池厂商宁德时代（CATL）、腾讯等，腾讯是微信背后的公司。

公司底子方面，DeepSeek 总部位于杭州，2023 年由梁文锋创立，他此前联合创立的量化对冲基金 High-Flyer 出资支持了早期发展。2025 年初，这家公司凭免费使用的开放权重 R1 推理模型（模型文件公开可下载）获得全球关注。据 WireScreen 分析的公司股权数据，前轮融资之后，梁文锋仍持有其中国运营实体约 81.6% 的股份。

据报道，新资金将支撑它继续加大 AI 基础设施与开源模型的投入，同时服务国内外市场，其扩张可能进一步加剧国内同行之间的竞争。资本对中国 AI 公司的热情有对照，Kimi 开发方 Moonshot AI 5 月融资 20 亿美元（估值 200 亿美元），Manus AI 本月早些时候融资超 5 亿美元，1 月先后在港上市的智谱（Z.ai）与 MiniMax 目前市值分别约 290 亿美元与 72 亿美元。

截至发稿，DeepSeek 未回应 TechCrunch 的置评请求，本轮融资的细节仍以彭博的报道口径为准。

微软 AI 诊断研究登 Science，疑难病例 83% 对医生 36%

这是什么：微软 AI 的多智能体诊断系统 MAI-DxO（简称 DxO）的评测研究周四发表于《Science》。它在《新英格兰医学杂志》疑难病例的模拟诊疗中诊断正确率 83%，是对照组的两倍多；以个人方式应诊、可查阅参考资料的全科医生和普通内科医生为 36%。系统协调多个 AI 智能体模拟医生小组问诊、开检查、辩论诊断，微软 AI 的 CEO Mustafa Suleyman 称这是迈向「医疗超级智能」的一步。
🔥 为什么今天值得看：微软借此加入 Google 和 OpenAI 的行列，宣称 AI 达到或超过医生水平，临床决策支持成了前沿实验室的新竞争面。后续动作密集，与梅奥诊所合训医疗基础模型计划明年发布，与波士顿 Beth Israel Deaconess 医疗中心启动号称同类最大的真实世界评估。成绩的读法要带着对照设计，对照组是单打独斗的全科与普通内科医生，现实中这类疑难病例多由专科医生或团队处理，未纳入对比；研究数据同时显示提升的主要部分来自更强的底层大模型，微软的编排层追加增益。

微软 AI 的诊断系统在《Science》周四刊出的研究里交出了一份亮眼的模拟考成绩。在《新英格兰医学杂志》疑难病例的模拟诊疗中，这套名为 MAI-DxO（简称 DxO）的系统诊断正确率 83%，是对照组的两倍多；对照组的全科医生和普通内科医生以个人方式应诊、可查阅参考资料，正确率 36%。微软 AI 的 CEO Mustafa Suleyman 称这个结果是迈向「医疗超级智能」的一步。

DxO 的核心动作是编排。它在底层大模型之上协调多个 AI 智能体，像一组医生那样分工，向患者问诊、开具检查、就诊断展开辩论。微软用 OpenAI、Google、Anthropic、Meta、DeepSeek 几家公司的模型做了测试，最好的成绩出在 OpenAI 的 GPT-5 和 GPT-5.5 上。

对照怎么设的，原文写得明白。考题是《新英格兰医学杂志》的疑难会诊病例，难度出了名；参与对照的医生单兵作战。现实中这么复杂的病例通常交给专科医生或整个医生团队处理，他们没有进入对比。微软 AI 医疗健康副总裁 Dominic King 对 TechCrunch 表示，当下医疗行业最大的挑战是医疗专长的供需缺口不断扩大。

研究自己给出的数据拆解，比 83% 对 36% 这个总分更能说明问题。GPT-5 单独用一个简短的基础提示词应诊，疑难病例正确率 78.9%，每例成本约 8400 美元；套上 DxO 后成本降约 3000 美元，正确率只多约 4 个百分点。急诊科病例上，GPT-5 裸用与配 DxO 在正确率和成本上几乎没有差别。换 2026 年 4 月发布的 GPT-5.5，疑难病例从 72% 提到接近 87%，成本略降；急诊科病例有无 DxO 都在 85% 上下，增益再次不见。较弱的模型从编排里拿到的好处更多，Gemini 2.5 Flash 单独应诊 46.4%，配上 DxO 接近 69%，但强弱模型之间的差距仍大过 DxO 带来的提升。

TechCrunch 据此给出的读法是，研究自身数据显示准确率提升的大部分来自更强的底层大模型，微软的编排层是在其上追加增益。微软研究人员的回应是，模型接近理论上限后准确率增益自然会收窄，DxO 的价值在于同时优化正确率和成本。

Suleyman 是 DeepMind 联合创始人，2024 年加入微软执掌 AI 部门，他给这条线排了时间表。微软与梅奥诊所合作训练医疗基础模型，计划明年发布；他预测 2027 年医疗记录领域会出现类似编程领域的突破，模型能对病历走向给出高精度预测，并预计未来 24 到 36 个月内医疗模型能力提升一个数量级。临床验证方面，微软与波士顿的 Beth Israel Deaconess 医疗中心启动真实世界评估，同意参与的患者照常接受诊疗，DxO 并行给出建议，微软和合作方把 AI 建议与人类医生的处置逐例对比，King 称这会是同类研究中规模最大的一次。本月 Google 刚与同一家医院在《柳叶刀》发表了对话式诊断 AI AMIE 的真实世界研究，几家公司挤在同一个门口。

从模拟考场到病房还有距离。这套系统目前证明的只是模拟疑难病例上的成绩，真实世界评估刚刚起步，同日发布的「医疗超级智能」宣言也还停留在定义层面，指在全病程的医疗推理与协调上超过当前最强的人主导医疗体系。微软已经向临床医生售卖听写和放射工具，把 DxO 视作这块业务的延伸，Suleyman 的目标是未来几年做出业界第一的临床决策支持产品。

Decisions API 从公测转正，OpenAI 把高频小判断做成独立生意

这是什么：OpenAI 10 月 22 日在官方博客宣布 Decisions API 正式上线，距 10 月上旬的公开测试只隔十来天。这个接口处理应用和智能体运行中的海量小判断，输入文本、图像或原生 JSON，直接返回程序能用来做分支的结构化答案。正式版基于 GPT-6 Luna，官方口径是最多比走 Responses API 的同一模型快 10 倍，每百万输入 token 定价 0.10 美元。公测后新增了 GPT-Live 语音集成、prompt caching 和美欧推理驻留等能力。
🔥 为什么今天值得看：公测到正式版只用了约两周，新增项集中在数据驻留、缓存计费、实时语音这些生产环境刚需上，说明高频小判断已经能承接真实业务流量。计费上只收输入 token 费用，判断被拆成可独立计价的最小调用单元，大模型能力又有一块被单独包装成产品。对做智能体的团队，路由和分类这类环节多了个更快更便宜的标准件选择。
展开正文

OpenAI 在 10 月 22 日的官方博客里宣布 Decisions API 正式可用，当天 TechCrunch AI 跟进报道。这个接口处理的是应用和智能体在运行中数量最多的小判断，一条输入归到哪个类别，一个请求路由给谁，下一步执行哪个动作。单个判断很简单，规模化之后延迟和成本会一起堆高，Decisions API 把这类判断从完整的模型生成里拆出来，直接返回程序可以做分支的结构化答案。它在 10 月上旬刚进入公开测试，当时官方预告正式版数周内推出，十来天后兑现。

正式版基于 GPT-6 Luna，走专用的 Decisions 端点。OpenAI 给出的速度说法是，处理答案范围有限的问题时，最多比通过 Responses API 调用 GPT-6 Luna 快 10 倍，输入支持文本、图像和结构化数据，定位在近实时决策。计费跟着这个定位走，每百万输入 token 收 0.10 美元，复用上下文命中缓存后降到 0.01 美元，输出侧不另收费，开发者只为喂进去的内容付钱。

从公测到正式版，新增能力集中在生产与实时两个方向。GPT-Live 原生集成允许把决策配置挂到实时语音会话的 session.triggers 上，比如根据用户刚说的话给数字人挑一个表情，会话收到 decision.event 后驱动动画，客服语音代理也能在追问、转接、升级之间现场做选择。复用上下文的 prompt caching、美国与欧盟的推理驻留、原生 JSON 输入、问题指令里直接带图像陆续加入，单次请求的问题上限从公测时的 200 个翻倍到 400 个，亚洲多个区域还扩充了容量继续压延迟。

用例方面，OpenAI 内部的 dots 团队用它缩短响应时间，个人财务团队拿它给交易描述分类，通讯团队按主题给媒体报道打分，判断一篇稿子在强化还是削弱关键叙事。外部客户包括 Datadog、Ramp、Sierra、Speak 和 Box，场景从 AI 成本归集到语言学习互动都有。Box 的做法有代表性，Box Extract 抽取商业文档内容，Decisions API 负责分类并把文档路由到下一个步骤。Box 产品管理平台与集成副总裁 Biswaroop Palit 介绍，在他们自己的评估里，30 个保险证书案例上路由选择快了约 5 倍，准确率与 Responses API 相同，低置信度案例自动转给人工审核。

这些数字要分开看来源。最多快 10 倍是 OpenAI 的官方口径，约 5 倍提速与准确率持平出自 Box 的自有评估，样本只有 30 个案例，覆盖面有限。官方也建议开发者从应用里最常重复的决策入手，先在反映真实用法的数据上测试。正式版目前只搭配 GPT-6 Luna 一个模型，选型时要把单模型依赖算进考量。

OpenAI 开源官方 CLI，终端直连 REST API

这是什么：OpenAI 以 Apache 2.0 协议开源官方 CLI 工具 openai，仓库 openai/openai-cli 近日登上 HN 热榜，10 月 22 日讨论帖拿下 228 分，抓取时已有 1.0k stars、85 forks,commit 历史有 560 多个。工具定位是在终端与 shell 脚本中直接调用 OpenAI REST API，覆盖图像生成、文件上传下载、批处理提交与模型查询，无需编写应用程序。
🔥 为什么今天值得看：开发者此前调用 OpenAI API 主要靠 SDK、手拼 curl 和第三方 CLI，官方现在自己维护一个终端入口，与 Codex CLI 形成 agent harness 与低层 API 工具两条产品线。开发者入口之争多了一个官方选手，脚本自动化与运维场景有了官方支持的选项，密钥处理也比裸写 curl 更讲究。
展开正文

OpenAI 的官方命令行工具来了。名为 openai 的 CLI 以 Apache 2.0 协议开源在仓库 openai/openai-cli，近日出现在 HN 热榜，10 月 22 日的讨论帖拿下 228 分，抓取时仓库已有 1.0k stars、85 forks,commit 历史有 560 多个。它做的是一件朴素的事，让开发者在终端和 shell 脚本里直接调用 OpenAI REST API，生成图像、上传下载文件、提交批处理、查询模型列表，不必为此先写一个应用程序。仓库创建于今年 5 月，560 多个 commit 说明这条产品线已经开发了小半年，此番进入公众视野并非仓促上马。

工具基于 OpenAI Go SDK 构建，命令结构沿用 API 资源命名，openai 一路映射到具体端点，旧的冒号分隔写法也继续兼容。图像生成默认把结果存到 ~/Downloads/gpt-images/ 并打印路径，文件可上传下载，批处理支持提交 JSONL 请求、等待完成、下载结果一条龙。

README 专门用一段说明它与 Codex CLI 的分工。想调用某个具体 API、想把 API 操作放进脚本时用 openai；想让编码智能体读改项目代码、执行命令、帮忙实现或调试变更时用 codex。认证支持 openai help setup 交互式引导，脚本场景走 OPENAI_API_KEY 环境变量，管理端点另设一把独立的 OPENAI_ADMIN_KEY，例如查询某一天的组织用量。输出默认是人类可读文本，可用 --format json/jsonl/raw/yaml 显式指定，--transform 配合 GJSON 语法直接提取字段，错误信息走 stderr，--format-error json 可以查看 API 错误详情。示例命令覆盖 gpt-5.5 模型与 /v1/responses 端点。

安全设计上有两处细节值得留意。管道输入的 JSON 或 YAML 来自不可信来源时，设置 OPENAI_UNTRUSTED_STDIN=1 可以防止输入内容触发本地文件读取；README 同时提醒 --debug 日志与 API 错误详情可能包含敏感数据，分享前需要自行脱敏。仓库还写明 PR 仅限协作者提交，外部贡献走 GitHub issue。

展开正文

10 月 22 日，OpenShell 的讨论帖登上 Hacker News，截至抓取拿到 250 分。项目本身已经开源超过半年。据 Tigera 的分析文章，NVIDIA 于今年 3 月的 GTC 2026 发布并开源了 OpenShell，EQTY Lab 3 月 18 日在 GTC 会场的合作公告也印证了这个时间点。GitHub 仓库至今积累 17.7k stars 和 1.8k forks，本轮上榜是社区对这个既有项目的又一次集中审视。

OpenShell 划定的题目是成群自主 agent 的安全私有运行时。agent 要干活就得能读文件、装软件包、调 API、用凭据，它的做法是把能力给足、把访问管住。每个 agent 跑在隔离沙箱里，内核级控制在运行时逐条检查文件访问、系统调用和网络连接，出站流量先过策略再放行。真实凭据 agent 全程接触不到，只在请求发往已获批准的端点时由系统代为注入。策略变更生效前还要过一道形式化验证，带风险的新授权（比如用凭据触达新主机、调用新 API 方法）先被标记，经人工审批后才应用。平台覆盖 Linux、macOS Apple Silicon 和 Windows WSL 2（实验性），Apache 2.0 许可开源，配套 Python、TypeScript、Go、Rust 四种 SDK，网关可用 Helm 部署到 Kubernetes。

热榜之外，安全争议也在同步累积。GitHub Issue #1169（5 月 5 日开立）报告，沙箱在未配置网络策略时确实拒绝全部 TCP/HTTP 出站，但 DNS 解析发生在代理做策略评估之前或期间，把任意数据编码进 DNS 子域标签就能送达攻击者控制的权威域名服务器，绕过代理的执行层。安全公司 Lasso Security 的实测文章给出另一类路径，二进制粒度的出站策略本身执行正确，但无法判断意图，攻击武器化的正是沙箱为基本功能必须放行的通道（npm install、node、git/gh），结论是「No policy was violated; the sandbox behaved exactly as configured」。研究者 dbugs 在 X 上补充了平衡视角，研究里没有发现对已记录安全控制的绕过，成功外泄依赖操作员开启的权限。Lasso 披露，NVIDIA 对报告的回应是这些场景不在漏洞披露计划范围内，沙箱本就用于限制提示注入场景的影响。

HN 评论区讨论的是同一件事的社区版。用户 fennecbutt 担心被提示注入的 agent 向可信域名每次只发几个字符，把代码库一点点带出去。用户 marcosscriven 认为只要 agent 能对公开内容产生微小影响，比如一个冷门论坛帖的阅读数，外泄就能成立。用户 smashed 则用致命三要素的框架主张拆分权限，让单个 agent 永远凑不齐不可信内容、私有数据、网络访问这三样。内核级的墙立起来了，策略语言管不到的意图与侧信道还是开放问题。

判分器变奖励函数，微软把数据库对账做进 RL 训练循环

这是什么：微软与 Hugging Face 于 10 月 22 日发布 ThinkingBox-Training，把 ThinkingBox 的数据库终态可执行检查用作强化学习奖励，对 Qwen3.8-27B 做 50 步全参数 GRPO 后训练。在从未参与训练的 507 个基准任务上，平均成功率从 51.70% 升至 60.78%，20 次全对任务从 38 个（7.50%）增至 107 个（21.10%）。训练栈在 microsoft/thinkingbox-training 开源。这是本报 10 月 4 日报道的 ThinkingBox-Bench 基准的续篇，当时训练环境尚未发布。
🔥 为什么今天值得看：这条路径的奖励来自数据库终态的确定性判定，训练全程不需要人工示范轨迹，也基本不依赖 LLM 主观打分。结果显示可重复成功率是能被直接优化的目标，一个 27B 模型经 50 步训练把 20 次全对任务做到接近原来的三倍，同时要接受 pass@20 微降的锐化代价。对要把 agent 放到生产数据库边上的团队，20 次全对率比单次成功率更接近真实的可靠性口径，这次它成了训练目标本身。
展开正文

本报 10 月 4 日报道过微软与 Hugging Face 的 ThinkingBox-Bench 基准，agent 拿到真实后端和工具干活，判分器直接核对数据库终态，专抓那种工具调用看着专业、数据库里却留下错误记录的 agent。当时面向强化学习训练的环境尚未发布。10 月 22 日两家发布续篇博客，同一套数据库终态检查被搬进了训练循环，评测时它是考官，训练时它输出 1 或 0 的奖励，成了老师。完整的训练栈同步在 microsoft/thinkingbox-training 开源。

可重复成功率出现了大幅抬升。Qwen3.8-27B 经过 50 步全参数 GRPO 后训练，在 507 个从未参与训练的基准任务上，平均成功率从 51.70% 升至 60.78%，20 次全对的任务从 38 个（7.50%）增至 107 个（21.10%），接近原来的三倍。代价是至少解出一次的 pass@20 从 89.35% 微降至 87.97%，少了 7 个任务，作者称这与此前工作观察到的锐化现象一致，概率分布向能反复走通的轨迹集中。单个任务的变化更直观，一个需经理审批的酒店订单降级任务，基础模型 20 次里 15 次未经审批就改单退款，训练后 20 次全部保住了预订和支付状态。

训练池的挑选方法叫离线策略相对难度，出发点是 GRPO 的组内算术。八个尝试全对或全错时，组内没有对比梯度，只有 [0,0,0,1,1,1,1,1] 这类混合组能提供学习信号。他们在训练前用基础模型对候选任务反复探测，以 Jeffreys 后验 Beta(k + ½, n − k + ½) 估计每个任务的成功率，按 0.08、0.40、0.60、0.90 四个边界分五档，保留中间三档，丢掉几乎不会做和几乎总会做的，最终筛出 187 个训练任务。这 187 个任务与基准的 507 个完全不相交，基准只用于分布外评测。

工程配置上，训练基于 Verl 0.9.0，token-mean GRPO 每步生成 18 组乘 8 个 rollout 共 144 个完整回合，在 24 张 H100 上同步进行，AdamW 学习率 1e-6。奖励绝大多数来自确定性终态检查，少数窄项由 GPT-5 Chat 作为裁判回答二元 rubric 问题。训练与评测共用同一套输出解释代码（trainer/core/tb_interpret.py），否则奖励衡量的就是另一个 agent。零方差组按 DAPO 风格替换，后端超时这类系统错误补组重跑，不计为失败。

按第一篇博客的成本口径折算，每个可靠任务的花费从 24.36 美元降到 8.00 美元，接近 GPT-5.4 的 6.80 美元、GPT-6 Astra 的 7.45 美元和 Claude Opus 5.5 的 7.80 美元。排序上还有一个细节，GPT-5.6 Sol 的平均成功率 61.91% 略高于微调后的 Qwen3.8-27B，20 次全对任务却只有 82 个，少于后者的 107 个，两个指标给出两种排序。开源仓库包含数据筛选、rollout、奖励与 Verl 集成，公开的示例任务列表只用于跑通接口，报告所用的 187 个任务训练池没有随仓库公开。

Gradium 开源端侧 TTS 系列 Phonon，31M 参数 64.5 MB 就能开口说话

这是什么：巴黎语音 AI 公司 Gradium（从 Kyutai 分拆）10 月 22 日开源端侧文本转语音系列 Phonon，为该系列首次发布权重。英文版 Phonon 31m 以 Apache 2.0 许可发布，31M 参数（不含音频 tokenizer），q8 GGUF 权重 64.5 MB，内置 37 个声音。Phonon 40m 提供英法德西葡单语种版本，40m 多语种版将五种语言装进一个模型并带 102 个声音，两款均为 CC BY-NC 4.0 非商业许可。
🔥 为什么今天值得看：Phonon 对准的是云端 TTS 的三笔固定成本，网络往返延迟、语音出网的隐私顾虑和按字符计费的开销。模型在手机、笔记本、树莓派 5 乃至浏览器（WASM、WebGPU）本地出声，无需 GPU 与联网，Apache 2.0 让商业产品可以把英文语音能力直接打包进端侧应用。对正在拼装智能体语音界面的开发者，这是一个许可干净、体积可控的即用组件。质量与速度数据目前均出自 Gradium 自测，第三方检验尚待积累。
展开正文

巴黎语音 AI 公司 Gradium 从 Kyutai 分拆而来，10 月 22 日开源了端侧文本转语音系列 Phonon，家族共三款模型。英文版 Phonon 31m 采用 Apache 2.0 许可，内置 37 个声音；Phonon 40m 提供英法德西葡五种语言的单语种版本，40m 多语种版把五语装进一个模型、带 102 个声音，两款 40m 均为 CC BY-NC 4.0 非商业许可。这是 Phonon 系列的首次开源发布。

参数量、体积、延迟、许可，四个数字就能讲完 Phonon 31m。它有 31M 参数（不计音频 tokenizer），q8 量化（8 比特）的 GGUF 权重 64.5 MB，输出 24 kHz 单声道音频，笔记本 CPU 上约 7ms 出第一帧声音。原文实测口径更具体，MacBook Air M5 CPU 四线程下首音频 6.9ms、29.9 倍实时，配合 Arm KleidiAI 与 Apple Accelerate 可达 46.7 倍实时；树莓派 5 上 38ms 启动、3.7 倍实时。作为对照，Gradium 称不支持流式的 Kokoro 在同款笔记本 CPU 上需 517ms 出声，在树莓派 5 上要约 7 秒启动。

质量数据均出自 Gradium 自测。盲听对比征集 1,189 名评分者、17,270 票，Phonon 31m 拿到 2098 Elo，高于 Kokoro 的 2043，位列其实测的开源模型前列。在塞满电话号码、邮箱与邮编的 500 句难句集上，Phonon 31m 词错率 1.70%，Kokoro 为 3.50%；换到更简单的 Seed-TTS 集上为 0.51%，略逊于 Kokoro 的 0.45%。原文称内置文本归一化贡献了难句集上的大部分差距，这些数字还有待第三方检验。

架构上是因果 transformer 骨干，SentencePiece 以 4000 词表直读原始文本，跳过音素转换，每 80ms 帧生成一个隐向量，flow-matching 头用一步把噪声变成音频嵌入，再交给 Kyutai Mimi 解码器的缩小版输出音频，整个系列蒸馏自更大的 Phonon 教师模型，技术脉络可追溯到 Kyutai 的 Continuous Audio Language Models 研究与 Pocket TTS。运行时按 MIT 或 Apache-2.0 开源，覆盖 Rust、Python、Swift、C、C++ 与浏览器，可在 Ollama、LM Studio、Transformers、MLX-Audio 里直接加载。云端 TTS 的往返延迟、隐私顾虑与按字符计费，是这套模型想替开发者省掉的三笔账。
