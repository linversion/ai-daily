时序预测基础模型Toto 2.0发布，40亿参数验证缩放定律

这是什么：研究人员发布了Toto 2.0，一个从400万到25亿参数的开源时序基础模型家族（Apache 2.0协议），首次在时序预测任务中系统验证了缩放定律，并在三个基准测试上达到当前最优。论文和模型权重已发布。
🔥 为什么今天值得看：此前时序预测领域的小模型方法论长期占主导，Toto 2.0用实验证明：大模型在时序任务上也能像在语言和图像领域一样，通过增加参数量和数据量持续提升性能。这为工业界和学术界提供了新的基础模型路线，且仅用可观测性和合成数据就击败了依赖公开基准数据的模型，说明模型学到了更通用的时序表征。

时序预测领域又有新突破。研究人员发布了Toto 2.0，一个从400万到25亿参数的开源时序基础模型家族，首次在时序预测任务中系统验证了缩放定律——随着模型变大、数据增多，预测质量稳定提升，不再是小模型就够用。

与第一代Toto相比，Toto 2.0在同等预测质量下参数量减少7倍，推理速度更快，并且仅使用可观测性数据和合成数据进行训练——没有采用任何公开的预测数据集——就在BOOM、GIFT-Eval和TIME三个基准测试上取得了当前最优结果。这意味着模型学到了更通用的时序模式，能更好泛化到不同领域。团队还提出了一种叫u-muP的超参数迁移方法，使得不同规模模型可以用同一套训练配方，大幅降低了调参成本。

当然，社区也有质疑声音。有研究者指出，缩放实验仅在三个特定基准上验证，实际场景中能否稳定复现仍是未知数；且开源权重不等于完全可复现，训练数据和流程细节尚未完全公开。Toto 2.0目前还处于演示阶段，距离工业级落地还有距离。

Anthropic 发布 Claude Code 新能力，AI 编程助手学会写笔记自主进步

🔥 为什么今天值得看：这标志着 AI 编程助手从“每次独立响应”迈向了“拥有持续学习能力”的新阶段。如果 dreaming 功能落地，开发者将能大幅减少重复描述上下文的时间，AI 的编码质量也可能随着使用积累而提升。然而，这种能力也让“AI 替代程序员”的讨论更加激烈——当工具学会自主学习，人类开发者的角色将变得更加偏向审查与决策，而这对入门级程序员来说可能意味着更少的练手机会。

Anthropic 在近日举办的“Code with Claude”开发者活动中，展示了其 AI 编程助手 Claude Code 的最新升级。核心亮点是一个名为“dreaming”的新功能——它让 AI 代理人能够在处理完一个编程任务后，自动写下经验笔记，并在下次任务中参考这些笔记，从而越用越聪明。

这项功能之所以重要，是因为它标志着 AI 编程助手从“一次一指令”的被动执行，向“能自我积累经验”的主动学习迈进了一步。过去，开发者每次聊天都需要把上下文重新喂给 AI；dreaming 功能让 Claude Code 像人类程序员一样，通过回顾和总结来改进后续编码。现场演示中，Claude Code 自主完成了代码编写、测试、调试甚至重构，效率惊人。

但活动的另一面是业界反复提及的隐忧：当越来越多公司（包括不少头部科技企业）宣称自家代码的相当比例出自 AI 之手时，代码质量、安全漏洞以及开发者的技术退化问题也随之凸显。与会者中不乏反对声音——一些资深开发者担心，过度依赖 AI 编写代码会让新程序员丧失基本功，未来的代码库将充斥着难以维护的“黑箱”片段。

具体来看，dreaming 功能允许 Claude Code agent 在工作区中保存笔记，用自然语言记录任务中的关键发现和解决方案。这些笔记会在后续会话中被自动检索，用作参考。活动现场还展示了 Claude Code 与 GitHub、VS Code 等主流工具的深度集成。不过，Anthropic 并未公布该功能的具体上线日期与定价，目前仍处于演示阶段。

Video2GUI 开源大规模 GUI 轨迹数据集，从无标签视频自动挖掘 1200 万条交互

这是什么：研究者提出 Video2GUI，一个全自动化框架，能从任意无标签互联网视频中提取带界面元素定位的 GUI 交互轨迹，并据此构建了 WildGUI——当前最大的开源 GUI 预训练数据集，包含约 1200 万条交互轨迹，覆盖 1500 余款应用和网站。论文已公开在 Hugging Face 上。
🔥 为什么今天值得看：此前 GUI agent 训练数据主要靠人工录制或合成程序生成，规模小、成本高，导致模型泛化能力差。Video2GUI 利用了互联网上海量的软件教学视频和操作演示，将数据获取成本降至接近零，使预训练数据量级从百万级跃升到千万级，首次验证了“数据缩放规律”在 GUI 领域同样有效——更多数据带来更稳定的跨应用迁移能力。

想让图形界面智能体（GUI agent）学会操作各种软件，最大的瓶颈一直是训练数据——人工标注 GUI 操作序列既昂贵又慢。如今，来自几所高校的研究者提出了一种全新的自动化方案：直接从未经标注的互联网视频中提取 GUI 交互轨迹，一口气生成了包含 1200 万条轨迹、覆盖 1500 多个应用和网站的数据集 WildGUI。

这套名为 Video2GUI 的框架并非简单识别屏幕上的点击位置，而是利用多模态对齐技术，将视频中的鼠标移动、按键动作与对应的界面元素精准匹配，形成完整的“动作-反馈”序列。这意味着过去只能依赖人工录屏或合成数据的 GUI 预训练，现在可以借力 YouTube 上的软件教学视频、直播演示等海量现成资源，规模直接跃升两个数量级。

从效果看，用 WildGUI 预训练的智能体在多个标准 GUI 基准测试上的表现提升了 5% 到 20%，尤其在跨软件迁移能力上优势明显——比如在 Photoshop 里学会的“拖拽调整图层”这类通用操作，能直接用在 GIMP 中。不过需要注意，自动提取的数据不可避免会混入视频噪点、非 GUI 内容片段，研究者也承认部分轨迹的准确率仍有优化空间。社区讨论中，有开发者担心数据集里的广告或低画质视频会引入偏见，但更多人认为这个“零人工标注”的思路打开了 GUI agent 预训练的想象力。
