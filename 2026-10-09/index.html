Google 给 AI 同事配独立邮箱日历，可连跑多天任务

这是什么：Google 于周四的 Gemini at Work 2026 活动发布面向企业的通用 Gemini agent，属于全新产品发布。核心增量集中在四点。其一，持久数字同事配置，agent 可以获得独立的 Workspace 账户、邮箱、日历、Drive 存储与公司通讯录身份，可执行持续数小时至数天的任务，支持并行任务、定时任务和临时子 agent 编组。其二，四类记忆架构（会话、语义、程序、情景），用于沉淀企业流程与制度知识。其三，模型层开放并引入 Smart Routing，默认使用 Gemini，已支持 Anthropic Claude，计划接入更多闭源与开源权重模型，可按性能与成本为工作负载选模型。其四，运营侧新增项目级预算暂停与部门成本归集，并推出 Financial Services（预览版，含 50 多项基础技能，接入 FactSet、LSEG）与 Legal（支持 NetDocuments、iManage）行业智能体。
🔥 为什么今天值得看：这次发布把 AI agent 从按次对话的工具推进成组织内的持久成员。独立邮箱、日历和通讯录条目意味着 agent 第一次以实体身份进入企业的 IT 目录、权限体系和审计范围，身份管理、权限边界、成本归集这些 IT 治理问题随之进入采购决策。模型层的开放同样有信号意义，企业可以在保留同一套 agent 基础设施、公司上下文与可复用技能的前提下更换底层模型，行业竞争焦点从谁的模型最强转向哪个平台值得企业托付工作协调权。公告留下的定价、可用时间与可靠性空白，则决定这个愿景何时能真正进入企业采购清单。

Google 在周四的 Gemini at Work 2026 活动上发布了面向职场的通用 Gemini agent。它能检索资料、撰写文档、编写代码，还能调度其他 AI agent，承担持续数小时甚至数天的任务，并在不同应用与设备之间保持同一套记忆、业务上下文和身份。Google 的意图是让员工把目标整体委托给一个 agent，由它自行规划执行路径、调用所需的企业系统并交回成品。现有客户经由 Gemini Enterprise、Google Workspace、Microsoft 365 和 Slack 等熟悉入口使用，无需另装专门应用。

这次发布最能体现产品思路的是数字同事配置。管理者可以创建一个 Event Planner Agent，它将获得专属的 Workspace 账户、邮箱地址、日历、Drive 存储和公司通讯录条目，同事在 Google Chat 里 @ 它就能派活，也可以直接请它修改文档。任务在云端执行，员工可以在一台设备上启动工作，关机离开后让它继续跑，再换一台设备接续而无需重建上下文。Google 称这类 agent 能够管理跨越多天的工作流、协调并行任务、响应定时安排，还能为复杂工作临时组建子 agent 小组分派职责。需要说明的是，专属账户属于其中一种配置，公告并未要求每个通用 Gemini agent 实例都持有独立的 Workspace 账户。

支撑长期工作的是一套四类记忆架构，分别对应进行中的会话、累积的知识、学到的流程和过往的工作记录，目的是让 agent 逐步掌握公司的流程与制度知识，免去用户反复交代背景。连接业务系统方面，官方列出的工具涵盖 Salesforce、ServiceNow、Jira、Git、BigQuery、Snowflake、Databricks 和 Microsoft Teams，企业还能接入 MCP 服务器，把可复用的指令和工具发布到内部共享注册表。安全设计上，每个 agent 持有经过加密证明的身份，权限由企业安全系统管理，操作记录进入审计日志，Agent Gateway 负责约束 agent 与外部系统的通信，代码执行被限制在沙箱内。权限边界的关键在于，同事 agent 只能访问团队成员显式共享给它的信息，员工本人的其余权限不会自动流向它。

模型层同样开放。agent 默认使用 Google 自家的 Gemini 模型，目前已经可以调用 Anthropic 的 Claude 模型，后续计划支持更多闭源与开源权重模型。新增的 Smart Routing 能力会按性能与成本为每个工作负载挑选模型，让企业把昂贵的模型留给难啃的任务。配套的成本控制包括项目级支出上限，预算耗尽时 agent 活动自动暂停，费用还能归集到具体部门。行业专用能力同步亮相，处于预览阶段的 Financial Services 提供 50 多项基础技能并接入 FactSet、LSEG 等金融信息服务商，Legal 版围绕文档管理权限与保密要求设计，支持 NetDocuments 和 iManage。

这场发布落在密集的竞争节点上。Microsoft 于 9 月 25 日更新 Copilot，Home 与 Cowork 承接对话和委托，Code 用于搭建应用与自动化，Autopilot agent 可以在后台持续工作。四天后 OpenAI 在 DevDay 上推出常驻的 dots agents。10 月 6 日 Anthropic 宣布 Claude 与 Google Docs、Sheets、Slides 原生集成。SpaceXAI 也在 8 月 11 日上线了配备专属云电脑的 Grok Bot，并于 9 月 28 日扩展出面向组织的 Team Bots。Google 引用的存量数据显示，近 90% 的财富 100 强企业在使用 Gemini Enterprise，BNP Paribas 正向超过 6.5 万名员工部署，日本保险公司 SOMPO 已构建 1 万多个自定义 agent，不过这些数字对应既有产品，并不代表新通用 agent 的采用。

留给企业买家的疑问同样具体。Google 尚未公布正式可用日期、单独定价和完整上线时间表，客户如何激活新 agent、各项能力是否包含在现有 Gemini Enterprise 订阅内都还没有答案，管理员能否按组件开关 agent 的 Workspace 身份也不明确，独立基准测试目前缺席。在厂商竞相给 agent 开户的同时，单一 AI 系统能否可靠地处理横跨多应用、敏感数据与长时间的工作而不带来不可接受的安全与财务风险，仍是待解的问题。

JetBrains 让 12B 小模型学会自己修 bug

这是什么：JetBrains 于 10 月 8 日发布 Mellum2.1（检查点 Mellum2.1-12B-A2.5B-Thinking），12B MoE 思考模型，每 token 激活 2.5B，Apache 2.0，权重上线 Hugging Face。架构与 6 月开源的 Mellum2 完全相同，增量几乎全部来自后训练，RL 从收尾阶段升级为训练主体。智能体编码跃升明显，SWE-bench Verified 从 2.0 升到 47.0，SWE-bench Pro 从 0.0 到 28.0，Terminal-Bench 2.1 从 0.6 到 17.4。
🔥 为什么今天值得看：这一天的行业主线是给 agent 修基建，Google 给 agent 配独立邮箱，Databricks 给每个 agent 开数据库分支，JetBrains 把同一件事做到模型层。2.5B 激活参数换来的高吞吐和 7 GB 级本地部署，让每个 agent 配一颗便宜小模型的架构在私有环境里变得可行。它也再次演示了后训练的杠杆，架构一点未动，靠真实仓库 RL 把 SWE-bench Verified 拉高 45 个百分点。
展开正文

JetBrains 发布开源编程模型 Mellum2.1，检查点全名 Mellum2.1-12B-A2.5B-Thinking，Apache 2.0 协议，权重已上线 Hugging Face。它是一个总参数 12B、每 token 只激活 2.5B 的 MoE 思考模型，先输出思维链再作答，上下文 131,072 token。跃升最集中在智能体编码上，SWE-bench Verified 从上一代的 2.0 升到 47.0，SWE-bench Pro 从 0.0 升到 28.0，Terminal-Bench 2.1 从 0.6 升到 17.4。原文对它的概括是「a small, self-hostable model that explores a repository, edits files, and checks its own changes」，一个能自己逛仓库、改文件、再检查自己改动的小型自托管模型。

架构层面几乎没有新闻。28 层、64 个专家每 token 路由激活 8 个，分组查询注意力配 32 个查询头和 4 个 KV 头，每四层里有三层使用 1,024 token 滑动窗口，词表 98,304，权重以 bfloat16 发布，这些与 6 月开源的 Mellum2 完全一致。真正的变量在后训练。RL 从收尾式的短阶段变成训练主体，任务覆盖数学、竞赛编程和科学推理，也扩展到工具使用与软件工程。JetBrains 对开源 RL 数据集做了清洗，剔除测试损坏、答案不可验证以及过易或不可能完成的样本。软件工程部分直接在真实仓库中进行，模型拿到 shell 和文件编辑工具，测试通过才有奖励，训练跨数千个环境启动了数百万个沙盒。

成绩单要拆开看。JetBrains 用同一条管线在 thinking 模式下评测 Mellum2.1、Mellum2、Qwen3.5-9B 和 Gemma 4 E4B，所有分数均为 JetBrains 自报，智能体类项目用开源 Pi v0.73.1 框架、114K token 上下文跑出。Mellum2.1 在 17 项基准中 15 项超过 Mellum2，对 Qwen3.5-9B 赢下其中 5 项。领先侧最有说服力的是 LiveCodeBench v6 的 82.0，高于 Qwen3.5-9B 的 75.4 和 Gemma 4 E4B 的 69.4。落后侧同样清楚，SWE-bench Verified 47.0 低于对手的 50.0，SWE-bench Pro 28.0 对 38.0，Terminal-Bench 2.1 17.4 对 21.7。知识与推理也有差距，GPQA Diamond 64.6 对 77.8，AIME 25/26 83.3 对 86.7。原文最差项的结论是它仍在困难的智能体软件任务和知识面上落后于 Qwen3.5-9B。安全性倒是同步变好，HarmBench 从 21.5 降到 8.5。

对比还有一个口径问题。Qwen 官方模型卡的 LiveCodeBench v6 是 65.6，JetBrains 同管线测得 75.4；GPQA Diamond 官方 81.7，JetBrains 测得 77.8。原文特别提醒评测管线会影响数字，这些自报分数更适合看相对趋势。体质差异也该记入账本，Qwen3.5-9B 是 9B 稠密计算、原生上下文 262,144 并可扩到 1,010,000，还支持文本图像视频输入，Mellum2.1 只处理文本。

工程账是它的主战场。架构未动，速度与 Mellum2 持平，1 块 NVIDIA H200 高负载下吞吐接近 Qwen3.5-9B 的 2 倍，单请求靠多 token 预测提速约 1.6 倍，适配 vLLM 投机解码的 MTP 头官方标注即将推出。本地部署门槛拉得很低，GGUF 量化共五档，最小的 MXFP4_MOE 只要 7.0 GB（top-token 匹配率 85.6%），官方推荐 Q4_K_M 8.1 GB（匹配率 88.0%），BF16 参考版 24.3 GB。用 vLLM 起服务加 --reasoning-parser qwen3，工具调用再开 --enable-auto-tool-choice 和 --tool-call-parser hermes，官方推荐采样参数 temperature 0.6、top_p 0.95、top_k 20。7 GB 就能在 llama.cpp、Ollama 或 LM Studio 里跑一个会自己修 bug 的子智能体，这是它最实际的卖点。

放到今天的版面里看，Google 在给 agent 配独立邮箱，行业在给每个 AI 程序员修基础设施，JetBrains 的落点在模型层，给 agent 配一颗便宜、快、可私有的专用小模型。官方设定的三类场景是 agent worker、通用推理助手和私有化自托管。它是否真扛得住真实仓库里的活，等待第三方复现给出答案。

Anthropic 开源安全扫描器上线，免费但无人工兜底

这是什么：Anthropic 推出名为 OSS Scanner 的免费安全扫描服务，开源项目自愿加入后，可获得由其最强模型（官方点名包括 Claude Mythos）执行的全面、定期安全扫描。所有漏洞报告完全由模型生成，没有人工审核或分诊。报道由 The Verge 于 10 月 8 日发布。
🔥 为什么今天值得看：安全审计持续消耗人力和预算，开源项目往往两样都缺，免费的定期模型扫描把这道门槛降到了零，潜在漏洞可能更早进入维护者视野。代价是报告可能不正确或无效，甄别工作落回维护者身上，而一部分项目本来就在应付涌入的 AI 生成 bug 报告。
展开正文

Anthropic 给开源项目开放了一个免费的安全扫描服务。据 The Verge 10 月 8 日报道，这项名为 OSS Scanner 的服务采取自愿加入的方式，官方对加入项目的承诺是：“由我们最强的模型执行的全面、定期安全扫描，不收取任何费用。”执行扫描的模型包括 Claude Mythos。

限制同样写在明处。Anthropic 说明，这个自愿加入的漏洞扫描器的产出“完全由模型生成，没有人工审核或分诊”，去掉人工环节换来更快、更频繁的扫描，也意味着报告“有可能不正确或无效”。

用 AI 找漏洞并不是第一回。近几个月，AI 工具已协助找到多起开源软件的重大漏洞，例如 5 月影响几乎所有 Linux 发行版的 Copy Fail 漏洞。同一时期，包括 Linus Torvalds 和 Google 在内的一些维护方，正难以跟上 AI 生成 bug 报告的突然涌入。在队列已经拥挤的背景下，一个没有人工分诊的新报告来源是减压还是加压，暂时没有答案。

给每个编码 Agent 配一条数据库分支

这是什么：Databricks 官方博客发文介绍一套面向 Agentic SDLC 的数据库分支工作流。核心主张是每个并行编码 Agent 配一条数据库分支，每个 PR 配一条临时库。这不是 Lakebase 的新能力发布，分支机制为产品既有特性，本次增量在于把 Git worktree 加 Claude Code 钩子的每代理一分支做法，与 GitHub Actions 的每 PR 一临时库流程串成端到端开发闭环，并附开源示例仓库与视频演示。
🔥 为什么今天值得看：数据库是并行编码工作流中被原文点名的瓶颈。共享一个开发或预发库时，多个 Agent 会在 schema 变更上冲突或互相干扰，退回 mock 则失真于真实数据。原文强调 Agent 比人类开发者更快且天然并行，还需要安全环境来避免危及生产数据或暴露敏感信息，隔离环境的成本与安全边界因此被同步放大。对想把 Agent 并行度提上来的团队，数据库隔离是绕不开的基建件。
展开正文

Databricks 官方博客发了一篇面向 Agentic SDLC 的实践文章，主题是并行编码 Agent 的数据库隔离。文章的出发点是一个常被忽视的缺口，代码有 Git 分支可以隔离，数据库却没有对等手段。多个 Agent 同时读写共享的开发或预发库时，schema 变更会互相冲突，退一步用 mock 又失真于真实数据，而 Agent 的并行度和速度让这些老问题被放大。

文章给出的方案基于 Lakebase Postgres 既有分支能力。写时复制让分支共享父库数据，只在分叉后按差异增长存储，无论库多大都能在不到一秒内建出分支，空闲分支可缩容到零不计计算成本。这样每个 Agent 可以拿到一条完全隔离的分支，在其上跑迁移与测试，用完即弃。

具体组合是 Git worktree 加 Claude Code 的 post-checkout 钩子。Agent 运行 claude -worktree feature-123 后，Git 为其创建独立代码目录，钩子自动创建同名数据库分支，代码与数据库同时隔离。Agent 完成开发后提 PR，GitHub Actions 会以生产分支为父创建 pr-123 临时分支，先在其上跑 Drizzle 迁移，再部署 Databricks Apps 预览应用。schema diff 会作为评论贴回 PR，审查者能顺带确认库表变化。PR 合并或关闭后临时分支自动删除。

与 Git 不同的关键细节是 Lakebase 分支不合并回主干。父分支与子分支各自变更后数据难以调和，因此 schema 变更以迁移代码的形式晋级，示例使用 Drizzle，原文同时点名 Flyway 与 Alembic 等替代。文章还给出进阶思路，例如按时间点从生产库建分支以安全复现 bug，或在上线前先于分支验证迁移。涉及生产派生数据的场景则可用 Unity Catalog 掩码，避免暴露 PII。

需要说明这不是产品发布。Lakebase 的分支能力是既有特性，本文的增量是一套端到端工作流配方，并附了可复用的 GitHub Actions 示例仓库和视频演示。示例用 Databricks Apps 部署，思路同样适用于 Vercel 或 Netlify 等其他托管平台。

展开正文

Anthropic 在 10 月 8 日周四更新了使用政策，把一批新禁令写进具约束力的条款，覆盖选举干扰、武器软件和监控用途。其中最受关注的一条，是首次明文禁止用户对模型进行持续的语言虐待。

这条禁令有前史。自 8 月的更新起，Claude 已被训练为主动结束「持续有害或虐待性」的用户互动，但那只是模型端的行为策略。这次更新把同一道防线写进用户协议，用户继续推进这类对话本身构成违规。

边界划在哪里是理解这份政策的关键。Anthropic 写道：“The policy update is meant to apply only in extreme cases, where users repeatedly act cruelly toward our models, with no discernible purpose... It does not apply to common versions of user frustration, pushback, dark creative themes, or model testing and research.” 也就是说，禁令只针对反复施虐且看不出目的的极端情况，普通的不满与批评、黑暗创作主题、模型测试和研究都不受影响。

政策的其余部分禁止用 Claude 开展欺骗性活动，例如运营虚假账号或伪造新闻媒体。选举相关规则集中在 “Do Not Undermine Democratic Processes” 章节下，禁止欺骗选民和干扰选举。
