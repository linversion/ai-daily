Anthropic IPO数字很惊人，但预测不是收入

这是什么：Anthropic IPO 前的财务叙事正在升温：报道称公司预计 2028 年收入约 1900 亿至 2000 亿美元，另有泄露文件和播客言论继续推高市场想象。但这些信息并不等于 Anthropic 已正式披露的经营数据。
🔥 为什么今天值得看：IPO 估值往往建立在未来增长预期上。若预测、匿名信源和评论被混写成事实，读者就无法判断公司当前表现与未来假设之间的距离。

Anthropic 的 IPO 还没开始，最先被推到聚光灯下的，却是一组组惊人的数字。问题是：这些数字里，哪些是已经发生的收入，哪些只是尚未公开计算方法的预测？

这正是 Gary Marcus 在《The hyping of Anthropic’s IPO》中拆解的核心。他注意到，Anthropic 正处在 IPO 前受美国证券交易委员会监管的“静默期”，预计秋季上市。公司对外沟通受到限制，但泄露文件、市场传言和看多者的叙事并没有停。

最抓眼球的说法来自路透社报道：Anthropic 据称预计 2028 年收入约为 1900 亿至 2000 亿美元。这个数字来自两名“熟悉公司财务的人士”，但计算依据没有公开。换句话说，它更像一张没有展示公式的成绩单。数字很大，不等于证据链很完整。

同期还有几种更激进的判断。彭博社看到的泄露文件被用来证明 Anthropic 第二季度表现亮眼；All-In 播客中，Gavin Baker 声称 Anthropic 每个 token 都能赚钱；更早时候，Dwarkesh Patel 预测公司年收入可能达到 1000 亿至 1500 亿美元，后来又部分收回了这句话。

这里最容易混淆的是“事实”和“外推”。已泄露的文件、媒体转述和个人判断，分别处在不同的可信度层级。把它们拼在一起，再直接讲成公司已经实现的经营结果，就会让预测披上事实的外衣。尤其是“每个 token 都盈利”这种说法，还需要知道成本口径、模型组合、客户结构和时间范围，单独一句话无法替代完整财务披露。

这并不是说 Anthropic 没有增长，也不是说 IPO 估值必然不成立。它真正提醒我们的是，资本市场最兴奋的时候，恰恰要把数字拆回来源：谁说的，依据是什么，发生在什么时候，是否已经实现。1900 亿至 2000 亿美元是 2028 年的预测，不是今天的收入；1000 亿至 1500 亿美元同样是判断，而且其中一项已经被部分修正。

AI 公司的故事越来越像一场速度竞赛，但投资和判断不能只看谁喊出的数字更大。面对 IPO 叙事，最有价值的能力不是复述估值，而是给每个数字标注它属于财报、泄露、传闻，还是预测。

一台普通电脑，能跑好 Qwen 3.8 27B 吗

这是什么：阿里巴巴 Qwen 实验室发布 Qwen 3.8 27B。这是一款 Apache 2 许可、27B 参数、具备视觉能力的模型；其约 17GB 的 Q4_K_M 量化版本可在配置较好的消费级设备上本地运行，并支持工具调用、代码生成、长上下文与多令牌预测（MTP）。
🔥 为什么今天值得看：模型能力继续向本地硬件下沉。开发者不必先购买数据中心级设备，就能在笔记本或工作站上尝试视觉分析、离线工具和编码代理；但本地部署的真实门槛从“能不能加载”转向内存带宽、响应速度、上下文配置和推理成本。

依我之见，Qwen 3.8 27B 最值得关注的地方，不是又多了一个模型名字，而是一个 17GB 左右的量化文件，已经把视觉理解、工具调用、代码生成和长上下文能力带到了消费级硬件附近。阿里巴巴 Qwen 实验室这次发布的模型采用 Apache 2 许可证，参数规模为 27B，并且具备视觉能力。这个尺寸对本地部署很关键：它不像超大模型那样必须依赖数据中心，也不是只能做简单问答的小模型。配置较好的笔记本，已经有机会把它装进自己的工作流。

原文作者在一台 128GB 内存的 M5 Max MacBook Pro 和 NVIDIA DGX Spark 上测试了 LM Studio 使用的 17GB Q4_K_M 量化版本，也尝试了直接运行 llama-server。模型能处理图像中的目标检测，返回 0 到 1000 坐标范围的 JSON 边界框；它还可以调用工具、阅读较长上下文，并在编码代理场景中完成文件检索、修改和测试。从实际体验看，Qwen 3.8 27B 不是只能在排行榜上证明自己，它确实开始具备“本地干活”的完整形态。

但它有一个非常反直觉的默认值：推理努力级别设为 xhigh，也就是最高档。LM Studio 的 GGUF 版本保留了这个设置，于是模型会对极其简单的任务投入不成比例的思考。让它画一个圆，它可能自行规划渐变、同心圆、动画和交互效果；让它生成一只骑自行车的鹈鹕 SVG，作者的测试耗费了 21 分钟和 22,276 个推理 token，结果虽然精致，却远远不值等待时间。更麻烦的是，普通的 8,192 token 上下文限制可能很快被“思考过程”吃光。把上下文提高到完整的 262,144，才能避免这类任务过早撞上上限。

所以第一次运行时，不要迷信默认配置。把 reasoning_effort 调到 low，或者直接关闭推理，通常更符合本地电脑的现实约束。xhigh 只适合确实需要深度分析的任务；对于简单绘图、格式转换和短代码，过度思考不是能力，而是成本。视觉任务则展示了它的另一面：在 pelican 图片上，它准确返回了两个目标的边界框，还能据此生成一个离线标注工具。开启推理后，工具界面虽然有些过度设计，却完成了坐标缩放和框选渲染；关闭推理的版本则差一点才能一次运行正确。这说明推理并非毫无价值，关键是把它当成按需开启的预算，而不是永远踩到底。

作为编码代理，Qwen 3.8 27B 也有可用性。原文通过 Pi 和 LM Studio 连接模型，让它读取项目文件、回答认证机制问题，再根据 JSONL 会话记录编写并测试 Python 转换脚本。它具备长上下文、工具调用和代码生成这三个代理回路所需的基本条件。不过速度是硬伤：LM Studio 实测约为每秒 15 到 30 个 token。对于交互式编码，这足以工作，却很难让人忘掉托管 API 的即时反馈。

速度优化正在成为它能否日用的分水岭。Qwen 3.8 27B 支持多令牌预测（MTP）：由较便宜的机制预先猜测多个 token，再由主模型快速验证。作者在 DGX Spark 上用 llama.cpp 的 draft-mtp 配置测试，较 LM Studio 默认 GGUF 获得了约 72% 的提升。这个数字来自单次作者测试，不能当作独立基准或普遍保证；不同显卡、量化版本、上下文长度和服务参数都可能改变结果。同样，Qwen 自报 benchmark 显示它超过前代 Qwen 3.6 27B 及闭源 Qwen 3.7-Plus，但独立评测尚待观察，不能把厂商数字直接当成结论。

这款模型真正的意义在于，它把“本地模型能不能做正经工作”从抽象讨论变成了配置和取舍问题：17GB 文件、Apache 2 许可、视觉能力、工具调用和代码能力都已经存在；剩下的限制，是内存带宽、推理速度，以及你是否愿意为不必要的思考付费。普通电脑未必能让它跑得飞快，但只要关闭 xhigh、合理设置上下文，并尝试 MTP，它已经足以成为一个可部署、可调教的本地工作伙伴。

Claude 系统提示词公开：开发者终于能看见产品行为的边界

这是什么：Anthropic 官方文档公开了 Claude 网页版和移动应用所使用的系统提示词说明及更新历史。文档列出 Claude Opus 5（2026 年 7 月 24 日）、Claude Fable 5（6 月 9 日）、Claude Opus 4.8（5 月 28 日）、Claude Opus 4.7（4 月 16 日）、Claude Sonnet 4.6（2 月 17 日）和 Claude Opus 4.6（2 月 5 日）等条目，并说明 Claude 4.6 起每个模型 ID 对应一个固定快照。
🔥 为什么今天值得看：公开系统提示词更新历史，为开发者解释网页端与 API 输出差异提供了更清晰的边界。它适合用作调试、版本追踪和评测设计的参考，但不应被误解为 API 会同步采用这些指令，或意味着所有内部策略都已公开。

Anthropic 最近把 Claude 的系统提示词更新历史放进了公开文档。它公开的不是某个 API 调用参数，而是 Claude 网页版和移动应用在每次对话开始时使用的一层系统指令：例如提供当前日期，鼓励模型用 Markdown 输出代码块，并规定一些基础的回答行为。文档同时明确，这些系统提示词更新不适用于 Claude API。

这件事对开发者的价值，不在于“终于拿到了万能提示词”，而在于看见了一个产品层面的事实：你在 claude.ai 里体验到的 Claude，不等于你通过 API 调用到的 Claude。前者会随着网页端系统提示词的定期调整而变化；后者不自动继承这份文档里的更新。做产品、写评测或排查输出差异时，如果忽略这一层，很多所谓的“模型变笨了”或“同一个模型表现不一致”，其实可能是运行环境和指令层不同。

这份页面还提供了可追踪的版本时间线。最新条目包括 Claude Opus 5（2026 年 7 月 24 日）、Claude Fable 5（6 月 9 日）、Claude Opus 4.8（5 月 28 日）、Claude Opus 4.7（4 月 16 日）、Claude Sonnet 4.6（2 月 17 日）和 Claude Opus 4.6（2 月 5 日）。从 Claude 4.6 这一代开始，每个模型 ID 都对应一个固定快照，因此每个模型只保留一条记录；更早的模型则可能有多个按日期排列的提示词版本。

实际开发中，可以把它当成调试和评测的参考坐标。第一，区分网页端、移动端和 API，不要把网页端看到的行为直接当成 API 保证。第二，记录模型 ID、调用时间、自己的 system prompt 和工具配置，避免只记一个模型名称。第三，把关键行为写进自己的提示词、测试用例和回归评测，而不是依赖某个产品界面“当前刚好会这样回答”。

但文档与实际行为之间仍有边界。公开的是 Anthropic 选择发布的系统提示词更新记录，不代表所有内部策略、运行时上下文或安全机制都被披露，更不能据此臆测未公开提示。文档列出的日期也只能帮助定位变化，不能保证每一次输出差异都由系统提示词造成。对开发者来说，真正有用的透明度不是复制几段文本，而是知道哪些行为属于产品界面，哪些属于 API 合同，哪些仍需自己验证。

这也是这次更新值得关注的地方：系统提示词从“看不见的产品层”变成了可观察的版本资产。它没有消除黑箱，却让排查、评测和沟通多了一条证据链。

OpenAI据报解散预备团队，AI安全审查走向何方

这是什么：据《金融时报》报道，OpenAI于上月底解散preparedness（预备）团队。The Verge称，该团队原本负责评估模型是否带来严重风险并制定缓解措施，相关职责现按生物、网络等领域拆分并转入现有团队。
🔥 为什么今天值得看：这不是单纯的人事新闻。前沿模型安全审查需要明确的责任边界、跨领域风险总览和能够升级问题的权限。职责分散可能更贴近研发流程，但也可能让外部更难判断谁拥有最终审查与制衡权。

OpenAI的安全治理又出现了一次值得警惕的组织变化。据《金融时报》报道，OpenAI在上月底解散了负责“preparedness”（预备）的团队。The Verge援引这则报道指出，该团队原本的任务，是评估模型是否可能带来严重风险，并制定相应的缓解措施；如今，相关职责被按照生物、网络等具体领域拆分，转入现有团队。

这件事最值得关注的地方，不是一个部门的名字消失，而是前沿模型的风险审查机制是否仍然拥有足够独立、清晰的组织位置。所谓预备工作，处理的不是普通产品上线前的漏洞清单，而是模型能力继续跃迁后可能出现的高影响风险，例如模型在网络环境中的异常行为，或被滥用于生物领域。把风险按专业方向交给既有团队，理论上可以让责任更贴近实际研发和产品流程，也可能提高执行效率。但从外部观察者的角度，职责拆分之后，谁负责跨领域风险的总览、谁拥有叫停或升级问题的权限，就变得更难看清。

OpenAI近期并非只有这一次安全团队调整。报道提到，这家公司此前已经解散AGI readiness和superalignment团队；伦理负责人Chloé Bakalar、首席未来学家Josh Achiam以及安全负责人Johannes Heidecke也相继离开。原预备团队负责人Dylan Scandinaro则将转向研究“递归自我改进”AI的影响。前OpenAI安全负责人Jan Leike对《金融时报》表示，公司可能是在追逐更“夺目”的产品时忽视了安全。这个批评属于外部人士的判断，不能直接等同于公司安全工作已经停止，但它确实反映了组织连续变化带来的信任成本。

时间点也不能被忽略。报道将这轮调整放在OpenAI筹备大规模IPO的背景下。资本市场更容易量化收入、用户增长和产品发布，却很难量化一次没有发生的事故，以及为了避免事故而放慢的发布节奏。当公司进入更强的商业化压力周期，安全团队如果从集中式机构变成分散在各产品线里的职能，治理就必须依靠更明确的标准、审计记录和升级通道来补足。否则，“安全仍然有人负责”可能只是组织图上的一句话，而不是能够影响决策的机制。

对开发者和普通用户而言，真正应该追问的不是“OpenAI还有没有安全团队”，而是三个更具体的问题：风险评估结果是否会在模型发布前留下可复核记录；发现高风险能力时，负责团队能否独立把问题提交到最高决策层；模型上线后，监测、回滚和外部报告是否有清楚的责任人。报道目前只说明了组织变化及相关回应，并没有证明所有安全工作都已停止，也没有给出拆分后新机制的完整细节。

前沿AI竞争进入深水区后，安全治理不能只靠少数明星团队的存在感。它需要稳定的职责边界、可追踪的证据链，以及在商业目标与风险判断冲突时仍然有效的制衡。部门解散本身不必然意味着安全倒退，但如果每次重组都让外界更难知道谁在评估、谁在拍板，那么模型能力增长得越快，信任赤字也会扩大得越快。

AI水印改写文字，谁来为每个词的选择负责

这是什么：Anthropic 正计划让新的 Claude 模型对生成文本加入所谓的“水印”。争议的关键不在于文字里是否藏着一串人眼看不见的字符，而在于模型生成每一个 token 时，可能会为了留下可检测的统计痕迹，改变原本的选词概率。系统在每个生成节点动态划分“绿色”和“红色”词语，并略微提高前者被选中的概率；足够长的文本积累后，持有密钥的一方就可能判断文本是否由 Claude 生成或修改。
🔥 为什么今天值得看：写作不是把同义词随便互换。模型本应综合上下文、语义、文体和用户意图选择最合适的词；如果某个词仅仅因为处在水印机制偏好的列表里而获得额外概率，更准确的表达就可能被挤掉。图片可以通过不影响观看的元数据留下水印，文字却只能通过实际选了哪些词来留下信号，因此变化发生在文字本身。

发生了什么

Anthropic 正计划让新的 Claude 模型对生成文本加入所谓的“水印”。争议的关键不在于文字里是否藏着一串人眼看不见的字符，而在于模型生成每一个 token 时，可能会为了留下可检测的统计痕迹，改变原本的选词概率。Daring Fireball 对这项计划的解读指出，这是一种语义层面的隐写方法：系统在每个生成节点动态划分“绿色”和“红色”词语，并略微提高前者被选中的概率。单次选择看不出规律，但足够长的文本积累了大量选择后，持有密钥的一方就可能据此判断文本是否由 Claude 生成或修改。

Anthropic 早先的说明称，这种 watermark“不可察觉”，不会改变回答的含义、质量或可读性。后续发布的解释才用更通俗的方式描述了技术思路。问题因此从“能不能识别 AI 文本”，变成了“为了识别，模型是否被允许在写作过程中偏离最好的表达”。

为什么影响写作

写作不是把同义词随便互换。“He leaped at the chance”和“He jumped at the opportunity”可以表达相近意思，却有不同的节奏、语气和精确度。一个模型在生成时本应综合上下文、语义、文体和用户意图，选择最合适的词；如果某个词仅仅因为处在水印机制偏好的列表里而获得额外概率，另一个更准确的词就可能被挤掉。变化也许很小，却发生在文字本身，而不是文件外部的元数据。

这也是文本水印和图片、音频水印的区别。图片文件可以携带不影响观看的元数据，文字却只能通过实际选了哪些词来留下信号。对私人与 Claude 的对话、人工写作后的校对，或只是把模型当作阅读和整理工具的用户来说，输出仍可能被同一套机制处理。用户未必打算冒充作者，却要承担模型为合规而增加的表达偏差。

证据与限制

目前能确定的是报道所引用的技术描述和政策背景，不是任何一段具体文本都能被可靠判定为 AI 生成。水印检测依赖秘密密钥，Anthropic 只能检测 Claude 体系留下的信号；文本太短时，样本不足，统计置信度也会明显下降。即便文本足够长，结果仍是概率判断，不是作者身份的数学证明。

报道还提到，相关欧洲透明度规则针对超过 200 tokens、约 150 个单词的文本，并要求服务条款限制移除水印；其目标据称还包括让信号抵抗截图、扫描、OCR、复制粘贴和翻译等常见处理。不过，重新组织文字的工具或大量人工改写，仍可能削弱这种信号。换句话说，它可能对诚实使用辅助工具的人制造怀疑，却未必能阻止有意欺骗者。这里不能进一步推断 Anthropic 存在恶意动机；更准确的批评是，产品选择把合规成本直接放进了每一次文字生成。

社区在争论什么

争论的底层问题不是“AI 是否应该被识别”，而是谁有权决定写作质量可以牺牲多少。支持水印的人会强调来源透明、教育诚信和内容治理；反对者则认为，检测机制如果依赖悄悄改变词语选择，就把普通用户也纳入了审查范围。最值得警惕的是一个尴尬的组合：信号足够宽，会让辅助写作被怀疑；信号又足够脆弱，动机明确的人可以通过重写绕开。

对开发者和内容生产者而言，现实的应对不是把检测分数当成作者证明，而是保留原始草稿、修改记录和人工决策过程。对模型公司而言，至少应清楚说明何时启用水印、影响哪些输出、检测的置信边界是什么，以及用户能否选择不让私人文本承担额外的表达约束。能否识别来源是一项治理能力，但不应以悄悄改写用户要表达的内容为代价。

模型真的在故意变笨吗？推理能力与事实记忆的交换

这是什么：一篇评论文章提出，模型在数学和代码任务上的推理分数持续上升，但在不允许工具的事实问答中可能表现较弱；作者将其解释为从权重中的事实记忆转向可压缩、可迁移的推理能力。
🔥 为什么今天值得看：这个角度把‘模型变聪明或变笨’拆成了推理、知识存储和运行时工具三个问题。若事实放在检索系统、文档和工具中，模型可以更小、更易更新，错误也更容易定位；但这仍需要可靠的检索、引用和评测，不能把单篇评论的解释当成行业共识。

依我之见，‘模型变笨了’这个说法，真正值得讨论的不是模型有没有突然退化，而是我们究竟用什么标准定义聪明。一篇题为《Models Are Getting Dumber on Purpose》的评论文章提出了一个反直觉判断：新模型在数学和代码任务上越来越强，但在不允许调用工具的事实问答中，表现却可能更差。这不一定是训练失败，也可能是模型设计主动把参数和训练资源从事实记忆转向推理程序。

现象：推理分数上升，事实回忆却没有同步

文章列举了几组对比。GLM-5.2 在 AIME 2026 上达到 99.2%，每个 token 约有 400 亿个活跃参数；Qwen3.5 的成绩为 91.3%，活跃参数约 170 亿；DeepSeek V4-Flash 每个 token 的活跃参数约为 130 亿。文章还把这些数字与一个未经官方确认的 GPT-4 参数规模传闻作比较，因此这部分只能作为评论中的参照，不能当作严格的同口径评测结论。若只看数学和代码基准，确实容易得出‘单位参数的推理效率大幅提高’这一印象。

但在 SimpleQA 这类不允许工具、主要考察事实回忆的基准上，文章称当前领先模型 Gemini 2.5 Pro 的准确率也只有 53%。文中还引用 Artificial Analysis 对 Qwen3.5 4B 和 9B 的知识基准观测，称其幻觉率约为 80% 至 82%。这些数据来自文章转述，测试设置和指标定义需要单独核验，不能直接外推到所有模型或所有使用场景。

为什么会有这种取舍

事实需要大量存储空间。文章引用《Physics of Language Models》系列的估计，认为每个参数承载的事实知识大约需要 2 bit 左右。想让模型记住大量人物、地点、软件包接口和不断变化的产品信息，就要把它们固化进权重，而权重规模、训练成本和更新周期都会增加。更麻烦的是，事实会过时：库的 API、价格、职位和网页内容都在变化，模型训练完成后，里面的知识就开始老化。

相比之下，推理程序更容易被压缩和迁移。拆分问题、保存中间状态、检查矛盾、失败后回溯，这些是可以通过蒸馏和强化学习迁移到更小模型中的通用步骤。于是，一种可能的工程路线是：权重保留理解问题、规划步骤和判断来源可信度所需的广度，把具体且易变的事实放到检索、网页搜索、文件系统和其他工具里。模型负责推理，运行时系统负责提供材料。

这并不等于所有模型都在故意变笨

文章的测试范围主要围绕数学、代码和事实问答的对比，且大量结论来自单篇评论中的数据整理。它没有证明各实验室存在统一的‘变笨计划’，也不能说明所有模型都牺牲了知识。反方解释至少有几种：不同基准考察的能力并不相同；事实题的覆盖面、提示词和评分方式会影响结果；小模型可能只是训练数据覆盖不足；模型也可能知道答案但在校准和拒答上做得不好。把这些现象直接归结为有意设计，是一个有吸引力、但仍需更多同口径实验支持的解释。

这篇文章最有用的结论，是把模型能力拆成了两个可独立优化的部分。一个没有工具的模型，应该在不确定时明确承认不知道；一个接入检索的系统，则要让来源可打开、知识库可修改、回答可以回归测试。外置事实并不能消除幻觉：模型仍可能误读文档、拼接冲突来源。但错误至少有地址，能定位、修复并验证，而不是只能等待下一轮训练。

文章进一步推测，若把事实存储从权重中移出，20B 到 40B 规模、4-bit 量化的模型可能更接近在 24GB 消费级显卡上运行。这个判断是对趋势的预测，不是已经实现的产品承诺。对开发者而言，实际启示很明确：评估模型时不要只看推理榜单，还要测试事实准确率、工具调用、引用质量和不确定性表达。模型显得更笨，有时只是因为它不再把世界硬编码在自己体内；真正的问题是，我们有没有为它接上可靠的外部记忆。

AI 额度也能倒手：Token Broker 正在形成新的中间层

这是什么：一笔没用完的 AI 额度，正在变成别人手里的生意。Vectoral 的调查直接联系额度经纪人，并发现 AI Credits、AICreditMart、CheapCredits 等公开交易渠道。经纪人通常以 30% 至 80% 的折扣收购或转售创业公司的闲置推理额度。
🔥 为什么今天值得看：创业公司之间交换额度并不新鲜，新变化是零散互换被商业化。经纪人把请求代理到可能由多把密钥组成的池子里，买家获得折扣，卖家把闲置额度变现，AI 额度因此出现了类似代币的流动性。

一笔没用完的 AI 额度，正在变成别人手里的生意。创业公司收到陌生邮件：有人想买下它们闲置的推理额度，再以折扣卖给下一位用户。Vectoral 的调查把这群中间人称为 token broker（额度经纪人）。他们不一定转交云厂商的 API 密钥，而是把请求代理到一组可能来自不同卖家的密钥池中。

这门生意的起点并不神秘。创业公司之间交换额度早已有之，作者此前也知道创业社区和群组里存在这类交易。变化在于，零散的互换开始被商业化，出现了专门的经纪人、交易网站和公开招揽。对卖家来说，闲置额度可以换回现金；对买家来说，折扣意味着更低的模型调用成本。额度因此像一张不能直接流通、却能被重新包装的代币。

作者从朋友那里拿到经纪人的邮箱，前两封邮件退信，第三封终于得到回复。对方提供的货量很惊人：每天可供使用的额度达到 10 万美元。交易并不是把提供商密钥直接交出来，而是由经纪人充当代理，把请求转发出去。买家看到的是一个入口，背后可能连接着经纪人掌握的密钥池。

公开市场也已经出现。AI Credits 和 AICreditMart 把自己定位为额度市场，覆盖多家云服务和推理提供商。AI Credits 的卖家列表显示折扣幅度约为 30% 至 80%，并允许卖家选择交付方式。CheapCredits 则把自己包装成路由器，宣称靠“批量定价”实现折扣，并给出统一 40% off 的价格。作者根据行业经验判断，如果没有成为提供商的顶级客户，这样的折扣很不寻常，因此怀疑其供给来源另有渠道。该网站还提供数据处理协议，面向希望满足 GDPR 要求的用户。Tokvana 和 Neokens 也采用类似的批量折扣叙事。

交易不只在网站上发生。作者还在 Telegram 看到相对活跃的相关频道，在 Reddit 发现出售 YC Startup School 额度和折价 API 额度的帖子，封闭的创业者群组里也可能有类似信息。作者对所浏览的网站、论坛和转售方做出的粗略估计是：市场上可能有数千万额度在被挂牌出售。但这不是完整行业规模，也不是经过审计的交易额。

真正值得注意的，是价格、合规和稳定性之间的拉扯。折扣越深，买家越难确认额度来源、授权边界和服务能否持续。代理转发隐藏了实际密钥，却也让请求链路更不透明。调查最后提醒，随着公司更关注成本，额度流动性为滥用留下的空间可能引来提供商打击。AI 额度一旦能被转手，模型经济里就会多出一层中间人；但能交易，不等于可长期使用，更不等于合规。
