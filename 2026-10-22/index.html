Anthropic 发布个人智能体 Claude Duet，每天替你盯应用，花钱前先问你

这是什么：Anthropic 发布了新产品 Claude Duet，一个替人打理日常事务的 AI 智能体，定位专业人士和小企业主，对标 Meta 的 Muse 和 OpenAI 的 Dots。它以研究预览形式推出，有 iOS 和 Android 独立应用，也能从网页版 Claude 进入，底层模型是 Claude Opus 5.5。

The Verge 与 VentureBeat 两家媒体同步报导了 Anthropic 的新动作。这家公司刚刚推出名为 Claude Duet 的新产品，直接对标 Meta 的 Muse 和 OpenAI 的 Dots。三者做的是同一类东西，替用户打理日常事务的 AI 智能体。

Claude Duet 面向专业人士和小企业主，以「研究预览」的形式推出。研究预览指官方明说的早期测试版，先放给一部分人用，边用边改。它有 iOS 和 Android 上的独立应用，也能从网页版 Claude 进入，底层基于 Claude Opus 5.5。

它的一天是这样运转的。每天早晨，Duet 发来一份简短简报，汇总各个已连接应用里最重要的事项。白天它持续盯着这些应用，只在确实需要用户出面时才发消息。任务也可以直接交给它，小到安排会议，大到用几十个工具搭仪表盘、做财务或销售预测，原型设计和网页应用开发也接。

Anthropic 自己也承认产品还早。官方的说法是它「仍可能误读一条消息线程，或对什么算紧急判断失准」，订票这类个人跑腿事务也「没那么强」。

AI 研究系统参与建造的开源编程模型 Flint，笔记本可跑

这是什么：Recursive Superintelligence 于 10 月 21 日发布首个模型 Flint，一个总参数 39.8B、每 token 约激活 2.5B 的开源编程模型，权重以 Apache 2.0 许可证上架 Hugging Face，免费可下载。它能翻代码库、修 bug、实现功能、写测试，在 48GB 内存的 Mac 或 NVIDIA 显卡上本地运行，4-bit 权重约 23GB。公司称自动化研究系统 Eureka Machine 参与构建了几乎整个技术栈，TechCrunch 报道一支小团队四个月内从零完成开发。
🔥 为什么今天值得看：这次发布把两件事推到台前。造模型的方式上，如果 Eureka Machine 这样的自动化研究系统能稳定产出架构、量化方案和专用内核，小团队就能用更少的人、更短的周期迭代模型，Recursive 把 Flint 称为递归自我改进的早期公开测试，公司预期每个新模型都会让 Eureka Machine 变成更好的研究员。使用侧，编程智能体对隐私和成本敏感，Flint 让代码留在本地、免按量计费；Meta 上周发布的 Muse Spark Open 要 816B 参数和至少 1TB 内存，Flint 把可用的本地编程模型门槛拉到一台高配笔记本。
展开正文

10 月 21 日，MarkTechPost 和 TechCrunch 同日报道了 Recursive Superintelligence 的第一个模型 Flint。这是一家去年成立的公司，CEO 是 Salesforce 前首席科学家 Richard Socher，今年 5 月走出隐身状态时融资 6.5 亿美元，估值 46.5 亿美元，投资方包括 GV、Nvidia 和 AMD Ventures。Flint 是开源权重的编程模型，已上架 Hugging Face，许可证为 Apache 2.0。

它为编程智能体设计，能翻代码库、修 bug、实现功能、写测试，纯文本输入输出，支持 OpenAI 兼容的工具调用。运行门槛不算高，一台 48GB 内存的 Mac（M4 Pro、M5 Pro、M5 Max 都可以）或 48GB 显存的 NVIDIA 显卡就能带动，4-bit 量化版本（把权重数值精度压低，文件随之变小）约占 23GB 磁盘。代码从头到尾留在自己电脑上，断网也能干活；云服务按 token 计费的账单（token 是模型处理文本的最小单位，一个汉字约合 1 到 2 个 token），在这里一并省掉。

它塞得进笔记本又跑得快，靠的是混合专家架构（MoE）。稠密模型每生成一个 token 都要动用全部参数，MoE 模型把参数拆成许多组专家，由路由器按当前输入挑几组来干活。Flint 总参数 39.8B，共 49 层，其中 47 层是 MoE 层，每层 256 个专家里每个 token 只激活 6 个，外加 1 个常驻的共享专家，任何时刻真正参与计算的只有约 2.5B。作为参照，Meta 上周为 Mac 发布的开源模型 Muse Spark Open 有 816B 参数、至少需要 1TB 内存，Flint 把这个门槛压到了一台高配笔记本上。

成绩单要分开看，以下数字全部由 Recursive 自报。SWE-bench Verified（修复真实软件 bug 的基准）74.2%，IFEval（指令遵循测试）95.1%，LiveCodeBench v6 80.3%；终端任务基准 Terminal-Bench 2.1 只有 54.9%，同场竞技的稠密 Qwen 3.8 拿到 73.0%。官方把 Flint 放在 50B 以下 MoE 模型的首位，全场最强暂时还轮不到它。公司也承认它比大型付费编程助手需要更多引导，大任务要拆成小步来做。早期口碑不差，Wired 的 Will Knight 在一台 48GB 内存的 Mac 上用它做出了待办事项应用和一个网页调研工具，他的体验里更小的编程模型常出错或偏慢，Flint 每次都完成了他的编码请求。

速度数字有两个口径，需要分开引用。Richard Socher 的发布推文称 MacBook Pro 上每秒输出 125 个 token 以上，64GB 的 NVIDIA RTX Spark 上超过 150。TechCrunch 报道的 Recursive 自测成绩是 M4 Pro 版 MacBook Pro 约 131 tokens/s，约为同一台机器上 Gemma 4、Nemotron 3.5 Lightning（58 到 69 tokens/s）的两倍。官方还称它比编码分数相近的 25 到 40B 稠密模型快 5 倍以上，以上均为短上下文场景的成绩。

真正让行业留意的是造模型的方式。Recursive 称自动化研究系统 Eureka Machine 参与构建了几乎整个技术栈，覆盖预训练、后训练和推理；TechCrunch 报道，一支小团队四个月内从零把它造了出来。Eureka Machine 提想法、跑实验，按结果决定下一步试什么。它在 Flint 项目里交出的东西分量不轻。架构上，它从 35B 总参数、3B 激活的基线出发，搜索出 40B/2.5B 的配置。它还把通常保持高精度的输出层压到 4-bit，再让 16-bit 版本当老师做离线蒸馏把精度补回来，训练步数较量化感知训练基线近乎减半。内核方面，它为 M4、M5 芯片写了一个 Metal megakernel，把整个解码过程融合执行。TechCrunch 还提到，Recursive 称低比特训练让 Flint 缩小了 71%，质量几乎没有损失。

AI 造 AI 正是 Recursive 押注的方向，也是这个行业争论最大的想法之一。有研究者担心会自我改进的 AI 脱离人类控制，现阶段 Recursive 的版本是一个有人监督的研究助理，公司没有说 Eureka Machine 究竟省了多少人力。OpenAI 上个月披露，到 8 月中旬，它的 AI 智能体每积累 3.1 个工作日的工作量，对应人类研究员 1 个工作日。Socher 对 Wired 表示，长期目标是让 Eureka Machine 实现完整的递归自我改进，人能监督全程，出问题随时叫停。

OpenAI 发官方公告，宣布把自家前沿模型和编程智能体 Codex 放进谷歌云的模型商店 Model Garden。两家在 AI 上是最直接的对手，谷歌自己也做模型，如今对手的云成了 OpenAI 模型的货架。

OpenAI 总裁 Greg Brockman 说：“这次合作是重要的一步，让我们最强的模型和 Codex 出现在客户已经在构建的地方，也给了客户更多使用前沿 AI 的选择，我们会一起把智能体生态做大。”谷歌云 CEO Thomas Kurian 的说法是，谷歌云要给客户足够宽的模型选择面，其中也包括 OpenAI 的模型，让每个任务都能配上合适的模型，质量更好，成本更低。

公告还提到 OpenAI 模型即将进入谷歌的 Antigravity 与 Gemini Agent，企业能在谷歌自家产品里选 OpenAI 的模型干活。正式可用计划在数周内推出，眼下只能提交访问申请。公告结尾写明，微软仍是 OpenAI 的主要云合作伙伴。

Vercel 开源 durable-harness，编程智能体崩溃后从日志续跑

这是什么：Vercel 于 10 月 21 日开源了 npm 包 durable-harness，版本 0.0.x，许可证 Apache-2.0，用 TypeScript 写成。它给 Pi、OpenCode、fx、Claude Code、Codex 五种编程智能体外加一层持久化日志，让这些智能体在程序崩溃、超时或重新部署之后能读日志接着干，已经完成的调用不重跑、token 不重复计费。
🔥 为什么今天值得看：编程智能体正在从个人电脑搬进云端，一跑几小时的任务交给云函数执行，而云函数随时可能死掉，一次网络错误就可能让工作白做，带持久硬盘的虚拟机也记不清哪些调用已经完成。durable-harness 用一份日志记下每一步的意图和结果，把崩溃丢工变成换一个函数接着干。它在同类方案里的差异点是直接包装这五种现成的智能体框架，Temporal 加 OpenAI Agents SDK、Inngest AgentKit、Cloudflare Agents SDK 都没有披露对 Claude Code 和 Codex 的包装支持。
展开正文

让 AI 编程助手连续干几个小时的活，最怕碰到的事是程序中途崩掉，辛苦干的进度全没了。10 月 21 日，Vercel 开源了一个叫 durable-harness 的 npm 包，专门解决这个问题。装上它之后，Pi、OpenCode、fx、Claude Code、Codex 这五种编程智能体的每一步工作都会写进一份持久化日志，程序崩溃、超时或者重新部署之后，新接手的函数读一遍日志就能接着干，已经完成的部分不用重来。这个包目前是 0.0.x 实验版，许可证 Apache-2.0。

这类智能体本来是为个人电脑设计的。它们把会话放在内存里，代码和历史记录就躺在本地硬盘上，中断之后恢复起来，一条提示就够。搬进云端后情况变了。云函数随时可能死掉，一次网络错误或一轮失败的调用就可能把工作丢掉，带持久硬盘的虚拟机也记不清哪些调用已经完成。Vercel 团队在原文里就点了这个痛点。

durable-harness 的做法是给每一步记账。模型或工具的调用要跑之前，它先把意图写进日志，调用结束后再把结果补上，每一轮工作都由一条 Vercel Queues 消息背书。这份日志放在函数之外的地方，函数死掉它也不会丢。函数死掉之后，队列把这轮工作交给一个新函数，新函数读日志，分清哪些已经完成、哪些还没跑到，然后接着干。它的底座和 Vercel Workflow SDK 是同一套接口，存储、队列和数据流都包在一个接口后面。

已经完成的调用直接从日志里读结果，模型用过的 token 不会重复计费。工具被分成两个重放等级。查询这类可以安全重跑的操作属于 safe 级，崩溃后允许再执行一遍；退款这类绝对不能重复的操作属于 never 级，系统绝不替它跑第二次，只会告诉模型这件事可能已经发生过。

文件和命令的存放给三种选择。virtual() 把文件放进会话日志，配一个不联网的 bash 兼容 shell，大约能装 500 个文件；临时文件可以放内存里，每一轮结束自动清空；第三种是给会话配一个挂载了 Drive 的 Vercel Sandbox。模型自己挑的 shell 命令永远不会跑在函数的磁盘上。待办清单这类结构化文档也存在日志里，单个不能超过 64KB。智能体的会话记录文件同样会镜像进日志，Claude Code 的 transcript、Codex 的 rollout、OpenCode 的 event store 都在这份保护范围内。

换运行环境不用改代码。同一份智能体代码既可以直接跑在 Vercel 平台上，会话在 Agent Runs 里能查，也能在本地拿文件直接跑、零配置；自托管则用 Postgres World 组件（5.0.4 及以上版本），环境要 Node.js 22 及以上，改 WORKFLOW_TARGET_WORLD 和 WORKFLOW_POSTGRES_URL 两个环境变量就能迁过去，Vercel 博客还提到了 MongoDB、Redis 和 Turso。

这个方向上已经有几家在做。Temporal 配 OpenAI Agents SDK 的组合今年 3 月 23 日已经正式发布，Inngest AgentKit 和 Cloudflare Agents SDK 也在做类似的事。durable-harness 的差异点在于直接包装这五套现成的智能体框架，给它们外挂持久化能力。同时要看清它的成色。它还是 0.0.x 实验版，Vercel 没公布任何延迟或吞吐的基准测试，恢复效果也都是 Vercel 自己报告的。Claude Code 和 Codex 只能跑在 Vercel Sandbox 里，自托管也不例外，Pi 和 OpenCode 则可以直接跑在函数内。

NVIDIA 开源 Kumo Relational，免训练预测数据库

这是什么：NVIDIA 在 Hugging Face 官方博客宣布开源预训练关系数据基础模型 Kumo Relational，官方称它是第一个在常见关系型数据基准上超过监督学习的基础模型。接上企业数据库，用声明式的预测查询语言 PQL 写明要预测什么，模型自动收集最多 10000 条历史样本当上下文，单次前向传播就给出客户流失、需求、欺诈这类预测结果，任务专属训练和特征工程都省了，表也不用摊平。
🔥 为什么今天值得看：语言和图像领域已经被基础模型改写过一遍，一个通用大模型替代了过去每个任务一个小模型的打法。结构化数据一直没跟上，企业核心决策靠关系型数据库支撑，预测建模却还要数周特征工程和逐任务调管道。Kumo Relational 把一个新预测从立项项目缩成一条查询，以前嫌太费事做不起的场景，现在小团队也能碰。它同时面向 AI 智能体开放，智能体用 PQL 就能向数据库提预测性问题并据此行动，等于给会读会写的智能体补上了预判能力。
展开正文

企业最值钱的数据多半躺在关系型数据库里，用户表连着订单表，订单表连着商品表，记录随时间不断累积。以前想从这些表里做预测，比如客户会不会流失、下个月需求多少、这笔交易是不是欺诈，团队得先把多张表摊平成一张大表，工程师花几周设计特征，再训练调优一个专属模型。NVIDIA 今天在 Hugging Face 官方博客宣布开源 Kumo Relational，把这套流程缩成一条查询。

它是一个预训练好的关系数据基础模型，直接接在数据库上，尊重原有的表、外键（表与表之间的连接字段）和时间戳结构。使用者用预测查询语言 PQL（一种声明式接口，写清要预测什么即可）发起问题，模型自动收集最多 10000 条历史样本当上下文，一次前向传播就算完，相当于模型跑一遍直接给答案，任务专属训练和特征工程都省了，表也不用摊平。模型内部三步走，先回放历史数据库状态自动构造上下文、防止数据泄漏，再用列注意力和行注意力交替理解每张表内部，最后靠基于主外键的图注意力跨表推理，把用户档案和交易记录串起来。因为跨表阶段只处理行嵌入，避开了平方级计算开销，自研图引擎靠内存映射 I/O 能撑住 5000 亿行以上的数据库，吞吐最高 5 GB/s。

成绩单上三组数字各对各的对手。官方在 RelBench V1/V2、SAP SALT、4DBInfer 共 41 个任务、15 个数据库上评测，这些库都没在预训练里出现过，模型在分类和回归上都超过了最强监督模型，包括关系型深度学习模型和专家做特征工程的梯度提升树管道。在 RelBench V1 分类任务上，它平均比专家特征工程的梯度提升树高近 4 个 AUROC 点，AUROC 是分类质量指标，越高越好。在 SAP SALT 企业基准上，它开箱即比做过特征工程的 XGBoost 高 7 个 MRR 点，微调后差距扩大到 13 个点，MRR 是排序质量指标，衡量正确答案排得有多靠前。同样在 SAP SALT 上，它比 AutoGluon 大集成高 8% 的 MRR，微调后领先扩大到 16%，比近期的表格基础模型高约 25%。RelArena-α 排行榜上它开箱即处在精度与效率的 Pareto 前沿，同精度下没有更快的模型，同速度下没有更准的，与最高分条目精度相近时快约 430 倍。

预训练数据全是合成的。真实企业数据库极少公开，NVIDIA 基于 PluRel（ICML 2026 论文，Kumo 团队成员参与撰写）生成模拟真实世界的关系库，按表结构、外键链接、随时间演变的列值分阶段构造，合成库加得越多训练损失降得越稳，这条幂律规律带来的收益能迁移到真实数据库。边界也写得明白，模型最适合表间有真实关联、数据带时间动态的场景；训练集特别大的任务上，任务专属的监督模型可能仍略胜，此时可以微调；预测信号要在有限跳数内可达，官方建议先从几张相关表的聚焦查询做起。

获取方式上，代码以 Apache 2.0 许可开源在 structured-data-models 库，pip 即装，首次使用自动从 Hugging Face 下载权重，权重按 OpenMDW 1.1 许可发布，也可以作为 NVIDIA NIM 服务部署，官方给了 Databricks 上的端到端示例。论文编号 arXiv 2604.12596，文档同步公开。模型同时面向人和 AI 智能体，智能体用 PQL 就能对数据库提预测性问题。语言模型当年把一个个专属 NLP 小模型变成一次提问，同样的替代故事正在结构化数据上开场。

按成本挑 token，Dharma-AI 重构小模型词表，推理成本实测降 77%

这是什么：10 月 21 日，Dharma-AI 团队在 Hugging Face 博客公开 VocabX 方法的预览结果。他们在自己生产环境中的葡萄牙语作文自动评分器（基于 Qwen3-4B 微调，输出 JSON 格式评分与评语）上重新设计词表，底座模型、训练数据和配方都不动，平均输出从 350 个 token 降到 101 个，实测推理成本降 77.0%，评分质量 bench score 从 0.703 升到 0.810，词表从 151,669 条裁到 64,767 条。
🔥 为什么今天值得看：推理成本优化通常盯着模型大小和量化，Dharma-AI 把注意力拉到词表这个训练开始前就定下的部件上。在他们测的场景里，模型写一个 token 的成本是读一个的 7.4 倍，压缩输出端的收益远大于压缩输入端，按成本加权挑 token 的思路给领域专用小模型指了一条新的省钱路。77% 出自单一生产系统的实测，其他场景需要先测自己的写读成本比再套用。
展开正文

10 月 21 日，Dharma-AI 团队在 Hugging Face 博客公开了 VocabX 方法的预览结果。他们在一个真实跑生产的葡萄牙语作文自动评分器上重新设计词表，底座模型、训练数据和配方都保持原样，实测推理成本降了 77.0%，评分质量反而从 0.703 升到 0.810。

这套评分器基于 Qwen3-4B 微调，读入作文、题目和参考材料，输出一段 JSON 格式的评估，给每项能力附上等级和评语。问题出在词表上。语言模型不直接读字母，它读的是 token。可以把文本想象成一根香肠，tokenizer 就是切香肠的刀，刀法决定一根肠切成几段，每段就是一个 token，模型按 token 读文本，也一个一个 token 地写出回答。

通用模型要应付各种语言和文体，Qwen3-4B 的刀法按大规模混合语料提前定死，词表有 151,669 条。一个只写葡萄牙语、只输出固定 JSON 格式的评分器背着这套刀法干活，浪费分两头。模型写得最勤的内容被切得碎，每次回复开头那段 JSON 信封要占 12 个 token；模型每写一个 token，还要给全部 15 万多个候选逐条算分，大量条目这个任务几乎永远用不上。

VocabX 换了挑 token 的尺子，按成本挑。团队先在生产系统里把账测清。模型读输入时整个网络一遍跑完，瓶颈在算力；写输出时一个 token 一个 token 地生成，显卡大部分时间在等数据从显存搬过来，瓶颈变成带宽。在他们测的这个评分器里，写一个 token 的成本是读一个的 7.4 倍。原文拿快递打比方，快递公司按箱收费，寄出的箱子比收进的贵七倍，压缩寄出的箱子比两头一起压划算得多。VocabX 就照这个价钱差定词表，输出端省下的 token 给足权重，同时把词表裁到 64,767 条。Qwen3-4B 里那块约占一成参数的输出层矩阵也随之瘦身，而它在生成每个 token 时都要整块读过。

具体改造分两层。子词层重切领域词汇；多词层找出反复出现的长片段，把它们合成单个 macro token，五类自动挖掘器分别盯长词、整行、短语、整句和 JSON 标签这类结构，其中结构类贡献最大。每次回复都写的那段信封，从 12 个 token 变成 1 个。

验证做得扎实。七个模型版本除了词表全部一致，底座、数据、训练配方和随机种子都相同，在同一台 RTX 5090 上用 vLLM 推理服务跑同样的 500 个请求，成本按实测运行时间计算。平均输出从 350 个 token 降到 101 个，成本降 77.0%，bench score 从 0.703 升到 0.810。团队还把方法拿到合同、医学论文、科学论文、新闻和 Python 代码五个公开领域，在 Qwen3、Llama-3.1、Gemma-3 三个模型家族上对比 FVT、MWT 和 in-place BPE 三个已有方法，十五种组合的压缩率和估算推理成本全部占先，合同场景 62.6% 对 61.8%，词表只要 113,426 条对 207,803 条。

过程里交过一次学费。第一版词表把评分等级连同周边 JSON 熔成一个 macro token，最省 token，质量却掉到 0.689，比生产基线 0.703 还低。等级藏进大 token 后，每种等级加结构的组合都成了同一个 token 的变体，模型选结构和选分数挤在了同一步。给等级单独立 token，每个回复多花 2 个 token，质量升到 0.810，实测还更省，成本降幅 77.0% 对熔合版的 73.3%。模型赖以做决策的那几个 token，压缩时碰不得。

两处边界要交代。论文标注 in preparation（2026），当前数字在正式发表前可能变动。77% 和 7.4 倍都出自葡语作文评分这一个生产系统的实测，比值随硬件、批大小和上下文长度变化，换场景要重测。团队自己也写明，VocabX 不让模型更聪明，它让模型不再为不需要写的内容逐片付费，不再为用不上的词表条目打分。

腾讯让编程智能体连工具框架一起训练，最高提升12.6个点

这是什么：腾讯团队 10 月 20 日在 arXiv 发布论文 2610.28069，提出训练方法 HarnessAdapt-RL。它把编程智能体的策略模型和 harness 放进同一个强化学习循环，一边训模型一边演化工具。9B 基座模型在 SWE-bench Verified、Multilingual、Pro 三个基准上，一次尝试通过任务的比例（pass@1）比 GRPO 基线分别高出 9.8、12.6、6.4 个百分点。
🔥 为什么今天值得看：实验显示训练产物从单个模型变成模型加演化工具的一对，部署时拆掉演化后的工具钩子最多损失 7.7 个百分点。这说明智能体的一部分能力长在工具框架里，做集成和选型的人以后要把模型和 harness 当整体评估，训练方法的设计也开始围绕这件事改变。
展开正文

10 月 20 日，腾讯团队在 arXiv 发布论文 2610.28069，提出名为 HarnessAdapt-RL 的训练方法，作者包括 Lingxiao Tang、Wei Tao、Yiwen Guo、Lingfeng Bao。这套方法把编程智能体的策略模型和它的 harness 放进同一个训练循环，模型在学，工具框架也在改。

训练编程智能体通常只更新策略模型的参数，harness 保持固定。策略模型就是决定下一步调用哪个工具、怎么改代码的那个模型。可训练过程留下的轨迹会不断暴露问题，比如修 bug 的思路本身有缺陷，比如模型和工具之间反复出现配合不畅。这些问题随任务各不相同，也随模型的学习不断变化，固定的 harness 接不住。

HarnessAdapt-RL 请两位教师分头处理。遇到有缺陷的修复策略，一个冻结的教师模型为当前任务生成机制级技能，相当于一份针对这个 bug 的修理笔记。面对跨任务反复出现的交互问题，另一个教师模型直接修改工具与钩子，每次改动只有在实测通过率或可训练率上升、且两项指标都不下降时才保留。策略模型带着改造后的 harness 继续训练，新产生的轨迹再指导下一轮改造，循环向前。

在 9B 参数的基座模型上，SWE-bench Verified、Multilingual、Pro 三个真实修 bug 基准里，一次尝试就通过任务的比例（pass@1）比 GRPO 基线分别高出 9.8、12.6、6.4 个百分点。GRPO 是一种常用的强化学习算法，强化学习指让模型在任务里反复试错、按结果调整参数的训练方式。同一组实验里，新方法也超过了 GRPO 搭配人类设计的 OpenHands harness 的组合。论文只在 9B 规模上做了实验，更大的模型能否同样受益，文中没有验证。

拆解实验给出两条关键结论。机制级技能在评估阶段拿掉，涨上去的收益依然在，看起来训练教的修复本事留在了模型里。演化后的工具与钩子则拆不得，部署时移除最多损失 7.7 个百分点，而且工具钩子随策略变化持续重新演化，效果好过沿用早期冻结的版本。这份训练最终交付的，是训练后的策略模型配上演化出来的工具与钩子，技能在部署时移除。评估编程智能体时，模型和它的 harness 要当成一个整体来看。

GitHub 为智能体改造 Git 存储，最忙仓库吞吐提升 3 倍多

这是什么：GitHub 10 月 21 日在工程博客披露，它把 Git 写入的串行化范围从整个仓库缩小到单个引用，引用是 Git 里分支、标签这类指向提交的指针。旧机制下每次写入锁住整个仓库；新机制下，往不同分支推送的写入互不排队。内部测试里，不同引用的写入吞吐提升 3 到 4 倍。这套改动让平台上最后 0.00001% 最繁忙的仓库也能迁入 Azure。
🔥 为什么今天值得看：AI 编程智能体让 Git 写入量指数级增长，GitHub 自有数据中心的电力容量又有硬上限，写入吞吐成了整个平台的瓶颈。这次粒度调整直接抬高单个仓库的写入上限，也解释了为什么代码托管这种最底层的服务要为智能体时代重造。Git 操作是 GitHub 的 Tier 0 服务，几乎所有功能都依赖仓库数据，改动必须在不停机的前提下小步推进。
展开正文

GitHub 10 月 21 日在工程博客披露 Git 存储改造进展。平台上 99.99999% 的仓库已同时存放在自有数据中心和微软 Azure 两处，2025 年 8 月第一份副本落地 Azure，多数仓库 5 个副本中已有 2 个在 Azure，约一半 Git 流量由 Azure 承接。

剩下 0.00001% 是最忙的一批仓库，卡在跨区域 25 毫秒的网络往返上。旧架构里，管理副本的 Spokes 系统每次写入都锁住整个仓库，还要等所有健康副本回应，最慢副本拖慢全部写入，最忙仓库扛不住。GitHub 把串行化的范围从整个仓库缩小到单个引用，引用是 Git 里分支、标签这类指向提交的指针。智能体和开发者各推各的分支，互不排队，同时写入。内部测试显示，不同引用的写入吞吐提升 3 到 4 倍，延迟更低。

推动这场改造的是智能体流量的指数级增长和自有数据中心电力容量的硬上限。Git 操作是 Tier 0 级核心服务，全站功能几乎都依赖仓库数据，团队先搬数据，落定后再改架构。
