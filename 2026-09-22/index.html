Grok 4.7 维持低价，实测单任务成本反超更贵对手

这是什么：9 月 21 日，xAI 发布编程与知识工作模型 Grok 4.7。定价与上代 Grok 4.6 持平，每百万 token 输入 2 美元、输出 6 美元；Fast 变体翻倍至 4/12 美元；单次输入超过 20 万 token 后，标准版也按 4/12 美元计费，上下文窗口上限 50 万 token。模型换用更大的基座并延长强化学习训练，还引入全新安全防护栈。目前已上线 Cursor、Grok Build 和 Grok API，GitHub Copilot 正逐步推送。
🔥 为什么今天值得看：这场发布把编程模型的比较标准从牌价推进到总账。独立机构 Artificial Analysis 实测发现，Grok 4.7 在 xHigh 推理档每任务输出约 8.1 万 token，比上代多 125%，单任务实际成本约 3.74 美元，超过牌价更贵的 GPT-5.6 Sol Max 的约 1.99 美元。单价便宜但消耗巨大的模型，放到企业月级用量下，账单差距会放大成年度预算问题。对选型团队来说，判断标准正在从每百万 token 多少钱，变成每干完一件事花多少钱。

9 月 21 日，xAI 发布新一代模型 Grok 4.7，主打编程和专业级知识工作。据 VentureBeat 报道，这次发布最受开发者关注的部分是价格没动，每百万 token 输入 2 美元、输出 6 美元，与一个多月前发布的 Grok 4.6 完全相同。追求速度的用户可以选 Fast 版本，价格翻倍到 4 美元和 12 美元；单次输入超过 20 万 token 后，标准版也按 4/12 美元计费，上下文窗口最大 50 万 token。

能力上，xAI 称 Grok 4.7 换用了更大的基座模型，强化学习训练跑得更久，训练任务偏向要花多个小时才能完成的难题，为的是让模型在跨小时的长任务里更可靠。官方基准涨幅可观，考察模型在终端里实际干活的 Terminal-Bench 4.0 得分从 20.3% 升到 38.0%，CursorBench 4.0 从 40.4% 升到 46.3%。不过独立评测机构 Artificial Analysis 在 xHigh 推理档实测只有约 26%，同期 GPT-6 Astra 为 59.6%，Claude Opus 5 约 49%，差距仍然明显。

真正该细算的是消耗账。Artificial Analysis 测得 Grok 4.7 在 xHigh 档每完成一个测试任务要输出约 8.1 万 token，比 Grok 4.6 的 3.6 万多 125%，比 GPT-6 Astra 的 2.7 万多 196%。把输入、缓存、推理、回答全部计价后，Grok 4.7 每任务实际花费约 3.74 美元，而牌价贵得多的 GPT-5.6 Sol Max 约 1.99 美元。单价便宜的模型，干完一件事的总花费反而更高。

企业用量会把这笔差距放大。按牌价测算，每月 100 亿输入加 20 亿输出 token 的团队，月账单约 3.2 万美元，年化约 38.4 万美元；用量加到 500 亿输入加 100 亿输出，月账单约 16 万美元。这是 VentureBeat 给出的示例测算，不代表典型部署规模，但足以说明 token 效率会直接变成基础设施预算问题。

安全方面，Grok 4.7 换上全新防护栈，xAI 自报在 LatchBio 生物安全基准拿到 62.4%，在 HackerBench v0.3 的危险双用途提示里只放行 3.3%。这两项都是公司自己公布的成绩，独立验证还没有。模型现在可以在 Cursor、Grok Build 和 Grok API 里用到，GitHub 也在 Copilot 中逐步推送。外界反应两极，开发者 Dan McAteer 在 X 上批评其终端表现“horrendous”（糟糕透顶）；博主 @haider1 则晒出 CursorBench 榜单，称 46.3% 的得分配上约 6.01 美元的单任务成本“absurd actually”（离谱地好），比 46.8% 但要 7.05 美元的 Claude Fable 5.1 Medium、41.7% 要 8.23 美元的 GPT-5.6 Sol Max 都划算。对正在选型的团队，办法很直接，拿自己真实的任务跑一遍，按干完一件事花的总钱来比，别只看牌价。

AWS 开源代理外壳 Strands Harness，自称不换模型省近三成费用

这是什么：9 月 21 日，AWS 的 Strands Agents 团队开源了通用 AI 代理外壳 Strands Harness，采用 Apache 2.0 许可证，提供 Python 和 TypeScript 两种语言版本，调用一次 create_harness() 就能起一个完整代理，本地可跑、可部署到云端，模型可接 Amazon Bedrock、Anthropic、OpenAI、Google、Ollama 和 LiteLLM。团队自称，在 6 个基准上让同一个模型跑同样的任务，这个外壳的每任务平均花费比 Claude Code、Codex、oh-my-pi、OpenCode、DeepSeek Harness 低 28%，准确率接近。
🔥 为什么今天值得看：这份发布把一件过去只在工程圈里流传的事摆到了明面上。同一个模型，外面那层壳不同，账单能差出数倍。对做 AI 应用的团队，挑对外壳成了换模型之外更容易下手的省钱杠杆；对普通用户，它解释了为什么用着同样的模型，不同产品的消耗和体验会差那么远。眼下所有数字都来自 AWS 一方，参考时需要带着这个前提。
展开正文

很多开发者的代理点子在 Claude Code 或者 Codex 里跑得挺顺，换成自己搭的循环就状况不断。AWS 的 Strands Agents 团队 9 月 21 日开源了冲着这个痛点去的新项目 Strands Harness，一个组装好就能用的通用 AI 代理外壳，采用 Apache 2.0 许可证，同时提供 Python 和 TypeScript 版本，调用一次 create_harness() 就能拿到一个完整代理，本地能跑，也能部署到云端，模型可接 Amazon Bedrock、Anthropic、OpenAI、Google、Ollama 和 LiteLLM。

harness 这个词可以理解成模型的外壳，指包在模型外面的那一整套系统，包括负责决定何时再次调用模型的循环、给模型配备的各类工具、决定每次塞入哪些历史的上下文管理，再加上记忆和出错恢复。Strands 之前开源的是这些零件的 SDK，这次直接把零件拼成了默认可用的整体。开箱自带 shell、文件读写和网页工具，过大的工具结果转存到文件，重复请求的部分走缓存，跨次运行保留长期记忆，凭一个会话 ID 就能恢复中断的对话，开放式子任务交给内置的帮手代理，多步任务用清单来跟踪。

团队自称的旗舰数字是，在 ALFWorld、ContextBench、GAIA、WebShop、τ²-bench、Terminal-Bench 2.1 这 6 个基准上，让同一个 Claude 或 GPT 模型装进不同外壳跑同样的任务，Strands Harness 的每任务平均花费比 Claude Code、Codex、oh-my-pi、OpenCode、DeepSeek Harness 这些对手低 28%，准确率接近。测试用 Terminal-Bench 作者的 Harbor 评估框架在 Amazon EC2 上分布式完成。图表脚注还交代了一个细节，DeepSeek Harness 整体比 Strands Harness 便宜约 14%，是全场最省 token 的外壳，代价是每个基准得分都更低，把它计入后，总节省比例被拉到了 28% 这一档。

最直接的对照来自 Terminal-Bench 2.1，同一个模型 Claude Fable 5，每个外壳跑 89 次试验。Strands Harness 每次运行花 56.29 美元、得 69.7 分，Claude Code 花 248.05 美元、得 61.8 分，算下来省了 77% 的钱，分数还高出 7.9 分。oh-my-pi 拿到同样的 69.7 分，花费多出 54%。DeepSeek Harness 只要 40.30 美元，分数落后 10.2 分。图表上得分最高的组合是 Claude Opus 5 配 Strands Harness，接近 85%。

团队把效率主要归给上下文管理的默认设置。工具返回结果超过约 1500 个 token 就先截断；上下文占用一旦超过 85% 就触发摘要压缩，把旧对话折叠成摘要接着用；窗口实在装不下时，恢复逻辑在循环内部直接接手，任务不必从头再来。

这个方向还有独立研究在讲。HarnessTax 研究比较了 Claude Code、Codex CLI 和 Pi 三款外壳跨 7 个模型的表现，发现换外壳几乎不改变成功率，同一个模型达到相近成功率，成本最多能差 5 倍。看完这些数字还需要记住一个前提，所有对比数据都出自 AWS 团队自报，配套论文尚未发布，团队表示后续会补上。

工具本身另有几处顺手的设计。附带的 skills 文件能让编码代理生成 AWS、GCP、Azure、Cloudflare、Modal 五家平台的部署配置；Strands CLI 支持用自然语言描述需求，团队演示里，代理被要求给一篇博客加装 Playwright MCP 并测量视频加载延迟，运行 /export 后直接产出可用的 Python 或 TypeScript 代码包。Strands 工程师 Gautam Sirdeshmukh 还用它做了一个能远程启动 Strands Harness 运行的桌面应用。所有默认值都可以覆盖，组件能一路换到底层 SDK，笔记本上原型验证过的代理，就是日后嵌进生产环境的那个。

两年预览收官，Python 成为 Cloudflare 边缘平台一等语言

这是什么：Cloudflare 的 Python Workers 在 2026 年 9 月 21 日正式告别预览状态，这项支持在预览轨道上运行了两年。官方现在确认，Python 是 Cloudflare 开发者平台上完全支持的一等语言。Simon Willison 当天发文记录了这个消息，并整理了实现方式和使用限制。
🔥 为什么今天值得看：Python 是数据分析与 AI 开发中使用最广的语言之一，这类代码能直接部署到离用户更近的边缘节点后，个人和小团队不用租服务器、不用配运维，也能把服务开到用户身边。已有 Python 代码的团队，多了一条现成的部署路径。
展开正文

2026 年 9 月 21 日，Cloudflare 宣布 Python Workers 结束两年预览正式转正，官方确认 Python 成为其开发者平台上完全支持的一等语言，Simon Willison 在博客里记录了这个消息。 技术上的做法值得一看。Python 代码先经 Pyodide 编译成 WebAssembly，一种原本为浏览器设计的通用中间代码，随后跑进 Cloudflare 基于 V8 引擎的 workerd 运行时。这套方案有明确限制，在 WebAssembly 虚拟机里，multiprocessing（多进程）和 threading（多线程）都用不了。 本地开发也有配套。官方工具 pywrangler 在 PyPI 上的包名是 workers-py，容易认错，它能在本机完整模拟云端执行栈，内含约 123MB 的 workerd 二进制。发布公告由 Gyeongjae Choi、Dominik Picheta、Hood Chatham 署名，其中两位是 Pyodide 核心维护者，看得出 Cloudflare 在认真投入 Python 生态。
