Claude Cowork 并入主聊天，智能体能力变成默认

这是什么：Anthropic 宣布停用独立的智能体入口 Claude Cowork，把它长时执行、调用外部服务、拆解任务的能力全部并回 Claude 主聊天界面。从今往后用户在对话框里提需求，Claude 自己判断该快问快答还是拉起一个多步骤项目。同场发布测试阶段的协作文档 Claude Docs 和演示文稿 Claude Slides，VentureBeat、The Verge、TechCrunch 三家媒体同步报导。
🔥 为什么今天值得看：以前用 Claude 干大活要先做一道选择题，判断这件事属于随口一问还是要交给 AI 长跑，选错入口工作就得重来。合并之后这道题由产品自己来答，普通用户头一回不用理解产品结构，就能把一整套活交给 AI。Docs 和 Slides 补上了出口，AI 的产出从聊天末尾的一个文件，变成挂在单个链接里、多人可同时编辑的正式工作成果，直接踏进在线办公软件的地盘。数周前 OpenAI 也把编程代理 Codex 并回了 ChatGPT 主界面，两家头部公司在同一个方向收拢。
展开正文

今天 VentureBeat、The Verge、TechCrunch 三家媒体同步报导了 Anthropic 的一轮产品大调整。Anthropic 宣布取消独立的智能体产品 Claude Cowork，把它长时执行、调用外部服务、拆解任务的能力全部并回 Claude 主聊天界面，同时推出测试阶段的协作文档 Claude Docs 和演示文稿产品 Claude Slides。

Cowork 是 Claude 里专门放大活的入口。以前用户要先判断一件事属于随口一问，还是要交给 AI 干上一阵，再决定留在普通聊天还是切到 Cowork。Anthropic 在公告里说：“我们当初为更大的工作建了 Cowork，为视觉工作建了 Design。两边都有人用，用户告诉我们，最烦的环节是判断一个任务该放在哪边。”从本周三起这道选择题消失，Claude 根据请求自行判断。一段对话可以从快问快答开始，中途升级成多步骤项目，需要的外部服务、技能和上下文由 Claude 自己调用，用户离开后它也能接着干。这些原本属于 Cowork 的智能体能力，现在变成 Claude 的默认行为，Cowork 这个名字会在过渡期结束后彻底消失。

配套的 Claude Docs 和 Claude Slides 都在测试阶段，用法跟在线文档一个路子，成果挂在单个共享链接上，手机也能接着编辑。Docs 支持多人同时编辑，文档默认私密，可以分享给指定同事，导出 Microsoft Word 和 Google Docs。Slides 可以逐页修改、直接在 Claude 里演示，导出 PowerPoint 或 PDF。原来独立的设计产品 Claude Design 也搬进了对话。Anthropic 举了个周报的例子，让 Claude 查看销售管道的变化，按固定格式写报告，标出延期项，把要点做成五页幻灯片，文档和幻灯片从同一次对话里产出，还能排期到下周一自动重跑。

推送从 Claude Pro 和 Max 订阅者开始，覆盖网页、桌面和手机端，Team 和 Free 计划随后跟进，企业版用户提前 30 天收到通知，用户不需要自己动手改任何设置。已有 Cowork 用户的聊天、项目、artifacts（Claude 生成的文件成果）、连接器（接入外部工具和服务的通道）和技能全部保留。面向开发者的 Claude Code 继续独立，不参与本次合并。默认设置下 Claude 每次行动前会先请求许可，用户也可以改成让它持续干活，只在需要把关时来打断。

这次合并要放进过去八个月里看。Cowork 于 2026 年 1 月 12 日作为研究预览发布，最早是 macOS 桌面端 Claude Max 的功能，定位是给非技术工作的 Claude Code。Anthropic 当时观察到开发者用 Claude Code 干旅行攻略、做幻灯片、清理邮箱这类闲活，就把同一套委托机制包进了图形界面。它发布后成了 2026 年夏天软件股抛售潮的早期催化剂之一，那波抛售后来被市场称作 SaaSpocalypse，ServiceNow、Salesforce、Snowflake、Intuit 和汤森路透都曾因通用 AI 代理会吃掉独立软件的担忧而承压，不过完整的抛售另有累积成因，不能全记在 Cowork 头上。数周前 OpenAI 把编程代理 Codex 并回了 ChatGPT 主界面，两家头部公司在同一方向收拢。

调整落地后，原本藏在开关后面的智能体模式成为 Claude 自身的默认架构。用户开口提需求，由产品来决定这活需要一个回答、一份文档、一套幻灯片，还是一段长时间跑着的任务。

OpenAI 给 ChatGPT 广告加智能体，点开广告能直接聊

这是什么：OpenAI 在 9 月 16 日的官方博客里升级了 ChatGPT 广告产品。用户点击广告后，可以选择进入一场带明确标注的对话，对面是商家赞助的智能体（Sponsored Agents），目前在美国部分广告主中测试。广告主同时拿到新工具，在 ChatGPT 里用自然语言就能建广告、查效果，HubSpot 和 Shopify 的集成也当天上线。
🔥 为什么今天值得看：广告的交互从一次跳转变成多轮对话，用户下单前能把尺寸、保养这类具体问题问清楚，商家则把咨询环节留在了自家智能体里。对商家来说，自然语言操作加上现有工具集成，接一条新广告渠道不必推倒重来。放进更大的图景看，各大平台都在把智能体收进自家主产品当默认能力，广告是这一轮变化里商业化最直接的场景。
展开正文

9 月 16 日，OpenAI 在官方博客发布广告产品升级，新功能叫 Sponsored Agents，可以理解为赞助智能体。过去点开 ChatGPT 里的广告，得到的常常只是一次跳转；这次升级后，用户可以选择发起一场带明确标注的对话，坐在对面的是商家出钱运营的智能体。看中一张餐桌的人可以直接问它桌子多大、坐得下几个人、桌面怎么保养，问到满意再点链接去商家官网。

边界也写得清楚。这场对话由用户主动开启，界面有明确标注，和 ChatGPT 本身的独立回答相互分开，也和用户原本的聊天相互独立。目前该功能只在美国部分广告主中测试。

广告主一侧同步拿到一批新工具。装上 Ads Manager 插件后，在 ChatGPT 里写几句自然语言提示词就能建广告活动，把网站或产品简介直接转成投放方案，也能查询效果、拿到下一步建议。制作广告素材同样有 AI 参与，系统会根据落地页和投放目标给出文案与图片建议，广告主审核修改后再决定是否采用。另有一项可选开启的文案定制，能把现有标题和描述调整得更贴合对话场景，并自动翻译成用户的偏好语言。

渠道上，OpenAI 拉来了第一批伙伴。HubSpot 是首个 CRM 合作伙伴，商家在 HubSpot 里就能连接 ChatGPT Ads 账户，直接投放广告、跟进销售线索。Shopify 是首个电商合作伙伴，美国商家当天就能在 Shopify 应用商店装上 ChatGPT Ads 应用，商品信息已经通过 Shopify Catalog 打通，9 月 23 日起扩展到其他可投放市场。有意向的商家可以在 ads.openai.com 注册。

OpenAI 在公告里把这组更新称为建设以 AI 为中心的广告平台的下一步，一侧改用户的广告体验，另一侧改商家的投放方式。社区反应两极。Hacker News 的讨论里，反对声音集中在商业化对信任的冲击，有评论直言不认识任何想要这种广告的人，并质疑一家宣称接近 AGI 的公司为何把广告当成主要策略。对话形态本身也引来警觉，有人担心这类广告比信息流广告更容易赢得信任，影响判断的力度可能更大。温和一派看法不同，一位用户表示 ChatGPT 从他的提问里已经比 Instagram 更懂他，做得好会真的有用，悬念在执行。付费模式的讨论同时出现，评论里提到 OpenAI 早已提供付费无广告选项，大多数用户并没有买单。

Google 用 MCP 把智能家居开放给任意 AI 代理

这是什么：Google 本周为 Google Home 推出 MCP 集成,任何支持 MCP 协议的第三方 AI 代理(包括 Claude、Open Claw、Google Antigravity、Hermes)都能接入 Google Home 生态,控制设备、读取全部事件历史,并代表用户执行操作。The Verge 和 TechCrunch 两家媒体同步报导了这一消息。
🔥 为什么今天值得看：这是 MCP 协议第一次由大厂官方落到消费级硬件上。代理拿到开关灯之外的权限,能读取家里的数据层和控制层,翻设备历史做推理,智能家居的使用方式从下指令转向有上下文的主动服务。对 Google 来说这也是一步基础设施的棋,自己当智能家居的底座,让第三方在上面做面向用户的产品,角色类似 AWS 之于互联网生意。
展开正文

你家的智能灯泡,现在可以听 Claude 的了。The Verge 和 TechCrunch 两家媒体本周同步报导,Google 为 Google Home 推出了 MCP 集成,任何支持这个协议的 AI 代理,包括 Claude、Open Claw、Google Antigravity 和 Hermes,都能接入 Google Home 生态,安全地操作全部设备和事件历史。Google Home 与 Nest 的集团产品经理 Taylor Lehman 在博客文章中表示,这套集成让支持 MCP 的代理「安全地处理 Google Home 生态系统里的所有设备和事件历史」。

能力清单比「帮你开灯」具体得多。因为代理能读到事件历史,你可以问它孩子放学回家后干了什么,它会跨多个摄像头拼出答案;它也能翻设备状态记录,统计你上周洗了几次衣服、灯开了多久。任务完成后,代理可以通过 Google Home 音箱给你发一条语音消息,或者自己生成一个自定义控制面板。The Verge 作者 Jennifer Pattison Tuohy 的判断是,关键变化在于代理拿到了家里的数据层和控制层,智能家居从被动执行指令,走向能理解情境、主动替你干活。

Google 自家的地盘没有被触动。Gemini for Home 仍然是 Home 应用和 Nest 音箱的官方界面,在 Google Assistant 退场后继续负责语音交互。MCP 集成是在官方助手之外叠加的一层,第三方代理通过自己的界面直接和设备打交道。

想用上它,门槛不低。首发只面向美国的 Google Home Premium Advanced 订阅用户,每月 20 美元或每年 200 美元,访问权限在未来几周内逐步推送,设置时还要创建并配置一个 Google Cloud 项目。安全方面,Google 加了速率限制和防护措施,比如不允许代理解锁门。Lehman 同时提醒,取决于你接入的是哪个代理,连接 Home MCP「可能导致意外甚至不希望出现的行为」,建议先看一遍开发政策和服务条款。

放在更大的盘子里看,Google 在下基础设施的棋。它在 2024 年开放过智能家居 API,后来又把 Gemini for Home 做成全栈 AI 服务,这次等于把家门向第三方开发者进一步敞开,自己当底座,让别的公司在上面做面向用户的产品,角色类似 AWS 之于互联网生意。开发者的观望有历史依据,Android @ Home、Weave、Project Brillo、Works with Nest,再加上刚退场的 Google Assistant,这些年 Google 立起来又放下的智能家居平台能列出五个。开源平台 Home Assistant 此前已实现过类似集成,作者 Tuohy 去年就用 Claude 搭过自己的智能家居,排障、写自动化和设计面板靠自然语言就能完成。

不动模型，Salesforce 让代理浏览器任务成功率翻倍

这是什么：9 月 16 日 VentureBeat 报道，Salesforce AI Research 与 Agentforce 团队发布 DarwinX 框架，配套论文来自 arXiv。它自动优化 AI 代理的外围配置层（提示词、工具、技能、任务流程，即 harness），底层模型权重全程冻结。在冻结 GPT-5.5 的代理 Monet 上，浏览器基准 WebArena-Infinity 完成率从 43.5% 到 93%，终端基准 Terminal-Bench 2.1 从 75.5% 到 83.2%，把 Terminal-Bench 上进化出的配置搬到 SWE-bench Verified 得 84.2%，基线 80.8%。实验基础设施 Beagle 同步开源（Apache 2.0）。
🔥 为什么今天值得看：多数开发者基于托管模型搭代理，摸不到权重，也没有自己的微调管线，想改进只能手动改提示词。DarwinX 证明外围配置层还有大量性能可挖，并且能把“改动、验证、防倒退”做成自动流水线，像持续集成一样把关每次改动。按资深作者 Ran Xu 的判断，模型会越来越通用，企业特有的上下文、权限、治理和工具会沉淀在 harness 层，这一层可能成为比单条提示词更持久的差异化来源。
展开正文

9 月 16 日，VentureBeat 报道了 Salesforce AI Research 与 Agentforce 团队的 DarwinX 框架。它把一个 AI 代理在浏览器任务基准 WebArena-Infinity 上的完成率从 43.5% 提到 93%，而底层模型 GPT-5.5 的权重全程冻结。被改动的是提示词、工具、技能、任务流程这层外围配置，研究圈叫它 harness，可以理解成套在模型身上、决定活怎么干的一整套装备。

手动改这层装备很不可靠。论文资深作者 Ran Xu 说，手动改 harness 容易收敛到局部最优，修好了一种失败，没有大范围回归测试，就可能悄悄弄坏原本正常的功能。代理评测还带随机性，同一个代理两次跑分能差出几个百分点。

DarwinX 把软件行业持续集成的纪律搬了过来，每次改代码都自动重跑测试，改动不许弄坏旧功能。它同时养多个 harness 变体，候选改动必须让代理确实变强，并让以前会做的任务保持在容差内不倒退，才能进入下一代，论文称之为“保留并扩展”。整体分数偏低却掌握独门本领的变体也不淘汰，互补时合并，合并版同样要过回归检查。这套流程在 TerminalWorld 的主打成绩基于 Opus 4.8，41 道保留题上基础版解出 25 道（61%），进化版 28 道（68.3%），四个各有专长的变体分别解 24 到 27 道，合并版 28 道超过所有个体。

四个基准全面提升，幅度差别很大。WebArena-Infinity 的进化只用 300 条按应用文档生成的合成意图，最终测试是 1,260 条没见过、由程序判定对错的任务，完成率 43.5% 到 93%。93% 是审计后数字，钻漏洞式的无效行为已被筛掉，十次任务里原来只有四次出头能干成，现在九次以上。Terminal-Bench 2.1 从 75.5% 到 83.2%，换更强基座模型到 84.7%，机器学习和科学计算类任务涨 14.8 分，数据和数据库类涨 13.8 分。进化出的配置新增 7 个技能，例如完成前先检查生成的文件，额外算力也花得有选择性，已会任务的中位轮数只从 12 变 13，新解出的任务从 11 翻到 22。把 Terminal-Bench 上进化出的配置原样搬到 SWE-bench Verified，拿到 84.2%，基线 80.8%，进化期间没接触过 SWE-bench 反馈，说明部分行为能跨基准迁移，不过 3.4 分的增幅远小于 WebArena，论文也只测了单方向。

实验基础设施 Beagle 已在 GitHub 以 Apache 2.0 开源，代理 Monet 保持专有。Xu 把 Beagle 比作“代理进化的 Hugging Face Trainer”，用户自带代理、环境、评估信号和进化算法，基础设施负责大规模跑实验。在他看来，模型会吸收越来越通用的推理能力，企业特有的上下文、权限和治理规则会沉淀在 harness 层，这一层比任何一条具体提示词都是更持久的差异化来源。

边界也写得明白。进化要多得多的评估算力；论文也公布了反面结果，同一套流程换 GPT-5.5 在 TerminalWorld 只有 56.1%，低于一个中性基线代理，对最强现成代理的领先只有一道题，作者称属提示性而非统计上决定性。Xu 建议，长时程、结果可验证、行为面大的任务才值得上这套，固定输入映射固定接口的简单流程，写确定性逻辑更好测试也好治理。

Cloudflare 开源的 security-audit-skill 是一个装进编码代理的技能包，让代理对整个代码库做安全审计。仓库今年 6 月 18 日创建，已积累 7.1k star 和 415 fork，9 月 14 日刚推送过更新，这次登上 GitHub Trending 属于老项目的持续维护。

审计按六个阶段推进。第一步侦察，把架构、信任边界和输入面整理成 architecture.md 和一份覆盖账本，账本记下哪些代码单元被查过。狩猎阶段按账本派出互相隔离的代理分头找漏洞，另有代理专挑覆盖盲区。每个候选发现都要交给一个全新的代理去证伪，活下来的才写入 findings.json，再换一批代理复核源码声明，最后汇总成报告。

三种判决各有门槛。confirmed 要有完整的源码追踪和有边界的观察结果；卡在某个事实上的记为 needs_validation，写明未解决之处，不给严重级别；被证伪的候选以 rejected 落档，证伪过程一并保留。流程里另有两个零依赖校验器，反复检查 findings.json 和覆盖账本的 JSON 结构是否合规。

最核心的规矩，是检查漏洞的代理永远不能是发现漏洞的那个代理。项目还要求在操作系统级沙箱里运行，条件不满足时发现留在 needs_validation，不执行目标代码。
