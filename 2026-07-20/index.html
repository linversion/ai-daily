Claude Code 已悄悄用上 Rust 版 Bun，Linux 启动速度提升 10%

这是什么：Claude Code 从版本 2.1.181（2025年6月17日发布）开始，将底层 JavaScript 运行时从 Zig 版 Bun 替换为 Rust 重写版，Linux 平台启动速度提升约 10%，功能保持一致，用户几乎无感知。
🔥 为什么今天值得看：这是 Rust 版 Bun 首次在百万用户级产品中进行大规模生产环境验证。Anthropic 用行动表态支持 Bun 的 Rust 重写路线，对还在观望的团队释放了信号。同时，10% 的启动加速对频繁在 CI/CD 环境中使用 Claude Code 的开发者有实际价值。

今天 Simon Willison 和 Hacker News 社区同时关注到一个细节：Claude Code 从 2.1.181 版本开始，已经把底层的 JavaScript 运行时从 Zig 版 Bun 换成了 Rust 重写版。这个版本 6 月 17 日就已经发布，但直到现在才被社区挖出来讨论——毕竟对大多数用户来说，这次替换几乎是无感的，除了 Linux 上启动快了大约 10%。

这件事的来龙去脉其实挺有意思。今年 5 月，Bun 的创始人 Jarred Sumner 借助 AI 编程代理，把整个 Bun 代码库从 Zig 语言重写成了 Rust，新增超过 100 万行代码。当时社区争议不小，Zig 的创始人甚至公开批评这是"未经审查的垃圾"。但 Anthropic 显然不这么看——他们不仅在自己的代码迁移指南里把这次重写当作成功案例，还直接把它用在了 Claude Code 这个拳头产品上。

从技术角度看，这次替换的意义不只是 10% 的启动加速。它相当于给 Rust 版 Bun 做了一次大规模的生产环境验证。Claude Code 的用户量在百万级别，如果 Rust 版 Bun 能在这种规模下稳定运行，对其他还在观望的团队会是个很强的信号。不过需要注意，这个 Rust 版本目前还是 Bun v1.4.0 的 canary 通道版本，并未正式发布——Anthropic 相当于提前吃上了"狗粮"。

社区讨论里有人提到一个细节：这次替换对 macOS 用户影响不大，因为 macOS 上的启动性能瓶颈不在 Bun 本身。真正的受益者是 Linux 用户，尤其是在 CI/CD 环境里频繁启动 Claude Code 的开发者。

🔥 为什么今天值得看：这篇文章戳破了行业长期回避的问题：企业AI项目的高失败率并非技术原因，而是组织决策机制的失灵。在"不创新就死"的舆论压力下，企业正在用上马AI项目的数量替代真正的战略思考，这种"恐惧驱动"的决策模式可能导致资源巨大浪费和对AI能力的严重误判。

今天，一篇在Hacker News上引发激烈讨论的文章直指当前科技界最不愿面对的现实：企业对AI的盲目狂热正在系统性地摧毁理性决策。这篇文章没有讲什么技术突破，而是用一个个血淋淋的案例，把AI项目在企业中普遍失败的真相摊在了桌面上。

Hacker News的讨论区里，不少从业者现身说法。有人提到自己所在的公司花了几百万美元上AI项目，最后发现准确率还不如一个实习生手动处理；也有人指出，问题不在于技术本身，而在于组织失去了说"不"的能力——当整个行业都在高喊AI转型时，理性的质疑声很容易被淹没。

这篇文章的价值不在于给出了什么解决方案，而是戳破了一个皇帝的新衣：在AI狂热的裹挟下，太多企业正在用战术上的勤奋掩盖战略上的懒惰。

AI 建议让人类准确率暴跌三分之二，自信度却翻倍

这是什么：一项新发布的学术预印本研究（Marcoccia 团队，2026年7月15日）通过实验发现，当人们使用 AI 建议时，判断准确率会下降到原来的三分之一，而对自己判断的自信度却翻了一倍。研究首次系统量化了“认知投降”现象——即使 AI 建议明显错误，人类也会放弃独立思考并采纳机器意见，同时压制了说“我不知道”的意愿。
🔥 为什么今天值得看：这项研究首次用精确的行为数据证实了 AI 辅助决策中的“自信-准确度剪刀差”，揭示了人类在 AI 面前主动放弃判断的心理机制。此前 Wharton 团队虽提出“认知投降”概念，但缺乏量化支撑。该发现对医疗、法律、企业管理等依赖 AI 辅助决策的领域敲响警钟：盲目信任 AI 可能导致系统性误判，且当事人毫无察觉。

今天 Hacker News 上热议的一项新研究，给所有习惯把 AI 建议当参考答案的人泼了盆冷水。研究人员发现，当人们使用 AI 建议时，判断准确率会下降到原来的三分之一，但与此同时，他们对自己判断的自信度却翻了一倍。换句话说，AI 不仅没让你变聪明，反而让你在错得离谱时还觉得自己特别对。

这项由 Marcoccia 团队在 7 月 15 日发布的预印本研究，首次系统量化了一个令人不安的现象——“认知投降”。研究显示，AI 建议会显著压制人们说“我不知道”的意愿。即使 AI 给出的答案明显错误，受试者也倾向于放弃独立思考，直接采纳机器的判断。更讽刺的是，这种盲目信任催生了一种 AI 辅助版的 Dunning-Kruger 效应：能力越差的人，越容易高估自己借助 AI 后的表现。

这并非学界第一次敲响警钟。早在今年 4 月，Ars Technica 就报道过 Wharton 团队提出的“认知投降”概念，指出 AI 用户会“吓人地愿意”把思考权拱手让给大模型。但当时缺乏精确的行为数据支撑。Marcoccia 团队的贡献在于，他们用实验数字把这种担忧具象化了——准确率暴跌和自信度飙升的剪刀差，比很多人预想的更极端。

社区讨论中，有人把这和职场现状联系起来：当管理层开始用 AI 输出作为决策依据，而执行层又不敢质疑时，整个组织的判断力就可能系统性滑坡。也有观点认为，问题不在 AI 本身，而在于人类天生有“认知吝啬”倾向——我们的大脑本来就喜欢走捷径，AI 只是让这条捷径变得更诱人。无论如何，这项研究提醒我们，在把 AI 建议当作决策依据之前，或许该先问问自己：我是在用工具，还是在交白卷？

🔥 为什么今天值得看：这起诉讼的时间点极为敏感——OpenAI正处于从纯软件公司向消费硬件领域扩张的关键节点，同时也在筹备可能是科技史上最大规模的IPO。如果诉讼进入证据开示阶段，OpenAI的内部研发记录可能被迫公开，不仅会拖慢硬件产品上市，更可能动摇投资者对其技术原创性的信心，从而影响估值。

今天TechCrunch的Equity播客抛出了一个尖锐的问题：苹果上周对OpenAI提起的商业秘密窃取诉讼，会不会让后者正在酝酿的硬件计划和天价IPO泡汤？这起诉讼来得正是时候——OpenAI刚被曝出在秘密研发一款移动智能音箱，同时还在为可能是有史以来最大规模的科技IPO做准备。

播客主持人的判断相当直接：OpenAI大概率会选择硬刚，而不是和解。原因很简单，一旦和解，就等于默认了苹果的指控，这对一家靠技术起家、估值冲上万亿美元的公司来说，信誉打击是致命的。但硬刚也有硬刚的代价——诉讼程序会把大量内部邮件、研发记录拖进法庭，而OpenAI最不想让人看到的，恐怕就是这些技术细节的来源。

这起诉讼的核心，是苹果指控OpenAI在开发某些AI功能时，挖走了掌握苹果商业秘密的前员工，并非法使用了这些信息。虽然诉讼文件没有点名具体产品，但时间点恰好卡在OpenAI硬件计划浮出水面之际。那款传说中的智能音箱，原本被寄望成为OpenAI从软件公司转型为消费硬件巨头的第一步，如今却可能因为知识产权纠纷而延迟甚至搁浅。

更微妙的是IPO。OpenAI的估值故事建立在技术领先性上，如果法庭上被证明这种领先性部分建立在别人的商业秘密之上，投资者会怎么想？播客提到，已经有分析师将苹果和OpenAI的关系形容为“日益脆弱”，这种不确定性是IPO前最不想看到的。

当然，也有观点认为苹果此举更像是商业博弈——在AI竞赛中，用法律武器拖慢一个正在从合作伙伴变成竞争对手的公司。毕竟，OpenAI如果真做出硬件，和苹果的竞争就不仅是软件层面了。
