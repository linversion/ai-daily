Gemini Omni 1.1 Flash 发布，视频生成有了可编程的镜头控制

这是什么：Google DeepMind 于 2026 年 8 月 27 日发布 Gemini Omni 1.1 Flash，一个面向开发者的正式版生成式视频更新。开发者可以续写已有场景（模型能参考最长 10 秒前文，按 10 秒步进续到累计 40 秒）、指定首帧和末帧生成平滑转场、用 360p 草稿快速试错（比 720p 快最多 60%、成本约三分之一）、输出 1080p 或 4K 成片，还能引用最多 3 秒视频作为参考保持角色一致。可通过 Google AI Studio、Gemini Enterprise Agent Platform API 使用，订阅用户在 Google Flow 和 Gemini 应用里也能用。
🔥 为什么今天值得看：生成式视频此前的主要用法是写一段提示词然后反复抽卡，镜头怎么动、故事往哪走基本靠运气。这次更新把镜头运动和叙事推进变成了可以指定的参数，续写有 10 秒上下文兜底连贯性，首末帧插值让转场可以提前设计，360p 草稿把试错成本压到三分之一。对做创意工具和媒体编辑软件的开发者来说，视频生成第一次可以被编排进创作环节，Adobe Firefly、Figma Weave、Runway 已经接进生产环境。
展开正文

Google DeepMind 在 8 月 27 日发布 Gemini Omni 1.1 Flash，定位是面向开发者的正式版生成式视频更新。这次的核心变化集中在控制能力上，开发者可以续写已有场景、指定镜头的首帧和末帧、输出 4K 成片，也能用低分辨率草稿快速试错。

改动最大的是场景续写。此前的模型续写视频时只能参考最后一秒的画面，Omni 1.1 能分析最长 10 秒的前文，画面和剧情的连贯性明显改善。视频可以按 10 秒一段往前续，累计上限 40 秒。官方示例里，开发者用一句提示就能让镜头完成推拉变焦、环绕定格角色这类复杂运镜。

首末帧插值解决的是转场问题。给定起始画面和结束画面，模型生成两帧之间连续的视频，适合复杂的镜头环绕、变焦转场或者无缝循环素材。

成本方面，360p 草稿模式比标准 720p 快最多 60%，费用只要三分之一，适合前期分镜和快速迭代，定稿后再升到 1080p 或 4K 输出。多模态输入还支持引用最多 3 秒视频作为参考，用来保持角色形象和视觉风格一致。

接入路径有三条。个人开发者可以在 Google AI Studio 直接试用，企业走 Gemini Enterprise Agent Platform 的 API，普通用户订阅 Google AI Plus、Pro 或 Ultra 后在 Google Flow 里使用，场景续写也开放给了 Gemini 应用。

客户侧已经有落地。Adobe 把它接进了 Firefly，Figma Weave、Runway 和 GMI Cloud 也都在生产环境使用。Figma Weave 创意总监 Itay Schiff 评价说，有了续写、更丰富的参考素材和 4K，团队从生成视频走向了真正执导视频。GMI Cloud 营销副总裁 Louisa Guo 则强调细节经得起推敲，让此前不敢依赖 AI 视频的教育类内容客户用了起来。

限制也要说清楚。40 秒是累计上限，长内容仍需分段生成再衔接；草稿和成片是两档分辨率，360p 里验证过的构图在 4K 成片中未必完全一致，正式交付前需要人工复核；官方标注的快 60% 基于 360p 与 720p 的系统吞吐对比，实际体感因场景而异。

Claude Code 自动模式被攻破，安全机制拦下了自己的清理命令

这是什么：提示注入研究者 Johann Rehberger 公开了一种攻击 Claude Code auto mode 的方法，他称成功率约 80%。手法是诱导 AI 下载并解压 zip 压缩包，再执行一段 import base64 的代码，Python 导入时会顺带加载压缩包里藏的本地 struct.py，恶意代码随之运行。部分运行中 Claude 察觉被入侵并尝试终止恶意进程，清理命令却被 auto mode 拦下。Simon Willison 8 月 27 日转发了这一发现。
🔥 为什么今天值得看：Anthropic 刚把 auto mode 设为默认，等于把这套防护交给了全部用户。这次攻击暴露的问题是分类器放行了创建恶意进程的命令，却拦住终止它的命令，防护机制参与了故障本身。对正在让 agent 自主干活的人来说，默认开启的防护不能当作安全边界，把运行环境隔离起来的必要性再次被摆上台面。
展开正文

Anthropic 最近把 Claude Code 的 auto mode 设成了默认模式，并对这套防护的效果给出过相当自信的说法。这个模式让 AI 编程助手自动执行命令，每条命令先经过一个分类器判断风险，危险的拦下，安全的放行。

8 月 27 日，提示注入研究者 Johann Rehberger 公布了一种针对 auto mode 的攻击，他称成功率约 80%。手法分几步。攻击者先诱导 Claude Code 下载并解压一个 zip 压缩包，再让 AI 执行一段会 import base64 的代码。坑在 Python 的导入机制上，解压出来的文件里藏着一个本地 struct.py，执行 import base64 时 Python 会顺带加载它，恶意代码就这样跑了起来。

更麻烦的在后头。有几次运行中，Claude 自己察觉到被入侵，尝试终止那个恶意进程，清理命令却被 auto mode 拒绝了。分类器放行了创建恶意进程的命令，转头拦住了想停掉它的命令。Simon Willison 在转发时提醒，安全机制本身可能成为故障的一部分。

他同意 Johann 的结论，只要 agent 存在被攻击盯上的可能，唯一稳妥的运行方式是沙箱。具体建议有四条，把无人值守的编程 agent 放进容器、虚拟机或操作系统级沙箱里跑，限制网络出口，持续监控 agent 的行为，别把家目录、SSH 密钥、云平台凭据这类敏感信息暴露给 agent 的运行环境。

auto mode 刚成为默认，这次攻击等于在默认配置上开了个口子。对刚把防护交给所有用户的 Anthropic 来说，分类器为什么放行创建恶意进程却拦下终止它的命令，恐怕需要给出解释。

五家 Agent 沙箱实测，冷启动差 7 倍，计费口径各说各话

这是什么：MarkTechPost 8 月 27 日发布了一篇 Agent 沙箱选型对比，把 E2B、Daytona、Modal、Cloudflare、Vercel 等平台的冷启动、文件系统持久化、出口策略和计费口径统一到同一单位下比较。文章引用 ComputeSDK 开源榜单 2026 年 8 月 21 日的实测数据，并发突发场景下 Vercel 中位冷启动 0.67 秒且成功率 100%，Daytona 中位数 0.27 秒最快但 100 次只成功 37 次，Cloudflare 中位数 5.06 秒最慢。
🔥 为什么今天值得看：沙箱选型过去只能看厂商宣传页，这篇的价值在于把口径统一了。计费模型比单价更影响账单，只有 Vercel 和 Cloudflare 按 CPU 实际使用计费，其余按沙箱存活时间计费，空闲多的 agent 场景下两者差约 2 倍，配挂起机制差距还能拉大。冷启动方面，并发突发实测从 Vercel 的 0.67 秒到 Cloudflare 的 5.06 秒差 7 倍，而厂商宣传的 90 毫秒和 150 毫秒描述的是串行创建，和 agent 实际产生的并发突发对不上。对要给 agent 配运行环境的团队，这四个维度比功能清单更能决定架构。
展开正文

写代码的 agent 需要一个地方真正把代码跑起来，这个地方如今成了一门生意，至少十几家厂商在做，计费模型有四种互不兼容的写法，各家营销页上的冷启动数字都是在自己挑的条件下测出来的，测试条件没人公开。

MarkTechPost 8 月 27 日发布的这篇对比文章做的是统一口径的活。它覆盖最常进候选名单的五家，E2B、Daytona、Modal、Cloudflare 和 Vercel，也顺带纳入会改变结论的 Runloop、Fly Sprites 和 Northflank。文章认为真正决定架构选择的只有四件事，其余都是偏好。并发下的冷启动是一笔税，agent 每次调用工具都开一个沙箱的话，一天要交几千次。文件系统能不能跨轮次保留是另一件事，第二轮还看得到第一轮 pip install 装好的依赖吗。出口策略决定沙箱能不能上网、能不能中途改主意。空闲计费最容易被忽略，agent 大部分时间在等模型回话，那些秒数总有人在付钱。

冷启动部分，厂商宣称的数字彼此不可比。Daytona 定价页宣传 90 毫秒内建好沙箱，E2B 常被引用约 150 毫秒，Modal 宣传预热容器亚秒级启动，三家都没说明并发量、区域、镜像大小，也没说计时停在 API 应答还是第一条命令跑通。文章认为最有用的公开数据是 ComputeSDK 的开源沙箱榜单，它定期自动测试，衡量从 create() 到沙箱内第一条命令成功跑通的时间，每家跑 100 次并发突发，从北弗吉尼亚一台 4 核主机发起。2026 年 8 月 21 日那轮结果里，Vercel 中位数 0.67 秒、P99 1.12 秒，Modal 0.88 秒，E2B 1.61 秒，Cloudflare 5.06 秒，成功率都是 100%。Daytona 中位数 0.27 秒全场最快，但 100 次只完成了 37 次。文章的解读是，只有三分之一调用能拿到的中位数反映的是容量上限，反映不了日常延迟，任何平台上重试逻辑都不能省。尾延迟比中位数更值得盯着设计，Runloop 和 Modal 的中位数只差 10 毫秒，Runloop 的 P95（95% 的请求不超过这个耗时）却是 Modal 的 3.3 倍。Cloudflare 的 5 秒源于架构不同，它的 Sandbox SDK 跑在 Cloudflare Containers 上，要调度容器实例再启动镜像，比恢复预热好的轻量虚拟机重得多，Cloudflare 自己的正式发布文章也承认，从零启动加克隆仓库加 npm install 大约 30 秒，从备份恢复同样环境只要约 2 秒。

计费部分，文章把各家费率换算成同一单位后跑了两组成本模型。只有 Vercel 和 Cloudflare 按 CPU 实际使用计费，E2B、Daytona、Modal 和 Runloop 按沙箱存活时间计费。在贴近真实 agent 循环的空闲场景里，沙箱开着、模型在想事、CPU 几乎不动，按存活计费的平台成本涨 6.7 倍，Vercel 靠活跃 CPU 计费从第四便宜升到第三，文章估算这种计费方式在这类负载上值约 2 倍的差价。配挂起机制还能再省，E2B 自动暂停后 1000 次执行约 2.16 美元，但 4 GiB 沙箱暂停加恢复有约 17 秒开销，只有轮次间隔明显长于暂停本身才划算。

持久化和出口策略是另外两个坑。E2B 默认超时动作是直接杀掉沙箱，未保存的工作会丢，文章建议第一天就设成暂停。Cloudflare 沙箱休眠后磁盘重置回镜像。出口规则上，E2B 的允许规则压过拒绝规则，Vercel 正好相反，策略从一家照搬到另一家含义就变了。E2B 文档还写明被拦截的 TCP 连接在沙箱内看起来像连接成功，验证得靠 HTTP 状态码或 TLS 握手。文章最后给出的选型建议是，等模型多算得少选 Vercel，要对抗性代码的内核级隔离和自托管选 E2B，把持久化当产品卖选 Daytona，碰 GPU 选 Modal，应用已在 Workers 上且更看重出口安全选 Cloudflare。

Cohere 发布 2.3B 小模型 Parse 5，专啃企业文档解析脏活

这是什么：Cohere 发布 Parse 5（parse-v5.0），一个 2.3B 参数的视觉语言模型，把 PDF、PPT 和 JPEG 页面直接转成 Markdown，表格输出为 HTML，附带边界框坐标和图片描述，不需要前置 OCR。API 定价每千页 1.5 美元，已在 Parse API、Microsoft Foundry、AWS SageMaker 和 Model Vault 上正式可用，没有等待名单。
🔥 为什么今天值得看：企业文档解析是 RAG 系统里最费工的环节，扫描件和密集表格处理不好，后面的检索和问答都是空谈。Cohere 把模型做小到 2.3B，走专用小模型的性价比路线，用 4.6GB 的体积和每千页 1.5 美元的价格去换企业级吞吐。对月处理量 10 万页以上的团队，这可能比堆大模型更划算。
展开正文

企业文档解析是 RAG 系统里最脏的活。扫描件、密集表格、盖章的表单，这些材料进不了模型，前面的解析环节就得先把它们变成干净的文本。Cohere 在 8 月 27 日发布了 Parse 5（parse-v5.0），一个专干这件事的小模型。

它只有 2.3B 参数，基于 Cohere Labs 的 North-Micro-Vision-Instruct 架构，8192 token 上下文，模型文件约 4.6GB。输入 PDF、PPT 或 JPEG 页面，输出 Markdown，文字按阅读顺序排列，表格转成 HTML，还带表单键值对、图片描述和边界框坐标。传统做法要在前面挂一个 OCR 阶段，Parse 5 一步到位，没有前置 OCR。支持九种稳定语言，包括英语、日语、西班牙语等，其他语言零样本可用但精度更低。

价格是每千页 1.5 美元。部署渠道包括 Cohere Parse API、Microsoft Foundry、AWS SageMaker 和单租户的 Model Vault，没有等待名单，也没有研究许可限制。Model Vault 上 Medium 实例每月 2500 美元，XL 每月 4300 美元。原文算了一笔账，按每页 0.0015 美元计，Medium 实例要到每月约 167 万页才比按量付费划算，XL 则要约 287 万页。低于这个量，按量调用更便宜。

基准成绩要打折看。Cohere 自报 ParseBench 得分 79.2，高于 Mistral OCR 4 的 74.5 和 Azure Document Intelligence 的 74.3，但这个分数只取了五个维度中的三个，即表格、内容忠实度和语义格式，弃掉了 charts 和 visual grounding，而后者是多数解析器最容易翻车的地方。在 LlamaIndex 的公开榜单上，同样几家厂商的五维总分都掉到 60 分上下，Cohere Parse 目前还没上榜，榜首 LlamaParse Agentic 是 84.88。79.2 只是厂商自报的子集分数，读者应把它和榜单排名分开看。

适用边界也清楚。Cohere 自己说，月处理量到 10 万页以上，这套经济性才开始显著，种子期初创公司用它可以，但意义不大。目标行业是金融、保险、医疗、公共部门这类文档密集的领域。对已经跑着 RAG 系统的中型团队，拿免费试用 key 在自己的文档上测一轮，可能是最实际的判断方式。

AI 编码代理写 Go 代码时有个通病，写出来的东西像是停在几年前的版本。JetBrains 把这个问题拆成两个病因。一是训练数据滞后，模型不知道训练截止日期之后加的新特性，比如 Go 1.26 的 errors.AsType[T]，模型没见过自然用不出来。二是频率偏差，就算模型认识新写法，训练语料里老写法出现得更多，于是 for i := 0; i < n; i++ 这种循环比 for i := range n 更容易被吐出来。

GitHub 上一个叫 awesome-claude-skills 的仓库最近登上 Trending，星标数达到 73.6k，fork 数 8.4k。它由 Composio 公司维护，收录了 1000 多个生产可用的 Claude 技能，按文档处理、开发、数据分析、商业营销、写作沟通、创意媒体、效率组织、协作、安全等类别整理。

技能（Skill）是 Anthropic 在 2025 年 10 月推出的格式，12 月被开放为开放标准，现在 Claude.ai、Claude Code、Claude API、OpenAI Codex、Cursor、Gemini CLI、Antigravity、Windsurf 都支持它。这意味着这份清单里的技能不只 Claude 能用，换一家 agent 工具，大部分照样能装。

仓库还讲清了技能的加载机制。每个技能在会话开始只占约 100 token，正文一般低于 5000 token，等 agent 判断当前任务用得上才加载，附属脚本和参考文件也是按需读取。所以一个 agent 可以挂几百个技能而不撑爆上下文窗口。

有一点读的时候要自己分辨。Composio 是一家商业公司，清单里有一整节应用自动化技能全部走它自家的 Rube MCP，README 也用不少篇幅推广它的 MCP 网关，注册 API key 才能用。资源本身是真实的，但这份清单同时也是它的获客渠道。
