Haiku 5.5 降价九成,专攻 agent 高频小任务

这是什么：Anthropic 于 10 月 7 日发布小模型 Claude Haiku 5.5，定位高吞吐、成本敏感的任务，比如摘要、分类、数据库查询、上下文压缩，以及给大模型当编码子代理。10 万 token 以内的请求定价为每百万 token 输入 0.10 美元、输出 0.50 美元，比上一代 Haiku 4.5 便宜 90%。模型已上线 Anthropic 自家平台及 AWS、Google Cloud、Azure，模型 ID 是 claude-haiku-5-5。
🔥 为什么今天值得看：agent 应用的成本大头常在高频小任务上，压缩上下文、检索、分类每一步都在消耗 token，过去用大模型跑这些活很贵，用旧小模型又常干不好，Haiku 4.5 的价格甚至是 OpenAI GPT-6 Luna 的十倍。Haiku 5.5 把这类任务的单位成本压低一个量级，自报的电脑操作和知识工作成绩又明显缩小了与大模型的差距，让小模型跑量、大模型收尾的分工在账面上站得住。同场的 Sonnet 5.5 缓存降价和订阅 API 额度，进一步降低了企业在 Claude 平台上跑代理的门槛。
展开正文

Anthropic 发布了小模型 Claude Haiku 5.5，官方称之为迄今最便宜、最快、能力最强的小尺寸模型。它瞄准摘要、分类、数据库查询、上下文压缩这类高频重复任务，也给 Opus 5.5 和 Sonnet 5.5 的编码工作当子代理，模型 ID 为 claude-haiku-5-5，已上架 AWS、Google Cloud 和 Azure。

价格是这次发布最硬的部分。10 万 token 以内的请求，输入每百万 token 收 0.10 美元，输出收 0.50 美元，比 Haiku 4.5 的 1 美元和 5 美元便宜九成；超过 10 万 token 后为 0.50 美元和 2.50 美元，仍便宜一半，缓存读取最低 0.01 美元。Anthropic 估算约 90% 的既有 Haiku 请求落在低档，平均负载成本约降 75%。这套低档价格与 OpenAI 上月发布的 GPT-6 Luna 完全打平，Luna 到 27.2 万 token 以上才提价至 0.20 和 0.75 美元，长请求反而是 Luna 更划算。

能力数字全部来自 Anthropic 自报评测。电脑操作基准 OSWorld 2.1 离线子集上，Haiku 5.5 拿到 72.4%，Haiku 4.5 只有 15.7%，GPT-6 Luna 为 48.9%，Sonnet 5.5 为 83.9%。覆盖 44 个职业的知识工作基准 GDPval-AA v2.1 上得 1620 分，是上一代 735 分的两倍多。编程代理基准 Terminal-Bench 4.0 要分清档位看，39.2% 是把推理投入拉满 max 档的成绩，默认 medium 档约 20%，Haiku 4.5 在这项上得 0 分。这也是 Haiku 系列第一次支持 low 到 max 五档可调 effort。

独立开发者 Simon Willison 用自己的 token 计数工具实测，同一段长提示词在 Haiku 5.5 上的 token 用量约为 Haiku 4.5 的 1.25 倍，新 tokenizer 切得更碎，Anthropic 在发布材料里也承认等效任务会略微多耗 token。九成的标价降幅落到真实账单上会因此打些折扣。

Anthropic 给它安排的是辅助工角色。金融 AI 公司 Rogo 描述的用法是，大模型负责搭建演示文稿，Haiku 子代理钻进 10-K 年报捞出某页需要的分部营收数字，够准、够快、够便宜，可以大量反复调用。多步复杂编码官方仍推荐 Sonnet 5.5 和 Opus 5.5。安全策略同步收紧，网络安全防护比 Haiku 4.5 更严，标准防护下屏蔽渗透测试类请求，生物安全限制与 Sonnet 5.5 等近期模型一致。

发布还捆带三件事。Sonnet 5.5 缓存读取价从 0.20 美元减半到 0.10 美元，Anthropic 估算多数代理类负载因此省约 20%；Max 5x、Max 20x 和 Team 订阅用户每月分别获得 100、200 和最高 500 美元 API 额度，当月不用即作废；Python 和 TypeScript SDK 新增 computer use 与 browser use 的 beta 支持。

微软让 Copilot 翻本地文件帮你报税,AI 动手干活

这是什么：微软在 10 月 7 日的 Windows 与 Surface 发布会上宣布,Copilot 将新增读取本地文件和跨系统执行操作的能力,支撑技术叫 Hybrid Intelligence,让本地模型和云端模型搭配干活。现场用一段报税视频演示了效果,AI 自己翻文件夹找材料、改文件名、打包压缩、起草邮件发给会计。这些功能未来两个月内进入 Copilot,新的搜索栏快捷操作今秋登陆 Windows 11。目前一切停留在宣布和演示阶段,尚未正式上线。
🔥 为什么今天值得看：过去 AI 助手都困在对话框里,只能你问它答。这次微软把文件系统和系统操作交给了 Copilot,它可以翻你的硬盘、改你的文件、替你发邮件,从问答工具变成在桌面上动手干活的执行者,人和电脑的协作多了一种新形态,一句话交代需求,剩下交给 AI。代价同样直接,能替你整理报税材料的 AI 也天然看得见你的收入证明和银行记录,而微软尚未说明它的隐私边界,能力越大,这个问题越绕不过去。
展开正文

微软在 10 月 7 日的 Windows 与 Surface 发布会上宣布,Copilot 将新增两类权限,读取电脑里的本地文件,以及跨系统替用户执行操作。支撑这些能力的技术思路被微软命名为 Hybrid Intelligence,让应用和工具同时依靠本地模型与云端模型来高效完成任务。

对普通用户来说,这次升级改变了一个基本格局。过去几年 AI 助手都活在对话框里,你问一句它答一句,真要动文件还得自己来。Copilot 拿到文件系统和系统操作的入口之后,就从回答问题的顾问变成了能在桌面上干活的执行者,用户的硬盘第一次向这类系统级 AI 助手敞开。

最能说明问题的是现场那段报税演示。Copilot 业务执行副总裁 Jacob Andreou 在台上讲解一段视频,视频里他对微软的 Autopilot 工具说,会计刚发了邮件来,让 AI 把会计需要的材料准备好。Autopilot 随即跨着多个文件夹把相关文件一件件找出来,给它们逐个改名,压成一个 zip 包,再起草一封发给会计的邮件,把压缩包放进附件。找文件、改名、打包、写邮件,整条链路没有一步需要人插手。

落地节奏也一并公布。Andreou 表示,基于 Hybrid Intelligence 的功能会在未来两个月内陆续进入 Copilot。同一场发布会还演示了新的 Windows 搜索体验,搜索栏里可以直接执行快捷操作,比如打开暗色模式、用内嵌的滑杆调高麦克风音量,或者发一条短信。负责 Windows 与 Surface 业务的 Pavan Davuluri 介绍,这套新搜索今年秋天登陆 Windows 11 电脑。

留下最大悬念的是隐私。Copilot 翻本地文件时能碰到哪些目录,改动和发送之前要不要用户确认,文件内容会不会被送去云端模型,微软在发布会上都没有说明。一个能替你整理报税材料的 AI,同时也看得见你的收入证明和银行记录,边界问题没有答案之前,这份方便始终要打个折扣。

微软联手Nvidia推出Arm笔记本,2599美元起正面叫板MacBook Pro

这是什么：微软在旧金山开了一场发布会,推出笔记本 Surface Laptop Ultra,10 月 16 日开卖,2,599 美元起。这台电脑最特别的地方是处理器换了供应商,芯片来自 Nvidia,叫 RTX Spark,采用和手机芯片同族的 Arm 架构,统一内存最高能配到 128GB。微软把它当作正面抗衡苹果 MacBook Pro 的旗舰来打造,同用 RTX Spark 芯片的首批笔记本里,最高配机型卖到 7,000 美元。
🔥 为什么今天值得看：Windows 笔记本的处理器市场几十年来由 Intel 和 AMD 分食,Nvidia 用 RTX Spark 第一次挤进来,而且一进门就打高端。128GB 统一内存意味着不少大模型可以整模型装进笔记本本地运行,不联网,不付 API 账单,数据不出设备,这对有数据合规要求的企业和开发者是实打实的新选项。苹果用 M 系列芯片证明过 Arm 架构做得出高端笔记本,现在 Windows 阵营终于有了对位产品,买高端笔记本的人第一次面对三家芯片同台竞争。
展开正文

微软今天在旧金山开了一场 Windows 与 Surface 发布会,CEO Nadella 与 Nvidia CEO 黄仁勋同台,聊的核心议题是本地 AI 会怎样塑造 PC 的下一个阶段。整场发布会最重要的落点是一台笔记本。Surface Laptop Ultra 定于 10 月 16 日发售,2,599 美元起,配 15 寸 HDR 触控屏,峰值亮度 2,000 尼特,标配 24GB 内存和 512GB 存储,处理器换成 Nvidia 的 RTX Spark,这是一颗 Arm 架构的 PC 芯片,统一内存最高可配到 128GB。Nvidia 借这台机器第一次把自研 Arm PC 芯片装进笔记本,微软则把整机的价位与配置直接摆到高端 MacBook Pro 的对面,首批 RTX Spark 笔记本阵营里最高配机型卖到 7,000 美元。

充电也换了方案。微软弃用了专有的 Surface Connect 磁吸口,改用名为 Magnetic Connect 的磁吸 USB-C 充电,线缆靠近机身右侧接口就会自动吸附,这个接口照常支持视频与数据传输。Windows 与 Surface 负责人 Pavan Davuluri 现场说:"把接头拿近,它就直接吸到位了。"

开发者拿到的是一台迷你主机。Surface RTX Spark Dev Box 同日开放预订,售价 5,999 美元,11 月发货,配 128GB 统一内存和 100 瓦的散热设计,官方称它面向本地 AI,可以运行超过 1,200 亿参数的模型,适合测试模型、原型搭建 AI 代理和在设备上跑 AI 编码工具。机身采用 3D 打印阳极氧化铝,外壳兼作散热器,造型神似 Xbox Series X 的顶部散热口。它比 Nvidia 去年推出的 DGX Spark 迷你主机更贵,背景是内存等元器件缺货涨价。

同场还有一条软件侧消息,Meta 的 AI 代理 Muse 将推出 Windows 原生应用,微软没有给出时间表,Mac 版今年 9 月已经上线。

对 PC 行业来说,RTX Spark 的冲击超出微软一家。Windows 笔记本处理器市场此前由 Intel、AMD 加上供应 Arm 芯片的高通三分,Nvidia 带着自研 Arm 芯片挤了进来,还有报道称 Lenovo 和 Acer 也在首批 RTX Spark 整机厂商名单里。买家真正要掂量的是软件成熟度,Windows on Arm 跑老的 x86 程序依赖模拟层,有媒体报道预发布测试中原型机出现过 CUDA 相关故障,而 CUDA 生态恰是这批机器卖出高价的核心理由,苹果当年打磨 Rosetta 转译层用了多年,Nvidia 和微软才刚起步。

ChatGPT 回答里长出可点的图表、按钮和小工具

这是什么：OpenAI 自 10 月 7 日起向 ChatGPT 推送 Intelligent UI,模型的回答可以在文字之外直接嵌入图解、图表、表单、可点击按钮和现做的小工具,功能随 GPT-6 的 Sol 与 Luna 两个版本一同上线。Plus、Pro、Business、Enterprise 四档付费用户先收到,Go 档和免费档从周四起跟进。
🔥 为什么今天值得看：交互形态变了。过去模型靠大段文字回复,用户读完还要自己动手做表、找工具;现在判断何时画图、何时给一个能点的部件图,本身成了模型被训练出来的能力,小工具直接长在对话里。这层界面把 ChatGPT 往应用生成器的方向推了一步,也确立了高档用户拿中档模型 Sol、免费和 Go 用户拿高效模型 Luna 的分层方式。
展开正文

OpenAI 自 10 月 7 日起向 ChatGPT 推送名为 Intelligent UI 的交互层,模型的回答可以在文字之外直接嵌入图解、图表、表单、可点击的按钮,甚至把现做的小工具嵌进对话,比如退休金计算器、复古小游戏或者账单分摊器。

这次更新随 GPT-6 的两个版本一起落地。Plus、Pro、Business、Enterprise 四档付费用户自 10 月 7 日起收到中档的 GPT-6 Sol,Go 档和免费档从周四起拿到更高效的 GPT-6 Luna。GPT-6 模型本身上月已经发布,这一轮推送的新东西是这层交互界面,加上 Sol 和 Luna 正式进入 ChatGPT。GPT-6 还带来更好的网页搜索,收集信息期间也会先给出更快的部分答案。OpenAI 同时在博文中称,GPT-6 对绕过安全训练的尝试表现出更强的抵抗力,这一条是官方说法。

Grok Bot 迎来后端大升级,智能来源切换为对手 Anthropic 的 Claude Opus 5.5

这是什么：据 9to5Mac 报道,Grok Bot 在 10 月获得重大后端升级,智能来源从 SpaceXAI/Cursor 的较弱模型切换为 Anthropic 的 Claude Opus 5.5,升级自 10 月 7 日起生效。Claude Opus 5.5 是 Anthropic 最强模型家族的最新版本。
🔥 为什么今天值得看：消费级 AI agent 应用从比谁先上线进入比谁更聪明的阶段,Meta 的 Muse 基本免费且刚登陆 iPad,OpenAI 的 ChatGPT Dot 由 Astra 驱动,Grok Bot 需要更强的模型守住位置。同时,模型能力开始像云服务一样跨阵营流通,SpaceXAI 旗下的产品直接接入了 Anthropic 的模型,而 Anthropic 今年已经向 SpaceX 采购算力,两家公司既有供应又有采购,生意网络越缠越紧。

微软开源3500行RL框架,部署agent不改代码参加训练

这是什么：微软亚洲研究院为已有开源项目 Agent Lightning 发布完全重写的 v1.0。框架约 3500 行代码,分 API Gateway、Rollout Controller、Customized Trainer(基于 verl)三个组件,正式定义 Harnessed Agentic RL 范式,部署态 agent 外壳不改代码直接参与 RL 训练,新增原生 Kubernetes 任务调度与 Collocated Async RL 共置异步训练。
🔥 为什么今天值得看：训练时重建 agent、部署时换回原版,这个错位让 RL 训练成果在真实外壳上打折扣。v1.0 用 OpenAI 兼容代理消掉重建成本,用 Kubernetes 原生调度避开商业沙箱的开销,把 agentic RL 的门槛压到普通团队能复现的水平。约 6000 个训练样本、不需要大规模算力,就在 SWE-bench Verified 上拿到 14.6 个百分点的绝对提升,给小样本起步的 agent RL 训练提供了完整配方。
展开正文

训练智能体的强化学习流水线里有个长期错位。实验室里训练的是一套按训练框架接口重新实现的 agent,部署上线的是另一套带完整工具链的 agent,两者行为很难对齐。微软亚洲研究院为已有开源项目 Agent Lightning 发布了完全重写的 v1.0,更强调轻量、接入真实外壳和完整可复现的训练流水线,整个框架约 3500 行代码,并正式定义了 Harnessed Agentic RL 范式,部署时用哪个 agent 外壳,训练时就让同一个外壳直接参与强化学习。

这里的 agent 外壳指模型外层那套管理上下文、调用工具、执行代码的程序,mini-SWE-agent、OpenHands、OpenCode、Claude Code、Codex 都属此类。传统 agentic RL 框架(早期的 verl、AReaL、slime)由训练系统自己管理环境交互循环,训练前必须把 agent 的循环在框架里重建一遍,重建昂贵,重建出来的 agent 也可能和部署版本行为不一致。

Agent Lightning v1.0 的做法是在 agent 和模型之间放一个 OpenAI 兼容的 LLM 代理。agent 照常运行,只要把原先调用模型 API 的端点指向这个代理,训练系统就能观察并记录每一次模型调用,收下提示、响应和对数概率。外壳代码一行不用改。

真实外壳给训练带来四个难题。重新分词后相邻调用未必能拼回一个完整样本;按样本计算优势会让产出样本多的 rollout 被重复计权;按样本数平均损失同样会被外壳行为带偏;样本数量和长度只有外壳跑完才知道,后端要把变化的负载映射到固定的 GPU 配置。v1.0 对每个难题都给出处理,实验显示 rollout 级优势计算加 rollout 级损失归一化能拿到更高的验证奖励,训练中的策略熵也更稳定。

框架本身由三个组件组成。API Gateway 充当那个 OpenAI 兼容代理,存储 rollout、模型和事件;Rollout Controller 启动并管理 agent 执行,本地进程或标准 Kubernetes 任务均可;Customized Trainer 基于 verl 构建,负责创建 rollout、等待完成、收集样本并拼装最终训练数据。

调度上,v1.0 引入 Collocated Async RL。agent 之间的 rollout 时间差异很大,同步 RL 要等批内最慢的那个,GPU 大量空转;完全异步方案又要为 rollout 和训练分别准备 GPU 池。新方案让两者共享同一组 GPU,攒够 rollout 后暂停接收新请求,等在途请求结束再更新权重,状态切换对外壳透明。实验中这套调度比同步 RL 端到端快约 2 倍,GPU 用量低于常规异步方案。

成本是另一个务实选择。同类框架常把 agent 放进 Modal Sandbox、E2B 这类商业沙箱跑 rollout,规模一上来开销快速上升。v1.0 改成标准 Kubernetes 任务,自建集群、云上 Kubernetes 或本地基础设施都能复用,整条流水线开源且可复现。

效果数据给得完整。研究团队在 SWE-smith 加 mini-SWE-agent 加 Qwen3.5-9B 上搭了端到端流水线,覆盖数据清洗、环境构建、防 reward hacking 和 RL 训练。训练集约 6000 个样本,基于开源数据集,不需要大规模算力,单独 RL 训练就把 Qwen3.5-9B 在 SWE-bench Verified 上的 Pass@1 从 41.8% 提到 56.4%,绝对提升 14.6 个百分点。这是基准测试成绩,迁移到生产环境还需另行验证。

机器人基础模型一步生成动作,GR00T 延迟最高降七成

这是什么：arXiv 2610.00864 提出 Kinematic MeanFlow(K-MF),让机器人基础模型一步生成动作。论文先诊断直接套用 MeanFlow 会崩溃的原因,去噪后期局部加速度急剧上升,且其幅度在样本间的分布随去噪进展发散,再给出对应解法,基于运动学恒等式把时间导数项拆成两个子区间项,由一个中间点分隔,分别捕捉早期与后期去噪动态。
🔥 为什么今天值得看：机器人控制对延迟敏感,每步动作都要模型现场算,算慢了整台机器就卡着等。一步生成把多轮迭代压成一次前向,在 Jetson Orin 这类机器人本体的边缘算力上尤其值钱,同样硬件可以支撑更高控制频率,或把省下的算力留给感知。论文还把 MeanFlow 类方法在机器人上的失败归因到两条可检验的动力学规律上,后来者能在这个基础上继续改进。
展开正文

机器人每动一下,策略模型都要现场算出接下来一段动作。主流的机器人基础模型(RFM)靠多步 flow matching 生成动作,从噪声出发迭代多轮,每多一轮就多一次前向计算,延迟随之堆高,机器人只能停下来等。图像生成里验证过的 MeanFlow 能一步出结果,直接搬到机器人上却会性能崩溃。

arXiv 2610.00864 这篇论文先查清崩溃根源。机器人模型的速度场里,局部加速度在去噪早期保持稳定,到了后期急剧上升,不同样本之间的幅度差异也随去噪进展越拉越开。一步生成要模型一口气回答整段去噪过程,后期剧烈变化的量把误差层层放大。

对策是 Kinematic MeanFlow(简称 K-MF)。它借一条运动学恒等式,把 MeanFlow 的时间导数项拆成由一个中间点分隔的两个子区间项,分别捕捉早期与后期去噪动态,压住误差放大。一步生成由此落地,从头训练与微调两种范式、多任务评测里多数设置好过多步 flow matching。把它装进 GR00T-N1.6 的动作头,L40 与 Jetson Orin 上 eager 和 compiled 模式延迟降 67.5% 至 74.4%,端到端延迟降 30.3% 至 54.9%。延迟数字来自基准实测,不等同真实机器人任务性能提升,真机表现仍待验证。
