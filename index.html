Kimi K3.1 Pro 权重如约落地，架构首次全公开

这是什么：月之暗面 11 月 2 日在 HuggingFace 上架 Kimi K3.1 Pro 的模型权重，比 10 月 24 日 API 发布时承诺的 11 月 4 日提前两天兑现开源。这是 K3.1 系列的第一个模型，完整架构细节随权重首次公开。开发者第一次可以不经过官方 API，自行部署这个在官方自报基准中摸到前沿集团的模型。
🔥 为什么今天值得看：开源权重把使用方式从租接口变成持有资产。开发者可以自己部署与微调，数据流向也掌握在自己手里，成本结构和数据安全都随之改变。对一个总参数 2.8T、官方模型卡自报成绩与 Claude Opus 5.5 及 GPT-6 Astra 同表对比的旗舰模型，这种开放显著拉低了同档能力的获取门槛。完整架构参数同步披露，外界第一次能看清月之暗面旗舰模型的内部构造，研究社区也拿到了分析与改进的一手材料。

11 月 2 日，HuggingFace 上出现了 moonshotai/Kimi-K3.1-Pro 的模型仓库。此时距离月之暗面许下的期限还有两天。这家公司在 10 月 23 日发布 Kimi K3.1 Pro 的 API 时承诺，11 月 4 日之前放出模型权重。承诺兑现了，还提前了。

权重可以理解成模型的全部"脑内参数"。AI 大模型本质上是巨大的参数文件，训练完成后这些数字固定下来，谁拿到文件，谁就能让模型跑起来。此前外界只能通过官方接口使用 K3.1 Pro，权重公开后，任何人都可以下载这套参数，在自己的服务器上部署运行，数据不必再经过官方。

这次一并公开的还有完整架构。Kimi K3.1 Pro 采用混合专家架构（MoE），总参数 2.8T，每个 token 只激活 104B。它内部有 896 个"专家"网络，每处理一段输入只调用其中 16 个，外加 2 个常驻的共享专家，用轮班制扛起了大模型的容量。全模型 93 层，注意力部分由 69 层 KDA 和 24 层 Gated DSA 组成。相比上一代 Kimi K3，月之暗面用 Gated DeepSeek 稀疏注意力替换了全注意力的 Gated MLA 层，官方称目的是让长上下文建模更高效。它的上下文窗口达到 1,048,576 个 token，大致相当于一次性读入整套长篇文档或一个大型代码库。

另有两个工程细节。模型采用量化感知训练，权重以 MXFP4 精度、激活以 MXFP8 精度发布，训练阶段就按压缩后的数值格式进行，发布的直接是瘦身版权重，部署时的显存压力更小。它还配备了 401M 参数的视觉编码器 MoonViT-V2，能同时读文字和图片，官方称其为原生多模态的智能体模型。

能力几何？官方模型卡自报了成绩单。在考察终端真实任务完成度的 Terminal-Bench 4.0 上，K3.1 Pro 得 65.7，低于 Claude Opus 5.5 的 66.4，高于 GPT-6 Astra 的 58.2 和 Claude Fable 5.1 的 57.9。博士级科学题库 GPQA-Diamond 上它拿到 94.2，联网查资料方向的 BrowseComp 成绩为 92.1。这些分数全部出自月之暗面自己的模型卡，各对比模型的得分来源不同并附有评测协议脚注，独立第三方的复测结果还有待跟进。

落地途径有两条。想省事的开发者可以直接调 platform.kimi.ai 的 API，接口兼容 OpenAI 和 Anthropic 两种格式，推理力度通过 reasoning_effort 字段在 low、high、max 三档之间调节，默认 max。想自己扛机器的，官方推荐用 vLLM、SGLang 或 TokenSpeed 三种推理引擎运行权重。另有一点需要留意，许可证是自定义的 Kimi K3.1 Pro License，具体条款需要使用者自行查阅。

社区的反应速度能说明需求。上架约一周，HuggingFace 页面显示下载已达 25,569 次，点赞 1,730 个，社区已经衍生出 17 个微调版本和 12 个量化版本，另有 11 个在线应用直接调用这个模型。一个总参数 2.8T 的旗舰模型，从 API 独占到人人可下载，中间只隔了十天。

高盛禁了交易员的编码代理，银行家却要承销 Anthropic

这是什么：彭博社 11 月 8 日报道，高盛今年 10 月更新的内部指引把 Claude Code 与 GitHub Copilot 限定为工程师专用，全行约 4.7 万名员工中约 1.2 万名工程师保留权限，交易员和银行家的访问被切断，横跨交易、量化研究与软件工程的 Strats 岗位仍在名单内。调整前经过一轮生产力与风险审查。这是彭博社从知情人士处获得的单源报道，高盛未发官方公告，发言人 Nick Carcaterra 仅回应银行在向员工提供某些 AI 工具以确定最佳用例。
🔥 为什么今天值得看：这件事给所有把 AI 编程工具发给全员的公司划了一条线。编码代理能以使用者本人的权限读写文件、执行代码，工程师产出的代码有审查、测试和部署流程兜底，业务人员攒出来的脚本往往直接跑在与客户数据相连的机器上。对受监管的金融机构，信息屏障这类合规要求不会因为代码来自一句提示词就豁免。高盛用角色划分给出了它的答案，谁有能力审查代理写的代码，谁才有权用它。工具收回之后，交易员盯客户流、建模的需求仍然存在，这些活最终还是要有人接。

彭博社 11 月 8 日报道，高盛在今年 10 月更新的内部指引中，把 Anthropic 的 Claude Code 和微软的 GitHub Copilot 收回到工程师群体专用，交易员和银行家失去访问权限。高盛全行约 4.7 万人，保留权限的工程师约 1.2 万，横跨交易、量化研究与软件工程的 Strats 岗位也在名单之内。消息来自知情人士，调整前经过一轮生产力与风险审查，高盛发言人 Nick Carcaterra 的公开回应只有一句，银行向员工提供某些 AI 工具，目的是"to determine the best use cases"，摸索全行的最佳用例。

受冲击最大的是交易员。他们此前用这些工具监控客户交易流、给市场走势和持仓建模，还拿它制作图文材料，新规落地后怨言不少。几个月前风气还完全不同，首席信息官 Marco Argenti 7 月对外称赞非技术员工的 vibe coding，也就是用大白话描述需求让 AI 生成可用程序，交易员和银行家搭出原型再交工程师完善；上个月在都灵的一场会议上，他把全行 AI 采用描述成一波一波推进，约 1.2 万开发者是第一波。10 月的指引把编码代理锁回了这一波人手里。

收紧的账算在风险上。Claude Code 这类代理能读写文件、自己写代码并运行，权限通常与使用者本人相同。工程师用它写的代码要过审查、测试和部署流程，交易员随手搭的监控脚本可以直接进入日常使用。投行还负有信息屏障义务，做并购的银行家与可能从中获利的交易员之间必须隔墙，业务人员攒出来的工具从没按这些规矩设计过，提示注入攻击还能让代理执行藏在数据里的恶意指令。代码的可解释性也是问题，一位 Meta 工程师上月自述，他如今上线的代码连自己都无法完全解释，专业开发者尚且如此，交易员更难判断代理写的模型在极端行情下会做什么。成本同样入账，代理按 token 计费，用得越多账单越贵，亚马逊已因员工为刷榜让代理跑无意义任务而关停内部排行榜，埃森哲则给每名员工每月补贴 29 美元的 Claude。

戏剧性在资本这一侧。招股书 S-1 显示高盛与摩根士丹利是 Anthropic IPO 的主承销商，文件 10 月 26 日提交，预计 11 月底前以代码 ANT 登陆纳斯达克。接下来几周，高盛的银行家要向投资者推销这家公司的股票，而他们中的大多数人刚被禁止使用其编码代理。高盛与 Anthropic 的工程合作并未中断，Anthropic 工程师今年在高盛驻场六个月，帮其搭建了贸易记账与客户入职的中后台代理，由工程团队运营。巴克莱则走在另一头，10 月刚宣布年底前一半开发者用上 Claude Code，三周后公布的 5000 人裁员名单里就有开发者。

Lovable 删掉几乎全部 agent 代码的工程账

这是什么：11 月 4 日，Lovable 联合创始人 Anton Osika 在公司新上线的技术博客发表首篇文章 How we built Lovable, and why we keep rebuilding it，首次公开团队删掉几乎全部 agent 代码的决策过程。同文披露平台代码库累计收到超过 10 万次 pull request，用户创建的项目超过 7000 万个，并首次交代异步多智能体系统的兴废、用知识文件加 RAG 替代微调的方案（Lovable Stack Overflow 使卡死率降 5%，作者数据），以及可复制整台运行中计算机的 Camille 框架等技术细节。
🔥 为什么今天值得看：行业主流做法在给智能体加更多自主性，Lovable 的复盘给出了一份反向账本。约束越少的智能体越容易钻进死胡同，完成时间不可预期，对完全不会编程的目标用户尤其致命。这家公司靠收窄问题域站稳，靠削减自主性换来可预测，又用检索知识文件替代了模型训练，每一步都在做减法，最终撑起 7000 万个项目。对正在做 agent 产品的团队，这份带着真实数据的一手取舍记录，比任何框架的宣传页都值得细读。

一家帮人靠聊天生成软件的公司，公开讲了自己删掉几乎全部 agent 代码的经过。11 月 4 日，Lovable 联合创始人 Anton Osika 在公司新上线的技术博客发表首篇文章，复盘这个平台三年多的架构演变。agent 中文常译作智能体，指让模型自己决定下一步调用什么工具、怎么干的程序。Lovable 的产品正是靠 AI 生成整个应用，这份自曝的家底因此格外有分量。

起点在 2023 年春天。Anton 把开源项目 GPT Engineer 放上 GitHub，用户描述想要的软件，程序追问几句就写出整个代码库。同年他写下 Lovable 的计划，让不会写代码的人通过聊天创建、部署并持续改进软件，实时看到结果。到今天，这个代码库累计收到超过 10 万次 pull request（开发者提交代码修改的合并请求），他与联合创始人 Fabian 带着团队把计划变成了产品，平台上用户创建的项目超过 7000 万个。

第一笔账是收窄。团队只做从零开始的全新项目，避开存量代码库的各种环境差异，随后砍掉了让用户自选前端技术栈的入口，替所有人定死一套固定技术栈。问题域变小后，代码结构和运行环境都在掌控之内，一处优化能惠及所有项目。作者把方法论概括为先把问题框小，再把执行握在手里，最后让每一次结果都变成学习素材。

最有戏剧性的一笔在自主性上。Anton 一直赌模型会快速变强，推动团队做更自主的智能体，工程师 Mårten Wiman 据此搭出精密的异步系统，主智能体能创建任务并委派子智能体。实际跑起来，约束越少的智能体越容易钻进技术死胡同，出错且完成时间不可预期，自由度越高产品越不可靠。团队后退一步，删掉几乎全部 agent 代码，回到一个用户请求触发一条可预测的工具链，配上聊天和实时预览。到 2024 年底，主编辑流程已是一次响应包含全部文件改动，当时模型的原生工具调用不够可靠，团队让模型把代码包进类似 XML 的标签里再事后解析。删掉的只是自主决策那一层，生成代码、一键部署的能力全部保留，下一步走哪由用户在预览页面上决定。

替代训练的方案同样朴素。原计划用产品数据微调模型，也就是拿自家数据继续训练。2024 年工程师们翻看故障应用的聊天记录，把反复出现的错误写成简短笔记，比如图标只能用 lucide-react 图标库里真实存在的名字，拿不准就选通用款，检索环节再按任务把相关笔记注入模型上下文，全程无需训练。Anton 当时把这条路称作一条新的缩放定律，一个应用里踩过的坑能立刻帮到下一个用户。同一思路后来做进 Lovable Stack Overflow，为智能体检索问题与解法，早期版本让用户卡死率降低了 5%（作者数据）。

速度是另一条主线。沙箱保留项目文件并让开发服务器持续运转，改动直接刷新预览，增量 TypeScript 检查复用此前的分析结果，把每次编辑、检查、修正的循环压到更短。这套有状态沙箱后来长成 Camille 框架，能对整台计算机的内存、CPU 状态和磁盘做快照，把运行中的应用连同环境与数据库整体复制或合并，多个智能体可以从同一起点分头尝试不同方案，隔几天回来也能在几秒内恢复现场。

文末他留下三道开放题，生产软件的测试、部署、维护与信任，桌面端与移动端等全类型软件，以及软件栈本身的重建。按他的判断，三题全解之后得到的将超越一个 AI 软件工程师，是一个能让人把整门生意跑在上面的平台。

无显卡 64GB 内存跑 284B 大模型，量化压到 1.71 比特

这是什么：开源项目 llama-modchip 发布 v2.4.0。这个已在 GitHub 累计 49 次提交的 CPU 推理项目，本次新增对 30B 级 MoE 模型的支持，量化位宽 3.75 bpw，开发者自报解码速度达到每秒 25 到 111.6 个 token；同时公布了 256K 上下文满载时 57.61 GiB 的峰值内存、13.1 毫秒的 KV 缓存槽位恢复速度，并放出技术论文、架构文档与可提交成绩的社区基准排行榜。项目在 Hacker News 的讨论帖收获 372 分。
🔥 为什么今天值得看：284B 参数这个量级，过去只存在于数据中心。llama-modchip 把它的运行门槛压到一台 64GB 内存的普通台式机，无 GPU 也能跑，对隐私敏感场景、断网环境和用量极大的个人用户都是一种新选项。更实际的意义在 30B 档，每秒 25 到 111.6 个 token 的自报速度说明纯 CPU 方案开始接近日常可用的区间。它同时划出了清晰边界，1.71 bpw 的激进量化换来了内存和速度，付出的是质量余量，社区对这笔交换是否值得并无共识。

一台没有独立显卡的台式机，只靠 64GB 内存和一颗 16 核 CPU，把总参数 284.33B 的 DeepSeek-V4-Flash 跑了起来。开源项目 llama-modchip v2.4.0 公布的自报实测里，这台机器预填充速度达到每秒 44.36 个 token，生成速度在每秒 9.1 到 14.7 个 token 之间。项目讨论帖当天在 Hacker News 拿下 372 分。

这笔硬件账值得细算。284B 参数的模型若按常见的 8 比特量化存放，需要近 300GB 存储，单台家用机无从谈起。llama-modchip 的解法是把每个权重平均压到 1.71 比特。bpw 这个单位衡量的是每个参数占用的比特数，主流量化方案在 8 到 4 比特之间，1.71 比特相当于把一部精装百科全书誊进一张便签。压缩后的模型文件只有 56.56 GiB，装进 64GB 内存仍有余量，项目方公布的数据显示 256K 上下文满载时峰值内存为 57.61 GiB。

敢压得这么狠，前提是模型的 MoE 架构。MoE 即混合专家模型，像一个 284.33B 人规模的顾问团，每次提问只有 13.17B 位对口的专家上场，其余人待命，真正需要搬运的数据天生就少。项目还叠加了两项加速手段。SwiGLU-H2 量化对模型中的 SwiGLU 计算层单独设计编码，守住最敏感部分的精度。Stockfish-PVS L3 投机解码则安排一个小型草稿模型先猜出后续若干个词，大模型只做批量核对，好比实习生起草、总监批红，比总监逐字亲写快得多。

v2.4.0 版本把这套思路延伸到了 30B 级 MoE 模型上，量化位宽 3.75 bpw，开发者自报解码速度达到每秒 25 到 111.6 个 token，已经摸到日常对话流畅度的边缘。仓库还配了技术论文、架构文档和可提交成绩的社区基准排行榜，Apple Silicon、Fedora、Windows 都在支持列表里，许可证为 Apache 2.0。

边界同样清楚。上述性能全部来自开发者自报，尚无独立复测。1.71 bpw 属于激进量化，压得越狠，模型出错的概率越高，评论区对这笔交换是否划算存有实实在在的分歧。这个项目更适合被看作本地推理可行性的极限演示，普通读者照抄配置之前，需要想清楚自己愿意用什么去换这份速度。

🔥 为什么今天值得看：AI 编码 agent 最贵的失败不是写不出代码，而是基于错误假设写出一堆能跑的代码，拖到 pull request 阶段才被人看出来。EGM 把审查关口前移到设计文档，而且评审者全是零上下文的金鱼子代理，不会被长会话里的先入之见带偏。这套流程不绑定任何模型，能派生子代理的宿主都能装。项目自述数千名谷歌工程师在用，说明这种规范先行的做法在大厂内部有真实需求，个人开发者也可以直接借鉴这套流程。

谷歌工程师近期开源了一套编码工作流插件 Elephant-Goldfish Model（EGM），中文名大象金鱼模型。它不是新的大模型，而是 Apache 2.0 许可的插件层，模型能力由宿主 agent 自带，插件本身不含任何权重。

它的核心想法很朴素。让 AI 直接写代码，错误假设往往一路混进 pull request 才被发现。EGM 把顺序倒过来，先让持有完整项目上下文的长会话「大象」起草设计文档，再派出一批不带任何对话历史的「金鱼」子代理，在写代码前用五个阶段独立评审这份规范，把错误拦在 Markdown 文件里。项目还提供 /egm-drift-report 命令，建议每周运行一次，检查代码与规范是否漂移。

插件包含 7 个技能、9 个评审 persona 和 6 个头脑风暴透镜，支持 Antigravity、Claude Code、Codex 等宿主。README 特别声明它不是官方支持的谷歌产品，据项目自述已有数千名谷歌工程师在使用。

英伟达董事会 11 月 8 日（周日）宣布，针对 CEO 黄仁勋与 Alice Huang 的关系启动独立调查，由独立董事联合外部法律顾问执行，TechCrunch 与 The Verge 均作了报道。Alice Huang 是新加坡芯片公司 Megaspeed 前高管。据今年早些时候在美国决策者中流传的一份备忘录声称，她被中国国家安全部招募，任务是监视英伟达 CEO。该说法未经证实，是此次调查要核实的核心疑点。

公司同步公开了黄仁勋发给全员的内部备忘录。他承认对妻子不忠并道歉，写道："我对妻子不忠，我的行为伤害了她和我们的孩子。我的所作所为没有任何借口，我深感抱歉。"备忘录未点名对方，据 TechCrunch 核实即 Alice Huang。

董事会在声明中表示"没有理由相信"国家安全或公司机密已受损害，称黄仁勋"完全支持审查并承诺配合"，董事会对他和领导团队"抱有信心"。此前英伟达曾回应，两人互动"并不罕见"。调查仍在进行，结论以官方披露为准。
