Grok Bot 摸到你的手机：六类原生应用逐项授权开放

这是什么：10 月 22 日（周四）下午 3:14（太平洋时间），Grok Bot 官方 @bot 账号宣布 Bot 可使用手机内置的日历、提醒事项、联系人等应用，iOS 与 Android 正在分批推送；权限截图显示共六类应用，每项独立 Allow，逐应用授权。
🔥 为什么今天值得看：Grok Bot 是在自有云端计算机上执行任务的代理，此前只能通过邮件、X 等连接账号工作；这次拿到的是手机本地数据与系统应用的直接操作入口（日程、通讯录、信息、智能家居），叠加本周的 Action Button 与 Android 默认助手能力，「按键—口令—自动执行」的闭环首次在手机端成形。逐应用 Allow 把触及范围的选择权交回用户，但云端代理读取私信与通讯录的隐私边界，官方尚未给出说明。

10 月 22 日（周四）下午 3:14（太平洋时间），Grok Bot 官方 @bot 账号宣布：Bot 现在可以使用手机上的日历、提醒事项、联系人等内置应用，更新正在 iOS 与 Android 双平台推送。对这款此前主要隔着连接账号干活的 AI 代理来说，这是它第一次拿到手机本地数据的直接入口。

六类应用，逐项授权

公告附带的权限截图列出了六类应用，每一项旁边都有独立的 Allow 按钮：

  • 信息：读取和发送消息
  • 位置：查找附近地点
  • 日历：查看当天日程、添加事件
  • 家庭：控制灯光和门锁
  • 提醒事项：设置和查看提醒
  • 联系人：查找和添加联系人

授权以应用为单位逐项进行，用户自己决定 Bot 能触及手机的哪一部分。官方没有说明这份清单是否在两个平台上全部可用，也没有说明需要哪个版本才能看到新选项。

从连接账号到本地数据

这一步的分量要从架构看。Grok Bot 不是只回答问题的聊天机器人，而是在自己的云端计算机上执行任务的代理。在此之前，它主要通过邮件、X 这类连接账号工作；拿到手机应用权限之后，它能直接操作用户真正存放在手机里的东西——日程表和通讯录。

一周三步，两周不停

这是 Grok Bot 本周在手机端的第三步：本周一，它上线 iPhone Action Button，按一下即可发起语音对话；次日，官方演示了它处理 X 私信、并作为 Android 默认助手运行。叠加本次更新，「按键—口令—自动完成」的闭环成形：按一下按钮，让 Bot 挪个会议或加条提醒，剩下的无需打开任何应用。另据二手报道，10 月 16 日前后的更新已让计算机任务提速约三倍、其他查询响应时间减半；再算上此前已报道的路由能力与 1Password 接入，这条产品线的密集更新已持续两周。

车机端早有先例。上个月，特斯拉让车内 Grok 访问邮件、日历和文件，Model Y 与 Cybercab 上也能经由 Grok 使用 Grok Bot。手机端开放日历与联系人之后，同一个助手可以从口袋延续到驾驶座。

保留的疑问

需要说明：目前信息来自垂直媒体对官方帖文的二手报道，官方未披露任何技术实现细节；功能仍在分批推送，双平台差异与应用版本要求均无说明。按下 Allow 之前，这些问题都值得等一等答案。

33B 开源模型对标 Qwen：agentic 编程拉回单张显卡

这是什么：BOSS直聘旗下的 Nanbeige 团队本周在 Hugging Face 发布 33B 参数开源模型 Nanbeige4.3-33B：Apache 2.0 许可证、512K token 上下文、原生支持 XML/JSON 工具调用。官方模型卡自报口径下，8 项 agentic 编程评测中 7 项超过 Qwen3.8-27B。
🔥 为什么今天值得看：在 H100 一年期租赁价五个月上涨近 40%（SemiAnalysis 口径）的当口，一个 4-bit 量化后可跑单张 24GB 消费级/准专业显卡的强 agentic 模型，让「买卡自托管」对「按小时租算力/调 API」的经济账开始变化；Apache 2.0 无商业使用上限，进一步降低团队自建编码 agent 的门槛。
展开正文

BOSS直聘旗下的 Nanbeige 团队本周在 Hugging Face 发布 330 亿参数开源模型 Nanbeige4.3-33B：Apache 2.0 许可证、512K token 上下文窗口，开箱支持 XML 和 JSON 两种工具调用格式。官方将其定位为「旗舰教师模型」，后续将蒸馏出更小、更便宜的版本——今年早些时候它已用同样路线发布过 3B 参数系列。

基准：7/8 领先，但并非全胜。 需要先写明口径：以下数字来自官方 Hugging Face 模型卡的自报数据，不是第三方验证。在 33B 量级的 8 项 agentic 编程评测中，Nanbeige4.3-33B 有 7 项超过 Qwen3.8-27B：DeepSWE 65.5 对 42.5，Terminal-Bench 2.1 80.9 对 73.0，Automation Bench 54.2 对 38.3，JobBench 44.8 对 34.5。对比集为同量级的 Qwen3.8-27B、Gemma4-31B 和 Muse-Glimmer-30B。

同一张表里也有输的一面：SWE-Bench Pro 60.3 输给 Qwen 的 61.7；GPQA Diamond 89.5 落后 Gemma4-31B 的 91.3；AIME 2026 95.2 对 94.5，基本打平。合理的读法是：多步任务执行、终端操作这类 agentic 编程能力是它的强项，通用推理只是「有竞争力」。

为什么时机重要。 据 SemiAnalysis，H100 一年期租赁价从 2025 年 10 月的约 1.70 美元/GPU 小时涨到 2026 年 3 月的 2.35 美元，五个月上涨近 40%；英伟达 CFO Colette Kress 5 月也表示 H100 租金年内已涨 20%。当「按小时租算力」的账越算越贵，一个 4-bit 量化后能塞进单张 24GB 消费级或准专业显卡的强模型，正在改变自托管与租用 API 之间的算术——代价是模型较大的 KV cache 会限制这类硬件上实际可用的上下文长度。

更大的背景是开源阵营的整体逼近：原文援引 Epoch AI 的 Capabilities Index（基于含 FrontierMath、SWE-Bench Verified 在内的 39 项基准），DeepSeek、Qwen、Kimi 与美国前沿的差距，已从 2023 年 MMLU 上 17.5 分的水平持续收窄，按其口径约合七个月。

Apache 2.0 还意味着没有商业使用限制——不少开放权重发布附带与营收或用户量挂钩的使用上限，这个没有。对在「租 API」与「自建内部编码 agent」之间做权衡的团队，卖点很直接：宽松许可、agentic 基准表现，以及买得起的硬件。

社区端，发布帖在 r/LocalLLaMA 快速爬过 140 分——按原文的说法，这种快速的自发热度，往往能把真正的开放权重竞争者与无人问津的「模型倾倒」区分开。当然，Qwen、Gemma 以及 DeepSeek、Kimi 的下一版几乎必然回敬，开源竞速远未到定局的时候。

自主科研系统 SplatLab：16 篇无人改码研究手稿

这是什么：UCSD 的 Seemandhar Jain 与 Manmohan Chandraker 于 10 月 21 日在 arXiv 公开 SplatLab（arXiv:2610.30468，10 月 23 日提交 HuggingFace Papers，标注 NeurIPS 2026）：一个面向 3DGS 的端到端自主科研系统，从读论文、复现、提扩展、写代码到产出研究手稿全程无人工改码，共生成 16 篇手稿，最高 +3.78 dB PSNR 提升来自此前无任何 3DGS 方法的天体摄影星云渲染。
🔥 为什么今天值得看：以往自主科研系统多停留在读论文、提假设、写代码片段的阶段，且从未在活跃的计算机视觉子领域被端到端验证。SplatLab 把「复现—扩展—实验—写手稿」整条链路跑通，并用八岛屿 Elo 锦标赛、常设证伪者、数字强制绑定训练日志三套机制对抗自我欺骗，为「AI 能否做真实验而不只是编故事」提供了第一个领域内的大规模实证样本。
展开正文

10 月 21 日，UC San Diego 的 Seemandhar Jain 与 Manmohan Chandraker 在 arXiv 公开论文（arXiv:2610.30468），两天后提交至 HuggingFace Papers，提交者标注其为 NeurIPS 2026 工作。论文提出的 SplatLab 是一个面向 3D Gaussian Splatting（3DGS，三维高斯泼溅）的自主科研系统：从读论文、复现基线、提出改进、实现代码、跑 GPU 实验、做消融，到写出完整研究手稿，全程不需要人工修改代码。截至发稿，论文页获 8 个 upvote。

这件事的起点是一个具体痛点：在 3DGS 这样高活跃度的计算机视觉子领域，复现一篇已发表论文通常要花掉数周专家级工程，之后才谈得上提出扩展。作者指出，此前的自主科研系统也能读论文、起草假设、写代码，但普遍受限于固定模板短、代码可执行性低、结果不可追溯，且从未在一个活跃的计算机视觉子领域里被端到端验证。SplatLab 的用法很宽：给定一个研究提示词、一篇目标论文的 URL，甚至零输入，它会自动复现已发表基线、提出扩展，在 Mip-NeRF 360 与 LLFF 两个标准数据集上训练并消融，最后写出研究手稿——并且每个报告数字都绑定到一条真实的训练日志。

系统的五项设计里，两项最值得展开。其一是跨八个「岛屿」的级联加权 Elo 锦标赛：候选方法不是各自跑分排队，而是以实测 GPU PSNR 互相对抗排名，并辅以口头梯度反馈；其二是常设的「证伪者」，候选方法在压力测试中失败即被扣减 Elo 分，把「能否扛住证伪」直接写进选择压力。可信度约束同样硬：每个报告数字必须绑定训练日志，只要还有声明没有实验支撑，运行就不允许终止。此外，候选方案从经过验证的复现骨干上以插件形式变异而来，而非从零写起；一套七分类的 3DGS 分类法把 EVOLVE-BLOCK 标记包装进领域对齐的脚手架，可跨 3DGS 代码库迁移。

结果可以量化：在以 PSNR 为目标的运行中，SplatLab 产出的手稿超过其复现目标 +0.18 至 +3.78 dB；最高的 +3.78 dB 来自天体摄影星云渲染——一个此前没有任何 3DGS 方法涉足的场景。作者在社区帖中给出的总量是 16 篇端到端研究手稿、单次自主运行 24–48 小时；论文摘要的表述是，研究周期从「研究生数月」压缩为「数天以自主计算为主」。代码、全部手稿、实验账本与跨运行论文库均已开源。需要注明：以上数字均为论文自报口径，暂无第三方复现。

边界也要说清：这一切仅在 3DGS 一个领域内得到验证。3DGS 论文密度高、基准明确、单次实验成本可控，几乎是自主科研最容易落地的赛道。SplatLab 展示的是端到端自主科研在一个具体子领域的首次大规模实证，而不是通用「AI 科学家」已经就位的信号——锦标赛与证伪者机制能否迁移到实验更贵、评价更模糊的领域，仍是开放问题。

Interconnects 播客第 20 期（10 月 25 日发布）请来刚搬去旧金山的评测专家 Florian，聊了上线三天的 Kimi K3.1 Pro。以下均为播客的观点性评估，但账算得很细。

评测账。 K3.1 Pro 在 Artificial Analysis 榜单上排到前三、四名，headline 成绩超过 GPT-6 Astra，与两个最新的 Claude 5.5 和 Muse Wonder Full 同处最前列；但在 Terminal-Bench Science 上落后 GPT-6 Astra 约 20 分，ProgramBench 等成绩也明显参差。两人的解读是：AA 采用的基准时间视野较短，而 ProgramBench 这类长视野任务要求模型自己探索，K3.1 Pro 的 RL 后训练更偏「利用」已知解法而非「探索」，「可能有一点 RL 过度优化」。

部署账。 三万亿参数要良好服务，需要 B300、每个模型副本独占一个节点（播客推测是 NVL72 级机架的投入），远比能跑在 H200 上的小模型昂贵；命名从 K3 改为 K3.1 Pro，被解读为后续会有 Flash 风格的小模型。开放权重仍按官方承诺在 11 月 4 日前放出（此前有两周独家访问期，本报 10-24 头条已报，不再展开）。

安全账。 PHP 一个存在多年的远程代码执行高危漏洞，由 OpenAI「Patch the Planet」项目联合安全研究者发现，报告 PHP Foundation 后协调各方一次性修复，大量 PHP 网站（WordPress 生态是重灾区）一度主动下线打补丁；目前多方报告显示，预期中的大规模利用并未发生。同一周，LLM 网关库 LiteLLM 再次被入侵，初步报告归因于一个在 GitHub 上暴露了五个月的 API key 被利用来传播恶意软件。播客观点认为：网络安全生态的动态并未质变，只是被 AI 整体加速；Kimi 在博客中自述通过调整中期训练数据刻意压低开放权重的攻击性网络能力、保留防御侧能力，是对「开放模型等于末日」叙事的聪明应对——网络安全从业者认为完整渗透一个组织需要长视野能力，这方面封闭模型（如 GPT-5.6 Sol）仍明显更强。

多智能体系统跑起来像一间没有监控的后厨：出了问题不知道是哪一步出的错，agent 调工具留下的副作用更难撤销。最近经 Hacker News 首次曝光的开源项目 Jukebox-OS，想给这类系统装上「黑匣子」——一个面向多智能体系统的确定性运行时，Rust 核心搭配 Python SDK，以 Apache 2.0 协议开源，作者为 Marius Carlsson。

项目的主打能力有三块：一是确定性飞行记录器，完整记录多智能体系统的执行过程，并支持时间旅行式回放调试——出了 bug 可以「倒带」到任意时刻重看一遍；二是写时复制（Copy-on-Write）ACID 工具沙箱，把工具调用的副作用包进事务里隔离管理，可提交也可回滚；三是 MCP ACID Proxy，一个兼容 MCP 协议的代理层，现有 MCP 工具链可以直接接入。项目还提供 在线 Neon Web Inspector 实时演示，不用 clone 代码就能看运行效果。

这正好对准了 agent 调试的两个老大难：故障不可复现、副作用难隔离。不过要说明的是，这是一个非常早期的项目：HN 帖子热度仅 10 分，暂无版本迭代与生产采用案例，概念价值目前大于工程成熟度，离生产环境还有相当距离。

这是什么：Winnin 工程师 ericholiveira 在 Show HN 首发 Farol（葡萄牙语「灯塔」），HN 58 points，仓库仅 9 个 commits，属全新首发。它定位在 AI 代码审查完成之后：为 PR 的人工审批者生成风险地图，标注哪些改动风险更高、该从哪些文件读起，让低风险 PR 快速放行、高风险文件逐行精读。
🔥 为什么今天值得看：AI 写码与 AI 审查普及后，人工审批成了流水线上新的瓶颈：注意力平均分给每个 PR，审查就退化成浏览。Farol 把「按风险分配审查注意力」工程化，与 Claude Code 团队「由改动决定审查层级，而非作者」的原则同频。相比模型打分的概率性输出，基于编译器的确定性静态分析可复现、可举证（每条结论附调用链），这是它在 AI 审查工具堆里最清晰的差异点。
展开正文

Winnin 工程师 ericholiveira 开源的 Farol（葡萄牙语「灯塔」）日前在 Hacker News 的 Show HN 首发即获 58 points，仓库仅 9 个 commits，是全新项目的首次亮相。它的定位很克制：不替代 AI 代码审查，而是补在「AI 审完之后」——代码由 agent 写、由 agent 审，最后点头合并的仍然是人，而人的审批注意力是稀缺资源，平均摊在每个 PR 上就成了走马观花。

Farol 给审批人的是一张风险地图：这次改动会触达哪些页面、API 操作、RPC 方法和脚本（附完整调用链），合并风险集中在哪些文件，diff 覆盖缺口与契约破坏在哪里。它刻意不用模型猜测，而是以真实编译器（TypeScript 类型检查器、go/types、Python ast）做静态分析构建声明图，同一个 PR 每次得到同一份报告；结论分 fast track / quick review / careful review 三档并附 0-100 风险评分，看不懂的部分明确标记 unknown 并要求仔细审查，而不是糊弄一个「安全」。

使用上是双形态：本地一条命令 npx @winninjs/farol，或在每个 PR 上跑 GitHub Action winnin/farol/action。MIT 协议，无账号、无托管服务，在本机或 CI 运行，从不执行用户代码、也从不外发代码。环境要求 Node.js 22+，Python 项目另需 3.11+。支持的栈按 README 所列：TypeScript/React 覆盖 React Router、Next.js（Pages 与 App Router）、TanStack Router 与 GraphQL/REST 后端；Go 覆盖 chi/gin/echo 与 net/http 路由、gRPC 服务方法；Python 覆盖 FastAPI/Flask/Django/Celery。仓库还附了基于 FastAPI 全栈模板真实 PR 的交互式在线 demo。

TARSphere：把仿真、大脑和基准打包的具身全栈框架

这是什么：论文 TARSphere 提出面向机器人的全栈具身框架，一次打包三个组件：TARSphere-Infra（物理仿真器中运行机器人策略，配具身 NPC 与受限对话，事件驱动 FSM 判定任务状态）、TARSphere-Harness（冻结多模态大模型作决策大脑，经多级可执行技能、分层记忆与执行反馈行动）、TARSphere-Bench（30 个室内场景、360 个回合、5 组对照条件的长时程基准）。对 8 个 MLLM 的横评显示通用模型可超越具身专用模型，任务更新与人机交互仍是难点。
🔥 为什么今天值得看：它补的是评测缺口：现有具身系统多面向固定目标、或把执行抽象成符号动作，难以在物理与社会双重约束不断变化的世界里评估长时程 agent。这套框架把「环境会变、人会插话」变成可复现的考场，并把执行安全（碰撞、跌倒）提为与任务成功率并重的评价维度。对选型者也有直接提示——在该基准口径下，通用 MLLM 可以打过具身专用模型；但结论限于这套基准，不应泛化到全部具身场景。
展开正文

具身智能的评测大多止步于「给定目标、按符号动作打分」：任务一变、人一插话，就很难衡量 agent 在演化世界里的真实水平。新论文 TARSphere（arXiv 2610.30043，见 HuggingFace Papers）把这件事拆成三层打包解决——仿真基础设施、决策大脑、评测基准。

三个组件分工明确。TARSphere-Infra 在物理仿真器里运行机器人策略，场内有具身 NPC 与受限对话（可理解为会说话、能被询问的仿真人）；一套事件驱动的有限状态机根据已完成动作和已传递信息更新任务状态、判定结果。TARSphere-Harness 是「大脑壳」：一个冻结的多模态大语言模型（MLLM，权重不微调、原样当决策器用）通过多级可执行技能行动，靠观测、分层记忆和执行反馈修正决策。在其之上，agent-in-the-loop 的构建流程对齐任务语义、因果依赖与场景几何，产出 TARSphere-Bench：30 个室内场景、360 个回合，5 组对照条件分别考察感知鲁棒性、干扰适应、任务更新、人机协调与意图理解，任务覆盖 navigate-and-report（导航并汇报）与 fetch-and-deliver（取物送达）两类。

最值得记的是 8 个 MLLM 横评的两个结论：其一，通用模型可以超越具身专用模型；其二，任务中途更新与人机交互仍是普遍短板。另一个信号是安全——评测中出现频繁的碰撞与跌倒，作者据此主张：即便各模型共享同一动作接口与决策预算，执行安全也必须与任务成功率一并评估。当然，这些结论的口径限于该基准的 30 个室内场景与两类任务，不必外推到全部具身场景。
