微软推出.NET Skills v1.0，AI编码代理获官方.NET技能插件

这是什么：微软 .NET 团队正式发布了 dotnet/skills 仓库，这是一套为 AI 编码代理（如 Copilot CLI、Claude Code、VS Code、Cursor 等）提供的 .NET 和 C# 技能插件集。2026年4月21日发布首个正式版本 v1.0.0，此后在5月22日和24日更新，新增 .NET 11 技能插件、VS Code 预览支持以及 Cursor 市场集成。
🔥 为什么今天值得看：这套官方技能插件让 AI 编码代理能更高效地处理 .NET 相关的编码、调试、测试、迁移、包管理、ASP.NET Core、MAUI、AI/ML 等任务。此前开发者需要手动编写提示词或依赖第三方工具，现在微软直接提供了标准化、持续更新的“技能库”，大幅降低了 AI 辅助 .NET 开发的门槛，尤其对团队协作和大型项目迁移有实际意义。

微软 .NET 团队最近推出了一组名叫“dotnet/skills”的官方技能插件，专门给 AI 编码代理（比如 GitHub Copilot CLI、Claude Code、VS Code 里的智能助手、Cursor 等）用的。简单说，以后你让这些 AI 帮手写 .NET 或 C# 代码时，它们能更懂 .NET 的内部机制——从调试、测试、包管理到迁移老项目，甚至支持 .NET 11 的新特性。

这个仓库在 4 月 21 日发布了第一个正式版本 v1.0.0，最近又更新了好几波（5 月 22 日和 24 日），加入了 .NET 11 技能插件、VS Code 的预览支持，还集成了 Cursor 市场。这意味着开发者不用再自己琢磨怎么让 AI 理解 .NET 生态——微软直接塞了一套标准化“工具箱”。对整天和 .NET 打交道的团队来说，这能省下不少调教 AI 的时间。

不过社区里也有声音提到，dotnet/skills 目前还处在 beta 阶段，文档和社区采纳度都不算高。相比微软自家的 Semantic Kernel 或第三方的 LangChain .NET，这套技能插件更专精但更窄。能不能成为 AI 编码代理的“标配”，还得看后续更新和开发者用不用得顺手。
