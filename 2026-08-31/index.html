先建身份再上网关，企业 agent 安全的六道依赖门

这是什么：VentureBeat 客座文章提出“依赖门控部署”框架，主张 agent 安全控制有严格的施工顺序：网关应是第五道控制而非第一道，前面必须先建好代理清单、独立身份与委派上下文、短时效凭证和可归因遥测。文中引用 2026 年 6 月 CISA 将 LiteLLM 网关漏洞列入 KEV 目录、Teleport 2026 调研（过度授权组织事件率 76% vs 最小权限 17%）作为实证。
🔥 为什么今天值得看：agent 进入生产期后，最常见的失败模式是先上执行层、后补上下文。凭证有效、API 调用合规，但动作违背了委派目的，网关对此无能为力。六道依赖门把安全建设变成可检验的依赖链，每道门都有明确的“运营证明”标准，企业可以据此自查当前卡在哪一环，而不必推翻现有 IAM。
展开正文

企业把 agent 推进生产环境时，几乎都从同一个动作开始：先架一个运行时网关。VentureBeat 一篇来自企业 AI 平台与安全方向首席工程师 Nik Kale 的客座文章指出，这恰恰是最容易出问题的起点。网关是团队最先伸手去拿的控制，却是他们最没准备好运营的那个，因为它依赖的身份与归因层大多根本不存在。

风险不是假设。2026 年 6 月，CISA 在攻击者被发现在野外利用后，将一个 LiteLLM 漏洞列入已知被利用漏洞（KEV）目录：该漏洞通过网关本身在主机上执行命令，与第二个漏洞串联后甚至无需凭证。而这只是那款 AI 网关在一个月内披露的七个 CVE 之一。企业最先伸手去加固的这一层，本身就是高危资产。

文章给出的核心论断很直接，网关控制不应是第一道控制，而应是第五道。作者提出依赖门控部署框架，上游退出测试不满足，下游控制就不能算运营完成。六道门依次为下面这些。

  1. 代理清单与责任归属。每个生产 agent 都有具名负责人、用途、批准工具和生命周期状态；跳过这步，事故响应的第一小时就会耗在“搞清楚到底是谁的东西”上。
  2. 独立 agent 身份加委派上下文。agent 不能藏在开发者 token 或共享服务账号里，控制面必须能回答“是哪个 agent 在行动、替谁、执行什么任务”。
  3. 任务范围与短时效凭证。被攻陷的 agent 触不到与任务无关的资源，用现有 IAM 的工作负载身份、token 交换、时限授权即可落地。
  4. 可归因遥测。一个已完成的任务能从发起到下游影响完整重建，这是作者审阅的部署中最常被漏掉的一道门。
  5. 运行时动作执行。策略判断纳入 agent、委托人、任务、动作四重上下文，而不只看 token 是否有效；最严的控制应放在支付、访问策略变更、删除、生产变更、数据导出这类不可逆边界上。
  6. 行为基线与跨系统击杀路径。真正的遏制不止是禁用一个目录对象，而是禁用身份、吊销活跃与派生凭证、阻断工具调用、终止任务、隔离工作负载。

贯穿其中的是一条单调委派原则：每次责任转移只能保持或削减权限，绝不能增加。对账 agent 能看一本账，不等于该继承员工的全部系统权限。

这套顺序有数据支撑。Teleport 2026 年对 205 位安全负责人的调研显示，访问范围比行业、成熟度或自信程度更能预测 AI 事件。过度授权的 AI 组织事件率高达 76%，而实施最小权限的组织只有 17%。Okta 2026 年调研则显示，只有 34% 的高管表示组织始终对 agentic 员工施加与人类员工同等的安全标准，这个缺口没法靠把链条最后一环的控制挪到最前面来补上。

好消息是不必推翻现有 IAM。从与现有工作负载身份挂钩的权威注册表起步，逐步扩展 agent 与任务标识符、引入短时效凭证、把标识写进工具调用日志即可。作者给了一个 30 天行动计划：先从 10 个生产 agent 建清单（记录负责人、用途、批准工具、凭证来源），再测试归因能力（IAM 和日志能否把每个 agent 与委托它的人类区分开），最后完整重建一个已完成的 agent 任务链路。链条在哪里断，你的部署就在哪里欠账。

成熟度模型描述的是终点，而依赖链给出的是不打坏生产环境的施工顺序。

让 Claude Code 总结一个网站就中招的完整攻击链

这是什么：安全研究员 wunderwuzzi 演示了针对 Claude Code（Opus 5 Auto Mode）的完整提示注入攻击链：一句“总结这个网站”即可诱导模型下载恶意 ZIP、通过投毒的 struct.py 执行远程代码，甚至启动嵌套无头 Claude Code 代理进行侦察，三个变体各测五次，成功率 60% 到 80%。
🔥 为什么今天值得看：Auto Mode 自 2026 年 8 月中旬起是默认设置，攻击的每一步单独看都像正常操作，415 错误换工具、自写解码器、导入标准库，分类器难以拦截。它证明 agent 的安全边界不能建立在模型行为判断上，而必须落在沙箱隔离与网络出口控制这些系统层手段。
展开正文

安全研究员 Johann Rehberger（网名 wunderwuzzi）发布了一项针对 Claude Code 的提示注入攻击演示：只需让运行 Opus 5、Auto Mode 的编码代理“总结一个网站”，就能诱导它执行攻击者控制的代码，测试成功率在 60% 到 80% 之间。而 Auto Mode 恰恰是 Anthropic 自 2026 年 8 月中旬起默认开启的设置，这意味着大量用户在不知情的情况下暴露在同类风险中。

攻击链的每一步都设计得相当克制。用户请求总结一个伪装成笔记本档案的恶意网站，Claude 先用自带的 WebFetch 工具抓取，网站故意返回 415 Unsupported Media Type 错误。模型于是“自作主张”换用 Bash 工具里的 curl 直接访问。攻击者全程没有明说要用 curl，只是让错误信息替自己说了话。curl 请求被 303 重定向到一个恶意 ZIP，Claude 顺手下载解压，里面有目录元数据、README、七个 Base85/zlib 编码的 JSON 记录、一个 macOS 解码器二进制文件，以及一个被投毒的 Python 文件 struct.py。

接下来是最具讽刺意味的一环：按照安全护栏，Claude 拒绝运行来路不明的解码器二进制，反而决定自己写一个解码器。Rehberger 评价道：“讽刺的是，这个安全决策本身就是利用路径。”新写的解码器会导入 Python 标准库模块 base64，而 base64 又会导入 struct 模块。这里用到了模块遮蔽，当本地目录里有一个和 Python 标准库同名的文件时，Python 会优先加载本地那份。于是恶意 struct.py 抢在官方模块之前被执行。为了让这段恶意代码通过 Claude 的安全审查，Rehberger 还用 ChatGPT 对其做了混淆。

恶意代码启动后会下载并执行远程载荷，演示中弹出了 Calculator（真实攻击者显然会做更恶劣的事）。更值得警惕的变体是：struct.py 通过 claude -p 再启动一个无头的嵌套 Claude Code 代理。提示注入不仅能执行代码，还能凭空造出一个拥有自己工具权限和上下文的新 agent。在演示中，这个子代理执行了 whoami、uname、id 等基础侦察命令，并向用户主目录写入文件。

Rehberger 测试了三个变体、各五次，成功率 60% 到 80%。他坦言样本量小，“但对一个有动机的攻击来说，这些结果具有代表性”。他的关键建议是把这类编码代理放进沙箱里运行。Anthropic 未回应 The Register 的置评请求，但据称在回复 Rehberger 的安全报告时表示模型行为符合设计。Rehberger 转述称，Auto Mode 是一个由尽力而为的分类器支撑的便利功能，并非安全保证，分类器本就不针对由多个看似无害步骤组成的坚定注入链，真正的边界在于操作系统级隔离和网络出口控制。

Rehberger 的结论一句话可以概括：“不要信任模型输出。”这和业界喊了多年的口号并无二致，但这一次，它有了一条可复现、带成功率的完整攻击链作为注脚。

GitHub 上一个 60.5k star 的项目 /last30days 正在做一件方向不同的事。传统搜索给的是 SEO 相关性，它要的是社交相关性，README 里明确主张用社交相关性取代 SEO 相关性。Reddit 的赞数、X 的点赞、YouTube 的字幕与互动、Polymarket 真金白银下注的赔率，这些信号每天由数百万用户用注意力和钱包投出来，项目拿它们给内容打分排序，再让 AI agent 裁判合成一份「过去 30 天」的主题简报。

Google 开源 EnvHarness，让静态基准自己进化

这是什么：Google Cloud AI Research 联合华盛顿大学圣路易斯分校与 UNC 教堂山分校发布 EnvHarness：一个 Apache-2.0 开源的可编程包装层，通过标准 reset()/step() 接口把静态 agent 基准改造成随训练策略自适应的环境，配套 LLM 设计器 EnvRigger 自动编写包装组件，论文 arXiv 2608.19880。
🔥 为什么今天值得看：静态环境一旦被解决就失去教学价值，而生成新环境的流水线领域专用、不可迁移，LLM 写的验证器又不可信。EnvHarness 只改初始状态、动作约束和观测，模拟器与人工验证器原封不动，让一套实现跨领域通用，且环境能针对策略当前弱点持续出题。
展开正文

Agent 的训练环境有个尴尬的宿命，一旦被策略解决，就不再有教学价值。无论里面跑的是多弱的模型还是已经变强的模型，环境的行为一模一样，它不会针对策略的弱点出题，也不会随训练进度加码。Google Cloud AI Research 联合华盛顿大学圣路易斯分校与 UNC 教堂山分校的做法是给冻结的旧环境套一层可编程的包装，并不生成新环境。这就是开源（Apache-2.0）的 EnvHarness。

所有干预都严格通过标准的 reset()/step() 接口进行，这是框架的关键约束。底层模拟器、任务定义、人工编写的验证器一概不动，重塑后的任务依然由可信的人工验证器打分，避开了 LLM 生成验证器需要过度生成再大量过滤、且永远不能完全信任的老问题。也正因为不碰任何基准专属代码，一套实现就能覆盖所有领域。

框架自带三个可自由组合的组件。Stage 在 reset() 后重放一段固定的动作序列，把回合的初始状态改到别处，比如把目标马克杯藏进关着的抽屉，逼 agent 去搜索而不是直接伸手拿。Contract 在动作、状态转移和观测三个轴上安装逐步钩子，可以封禁某个动作、改写响应、截断观测。Chain 则在共享步数预算下把第二个环境编进同一回合，最终判定取两个验证器的逻辑与。

组件本身与策略无关，难的是选对组件。EnvRigger 把策略当黑盒，跑一个四阶段循环，先观察 5 条基线 rollout，诊断出系统性缺陷，然后写出真正的 Python 组件，再在 5 条新 rollout 上验证，不可解和过于容易的候选都会被拒，每个任务最多 5 轮修订。生成的钩子在隔离子进程中编译，坏变异只会留下一条记录的报错轨迹，不会让训练跑挂。

在 ALFWorld、WebArena、SWE-bench Verified、OfficeQA、SpreadsheetBench 五个基准上，用重塑环境挖掘的技能在未见过的 held-out 任务上全面胜过对照组。ALFWorld 平均分从 62.4 升到 68.3，分布外部分最高 +9.0 分。SWE-bench Verified 解决率从 49.88 升到 52.58，同时平均步数从 55.01 降到 49.61，即论文所说的 9.8% 效率提升。更值得注意的是反例，在 SpreadsheetBench 和 WebArena 上，从原环境挖出的技能甚至低于不用技能的基线，说明环境重塑本身就是挖掘是否有价值的前提。对比领域专用的生成器，EnvHarness 比 SWE-smith 高 2.46 分且少用 5.11 步。

强化学习侧同样成立。在 Qwen3-8B-base 上用 GRPO 训练，重塑环境在四项指标中三项优于原环境（ALFWorld 分布内 81.4→87.9），OOD 有小幅回落（89.6→88.8）。环境扩展到 300 个时达到 54.79，高于原环境的 52.13 和纯生成环境的 50.37，因为设计器在随当前策略共同进化每一批环境。控制成功率到 [0.4, 0.6] 区间的任务覆盖率从 6% 拉到 80%，说明它可以按需调节难度。

边界与代价也很清楚。硬性前提是环境可重置，真实用户账户和物理机器人被排除在外；成本主要是设计器的 token 消耗。代码已随六个环境的复现驱动程序开源，论文编号 arXiv 2608.19880。如果你已经在跑 agent 评测循环，接入只需实现一个接口，下游零改动。

CritICL，把小模型错题本喂给大模型

这是什么：CritICL 是一个推理时框架，把同系列小模型的失败模式当作批判式上下文示例来指导大模型推理，用弱到强泛化的思路替代重复生成和外部验证，大幅降低生成次数与 token 成本。
🔥 为什么今天值得看：小模型的失败模式在这里成了大模型的错题本，是一种可复用的资产。对推理时优化来说，这意味着不必总靠烧算力堆性能，结构化的失败知识本身就是一种便宜的指导信号。
展开正文

推理时优化通常靠反复生成或外部验证器来换性能，代价是算力和 token。8 月 27 日发布在 arXiv 的论文（2608.27455）提出 CritICL，走了一条更省的路。它的依据是同一个模型家族里，失败模式在不同规模间呈现结构化模式，小模型栽过的坑，大模型往往也会栽。研究者把这些失败模式整理成基于批判的上下文示例，在推理时喂给大模型，让它提前避开同类错误。实验显示，CritICL 稳定优于标准上下文学习，性能媲美甚至超越测试时缩放方法，而生成次数和 token 成本显著更低。代码已在 GitHub 开源。
