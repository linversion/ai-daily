Chrome DevTools MCP 大更新：AI 代理可实时操控浏览器调试

这是什么：Chrome 开发团队对 Chrome DevTools MCP 服务器进行了重大更新，使 AI 编码代理（如 Claude、Cursor、Copilot 等）能够直接控制并检查实时 Chrome 浏览器，进行调试、性能分析和自动化测试。该项目已有 880 多次提交和 41.4k Star，并非全新发布，但本次更新整合了性能洞察、高级调试和可靠自动化功能，并新增了 CLI 模式和 slim 模式，以及详细的客户端配置文档。
🔥 为什么今天值得看：此前，AI 编码代理在生成代码后无法实际测试或调试，开发者需要手动操作浏览器验证结果。Chrome DevTools MCP 打破了这一瓶颈，实现了从代码生成到浏览器调试的闭环自动化，显著提升了 AI 辅助开发的效率和可靠性。对于前端开发者、AI 工具用户以及希望用 AI 全流程完成网页测试的团队来说，这是一项实用且影响深远的进展。

Chrome 开发团队今天发布了 Chrome DevTools MCP 服务器的重大更新，让 Claude、Cursor 等 AI 编码代理能够直接控制并检查实时 Chrome 浏览器。这意味着 AI 不再只是生成代码，还能真正打开浏览器、查看页面、调试脚本、分析性能，甚至自动修复 Bug。

过去，AI 编码代理最大的短板就是无法实际操作浏览器——它们写出来的代码是否正确、页面渲染有没有问题、性能瓶颈在哪，都需要开发者手动测试。Chrome DevTools MCP 通过 Model Context Protocol（MCP）把浏览器的全部调试能力开放给 AI，相当于给 AI 配了一双“真实浏览器的眼睛和手”。这次更新更是把性能洞察、高级调试和可靠自动化整合进来，还新增了 CLI 模式和 slim 模式，方便在终端或轻量环境中使用。

项目上线以来已有 880 多次提交和 41.4k Star，积累了大量用户。不过官方明确标注为“beta”阶段，MCP 协议本身也还在演化，开发者部署时需要留意安全边界——毕竟让 AI 直接控制浏览器，如果权限没管好，可能带来意想不到的风险。社区里对这次更新的讨论相当热烈，不少人认为这是“前端开发 AI 化的关键一步”，同时也呼吁加强权限控制和审计日志。

微软发布 .NET 技能插件 v1.0，AI 代理可自动处理 .NET 11 新任务

🔥 为什么今天值得看：此前 AI 编码代理对 .NET 开发的支持较为通用，缺乏针对 .NET 特有任务（如平台迁移、版本升级、框架配置）的深度优化。dotnet/skills 填补了这项空白，让开发者通过插件形式直接让代理执行 .NET 操作，显著降低使用门槛。新增的 .NET 11 技能能帮助开发者快速适配新版本特性，提高开发效率。同时，该仓库遵循 agentskills.io 开放标准，有望推动更多 AI 代理生态与 .NET 的结合。

微软 .NET 团队最近对 dotnet/skills 仓库做了一次重要更新：在 2026 年 4 月 21 日推出首个正式版本 v1.0.0 的基础上，5 月 22 日又加入了 .NET 11 技能插件、VS Code 预览支持和 Cursor 市场集成。这个仓库到底做什么的？简单说，它是一套给 AI 编码代理（比如 GitHub Copilot CLI、Claude Code、VS Code、Cursor）准备的“专业技能包”，专门用来处理 .NET 和 C# 开发的常见任务——从写代码、调试、测试，到项目迁移、包管理，甚至 ASP.NET Core 和 MAUI 框架的配置，都在覆盖范围内。

过去 AI 编码代理对 .NET 的支持很泛，遇到 .NET 特有的项目文件结构、命令行工具或者版本迁移就不太灵光。现在有了这套技能插件，开发者不用再手写一堆复杂的提示词，直接让代理调用这些预装好的技能就行。比如你要把项目从 .NET 8 升级到 .NET 11，代理可以自动执行迁移步骤。这次更新的 .NET 11 技能尤其及时，能帮开发者快速适配新版本特性，节约大量手动操作的时间。

不过需要留个心眼：这个仓库目前还处于 beta 阶段，社区采用度不高，官方文档也不算特别详尽。市面上已经有 Semantic Kernel、LangChain .NET 这类工具也提供 .NET 相关的 AI 能力，但 dotnet/skills 更轻量，不需要引入额外框架就能直接挂到现有 AI 代理上用。目前 GitHub 上的讨论还不算热闹，有些开发者担忧后续维护节奏和兼容性——毕竟 AI 代理本身迭代很快，插件能否跟上是个问号。
