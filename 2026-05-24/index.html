一个名为“Anthropic-Cybersecurity-Skills”的开源项目近日迎来显著更新，它将754个结构化网络安全技能打包成AI代理可直接调用的决策知识库。这些技能不仅覆盖了云安全、威胁狩猎、恶意软件分析等26个领域，还精确映射到MITRE ATT&CK、NIST CSF 2.0等五个行业主流框架，并遵循开放的agentskills.io标准——这意味着像Claude Code、GitHub Copilot这样的AI代理能“读懂”安全分析流程，直接执行专家级任务。

这项工作的核心价值在于填补了一个空白：过去的网络安全知识库要么是文本文档，要么是人类专家才能操作的表格，AI代理很难直接理解和使用。而该项目将安全专家的判断逻辑（比如“检测到异常流量后，下一步应该检查哪些日志”）转化为机器可读的结构化技能，每个技能都对应具体的攻击路径和防御措施。这样一来，即使是缺乏安全经验的团队，也能让AI代理按规范流程进行初步威胁分析。

不过，该项目并非全新发布——早在5月的日报中就已报道过初始版本，本次更新主要增加了更多技能的映射范围和对云安全领域的覆盖。但有声音指出，它本质上可能是对MITRE ATT&CK、NIST等公开框架的简单聚合，缺乏原创性贡献。而且框架本身也在不断进化（如MITRE ATT&CK每年更新多次），仓库若不持续维护很快会过时。此外，采用agentskills.io这一相对小众的开放标准，是否会被主流生态接受仍是未知数。社区在肯定的同时，也期待项目方能展示更多独到的安全逻辑，而非仅仅是框架的“转述”。

.NET 技能插件正式版发布，AI 编码代理现在能处理 .NET 11 项目

这是什么：微软 .NET 团队维护的 dotnet/skills 仓库于 2026 年 4 月 21 日发布首个正式版本 v1.0.0，并在 5 月 22-24 日更新中新增对 .NET 11 技能插件的支持、VS Code 预览功能以及 Cursor 市场集成。这是一套让 AI 编码代理（如 Copilot CLI、Claude Code、VS Code、Cursor）能更好处理 .NET 和 C# 编码、调试、测试、迁移等任务的技能插件集合。
🔥 为什么今天值得看：过去 AI 编码代理对 .NET 生态的支持不够精细，特别在处理企业级项目迁移、版本兼容和框架特定操作时容易出错。dotnet/skills 以结构化技能插件的形式提供专业知识和最佳实践，使代理能更准确地完成从创建项目到调试迁移的全流程。v1.0 正式版加上 .NET 11 的提前适配，表明微软正将 AI 代理内化为 .NET 开发的核心工具，降低开发者使用 AI 助手的门槛。

微软 .NET 团队维护的 dotnet/skills 仓库在近期迎来重要更新，于 2026 年 4 月 21 日发布了首个正式版本 v1.0.0，随后持续迭代。最近一次推送（5 月 24 日）和 README 更新（5 月 22 日）新增了对 .NET 11 技能插件的支持、VS Code 预览功能以及与 Cursor 市场的集成。

这套技能插件专门面向 AI 编码代理（如 GitHub Copilot CLI、Claude Code、VS Code 和 Cursor 内置代理），让它们能够更专业地处理 .NET 和 C# 相关的编码、调试、测试、迁移、包管理，以及 ASP.NET Core、MAUI、AI/ML 等任务。过去 AI 代理虽然能生成代码，但针对特定框架和语言特性的理解往往不够精准，尤其是在企业级 .NET 生态中，涉及版本兼容、项目迁移、调试技巧等复杂操作。dotnet/skills 相当于给 AI 代理装上了一套“专用工具箱”，不仅提供更准确的 API 调用建议，还能指导代理完成从创建新项目到调试旧代码的完整流程。此次 v1.0 正式版的发布加上对 .NET 11 的提前适配，意味着微软正加速将 AI 代理变成 .NET 开发者的高效助手。VS Code 预览支持和 Cursor 市场集成进一步降低了使用门槛——开发者可以直接在熟悉的编辑器里通过 AI 伴侣调用这些技能。

AI 编码代理的技能插件（skills）类似一个可插拔的知识模块，告诉代理如何处理特定任务。不同于通用提示，技能插件包含结构化的指令、代码示例和最佳实践。dotnet/skills 遵循 agentskills.io 开放标准，理论上也能被其他代理框架使用。目前该仓库仍处于 beta 阶段，但 v1.0 版本标志着初步成熟。社区讨论中，一方面开发者对微软官方提供此类技能插件表示欢迎，认为能显著提升 .NET 项目的 AI 辅助效率；另一方面，有用户指出替代方案（如 Semantic Kernel、LangChain .NET 和 GitHub Copilot Extensions）已经存在，dotnet/skills 需要在易用性和覆盖面上证明自身优势。反方观点认为，通用代理加上良好提示也能达到类似效果，技能插件的实际价值尚待验证。
