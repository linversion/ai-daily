Dr. Claw 开源，给编码代理套上可控可审计研究流程

这是什么：研究团队发表论文并开源了 Dr. Claw，一个研究工作区。它给 Claude Code、Gemini CLI 这类命令行编码代理套上一层可控、可审计的研究流程，论文编号 arXiv 2609.00365。团队在分子生成、蛋白质设计、材料科学三类任务上测试，成功率与基线自主代理相当或更高。代码以 Apache 2.0 协议开源。
🔥 为什么今天值得看：编码代理能干活，开放式研究却要求过程可查、决策留痕，把使用切碎在聊天工具和终端里的老办法给不了这两样。Dr. Claw 把控制做进流程，任务执行器限定并记录每条命令的输出，技能库让跑通的做法沉淀复用，编排层把规划、执行、写作拆成三种模式，人工监督每一步都在。代理做出的研究结果因此更容易被别人复查，跑通的命令序列也能留给下一次任务。
展开正文

一篇挂在 arXiv（编号 2609.00365）并同步到 HuggingFace Papers 的论文公布了 Dr. Claw，一个面向科研场景的开源工作区。它针对的痛点很具体。Claude Code、Gemini CLI 这类命令行编码代理已经能读写文件、执行 shell 命令、维持很长的会话，可一旦接手开放式研究任务，过程就脆弱且看不清。研究被切碎在聊天工具、IDE、终端和写作软件之间，让研究可被审计的那些决策记录很少被保留下来。

Dr. Claw 的作者刻意绕开再造一个自主 agent 的路线，把力气花在流程上，给现成的编码代理套上一层可控、可审计的外壳。外壳里有三个核心抽象。任务执行器负责运行命令，输出被限定在固定范围内，标准输出和错误输出都会捕获留档。技能库把跑通的命令序列记下来，变成可复用的积木，之后的运行可以直接搬用。人机协同编排层提供规划、执行、写作三种模式，研究者在三种模式间切换，每一步都留有人工监督的位置。

评估覆盖分子生成、蛋白质设计、材料科学三类任务。Dr. Claw 的成功率与基线自主代理相当或更高，同时人工监督每一步都在。技能库还带来跨运行的累积学习，一次跑通的做法可以沉淀给后续的研究。代码和演示以 Apache 2.0 协议开源，仓库为 GitHub 上的 OpenLAIR/dr-claw。

对正把编码代理引进日常工作的团队，这篇论文点出了短板。代理能干活这一步已经跨过去了，流程还没跟上，谁限定它的动作、谁记录它的决策。Dr. Claw 把这两个问题做进了工具里，顺着这条路，代理的产出才容易被人复查和复用。

面壁开源 MiniCPM5-2B，训练数据和中间检查点全部公开

这是什么：面壁智能的 OpenBMB 社区开源了 MiniCPM5-2B，一个 25.2 亿参数的稠密语言模型，原生上下文 131,072 token，权重按 Apache 2.0 协议放出，用 llama.cpp、Ollama 等本地工具就能加载，面向手机和笔记本这类端侧场景。它在官方模型卡的 34 项基准里平均拿 53.9 分，比表中成绩最好的对比模型 Qwen3.5-4B（参数更大，列在参考组）的 51.1 还高。这次连完整训练数据和训练中途的检查点也一起公开。
🔥 为什么今天值得看：2B 档位的竞争过去主要拼榜单名次，榜单数字怎么来的，外人很难核对。MiniCPM5-2B 把预训练数据、SFT 和 RL 数据、三个中间检查点全部放出，RL 加蒸馏让推理基准平均涨 10.96 分这类官方自测数字，第三方可以逐阶段复核，小模型的发布从贴成绩单变成了可验证的过程。对开发者，标准 Llama 架构省掉了适配自定义内核的工程量，接入 vLLM、Ollama 等引擎的门槛降到很低；对开放权重生态，这是一次拿透明度换信任的做法，工具调用和代码能力下放到 2B 体格，也让本地设备跑智能体这件事更近了一步。
展开正文

面壁智能的 OpenBMB 社区发布了 MiniCPM5-2B，这是 MiniCPM5 系列的第二个检查点，前一个是 MiniCPM5-1B。模型总参数 2,516,756,480，其中嵌入层之外有 1,981,982,720，共 42 层，注意力部分用 16 个查询头配 2 个 KV 头，原生上下文窗口 131,072 token。架构是标准 LlamaForCausalLM，主流推理引擎不需要写自定义内核，也不需要改模型代码，vLLM、SGLang、llama.cpp、Ollama、LM Studio、MLX 都能直接加载，权重按 Apache 2.0 协议放出。

官方模型卡测了 34 项基准，平均 53.9。同尺寸组的对手是 LFM2.5-2.6B、Qwen3.5-2B 和 Gemma-4-E2B-it，表里另外把 Qwen3.5-4B、granite-4.2-3B、LFM2.5-8B-A1B 等列为参考组。表中成绩最好的基线是参考组的 Qwen3.5-4B，平均 51.1，同尺寸组的 LFM2.5-2.6B 只有 33.2。分项看，工具调用拉开了最大差距，τ²-Bench Telecom 拿 97.1，BFCL v4 拿 66.6，τ³-Bench Banking 是 20.8 对 6.8。代码方向 LiveCodeBench v6 拿 69.1 对 56.4，SWE-bench Verified 拿 46.4 对 33.6。长上下文的成绩有涨有跌，NoLiMa 68.1 对 43.5 领先明显，AA-LCR 59.0 对 61.0、LongBench v2 43.7 对 47.3 都落在后面。通识方向最能看出体格差距，MMLU-Pro 70.8 对 78.0，Humanity's Last Exam 8.9 对 9.9，原文还提到 GPQA-Diamond 和 MATH-500 两项也落后于更大的模型。基准表把来自 Artificial Analysis 的成绩和 OpenBMB 自行复现的成绩分开标注，来源没有混在一起。

训练配方分三段走。基础训练先过稳定和衰减两个阶段，中间训练把模型对准目标数据分布，后训练的起点是 400B token 的深度思考 SFT，随后用基于评判器的 JustRL II 算法训练数学、代码、智能体、写作四个方向的 RL 教师。最后一步是在线策略蒸馏，把 16 个 RL 专家模型（其中 5 个做智能体）合并成一个最终发布的模型，蒸馏时在每个响应位置上用学生和教师在全词表上的反向 KL 散度当优势估计，蒸馏数据直接复用 RL 阶段的提示词，没有另建语料。按 OpenBMB 自己的测量，RL 加蒸馏这段让推理和通识基准平均涨 10.96 分，智能体类基准涨 6.96 分。

这次发布分量最重的部分在权重之外。Ultra-FineWeb、UltraX 和 UltraData 系列的预训练、SFT、RL 数据集全部放出，其中智能体 SFT 数据含约 50 万条样本，RL 数据超过 8 万条；Base、Midtrain、SFT-only 三组中间检查点也一并公开，每个训练阶段的贡献可以拿数据直接验证。多数小模型发布给到的是最终权重和一份模型卡，训练数据和中间存档很少跟着一起出。数据和检查点都在手上，RL 加蒸馏涨分的官方说法就不再只能照单全收，第三方可以逐阶段复核，这对想学训练方法的小团队和想确认成色的使用者都是实打实的材料。

Uber 烧光全年 AI 编码预算，企业开始给 token 支出算账

这是什么：VentureBeat 9 月 7 日刊出一篇长文，给企业 AI 支出的毛病起了名字，tokenmaxxing，指 token 消耗猛涨却拿不出对等回报。核心案例是 Uber，去年 12 月给工程师配发编码代理 Claude Code 并按用量给团队排名，今年 4 月烧完 2026 全年 AI 编码预算，随后给每个智能编码工具设了每人每月 1500 美元上限。Microsoft 一个部门取消了 Claude Code 授权，Duolingo 撤回了把 AI 使用纳入绩效考核的计划。
🔥 为什么今天值得看：Gartner 预计今年 AI agent 软件支出接近 2070 亿美元，较 2025 年的 864 亿美元增长超过 139%。token 按用量计费，同一个工程师同一天的不同任务能开出大不相同的账单，传统软件预算的财务模型套不上。文章记录的转向很具体，企业从推动员工使用 AI，转向要求用量能对上更多上线功能或修掉的 bug。Databricks、AWS Bedrock、Azure AI Foundry 等厂商已推出按任务复杂度分流的自动路由，谁能耗得起、谁花得值，开始取决于治理和计量能力。
展开正文

2025 年 12 月，Uber 给工程师配发了编码代理 Claude Code，还搭起一块内部排行榜，按 token 消耗给各团队排出名次。到今年 4 月，2026 全年的 AI 编码预算已经花光。比超支更让人意外的，是总裁兼 COO Andrew Macdonald 的表态，用量冲上去了，他却说暂时看不到这轮消耗和为乘客司机做出更好的产品之间有什么关联。Uber 随后给每个智能编码工具设了每人每月 1500 美元的上限。

Uber 的风波给一个更普遍的问题起了名字，tokenmaxxing，token 消耗猛涨，对等的回报却拿不出来。Gartner 预计今年 AI agent 软件支出接近 2070 亿美元，比 2025 年的 864 亿美元增长超过 139%。这笔钱很难套进 CFO 们熟悉的软件成本模型，token 按用量计费，同一个工程师用同一个工具，上午做代码补全和跑一堆并行代理做数据库迁移，开出的账单会大不相同。收紧的还有 Microsoft，它在质疑过 Claude Code 的授权成本后，在 Experiences and Devices 部门取消了授权；Duolingo 把 AI 使用纳入绩效考核的计划也在员工反弹后撤回。

问题出在哪里，受访高管分成两派。Agiloft 负责 AI 运营的副总裁 Noe Ramos 把矛头对准默认配置，多数企业把选模型的权力交给正在敲提示词的员工，前沿模型在干便宜的开权重模型就能干好的活。Promova 工程负责人 Dmytro Palaniichuk 的观察更具体，团队企业版默认勾选高价模型、默认高推理强度，Opus 会话自动升到 100 万 token 的上下文窗口，没人去改这些设置，几个月内高价模型连查邮件的活都在接。Promova 现在朝 Opus、Sonnet、Haiku 按 40/50/10 分配用量的方向调整，他同时承认卡点在习惯，员工不清楚什么任务该配什么模型，再合理的默认值也会被旧习惯磨掉。

治理的打法开始分化。SUSE 负责技术与产品的总经理 Rick Spencer 对 VentureBeat 说：“如果有人用 16000 美元的 token 帮我们省下 10 万美元，我们当然要鼓励这种用法。” SUSE 把 AI 用途分成日常开发、自主代理、一次性战略攻坚三类，让管理者按类别辅导，公司眼下没有自动路由层，相关代理还在路线图上。Agiloft 干脆废除了用量上限，理由是 74% 的员工从来没碰到过旧上限，转而把便宜模型设为默认，在基础设施层做路由和缓存。Everlaw 也给每个人设 token 上限，工程师触顶后给工具团队发一封邮件，通常当天就能拿到翻倍的额度，上限在这里只起提醒作用。

Everlaw 还是文中唯一拿出硬回报数字的公司。一个核心 Java 基础设施项目消耗 3500 美元 token，工期从 9.5 个工程师月压到 2.5 个；另一个未发布产品已经花掉 2.7 万美元 token、预计到 4 万美元，工程师投入从 90 到 100 人月的估算降到 19。翻车的例子也有，团队花数千美元让代理把界面代码从 Dojo 迁到 React，产出全部作废，现在的做法是先让代理写清旧系统的行为再动工。平台侧也在跟进，Databricks 今年 6 月在 Data + AI Summit 上把 Smart Routing 带进 Unity AI Gateway，按提示意图、改动范围这类信号给每个请求挑模型，运行时决策保持透明，撞到预算上限时由管理员选硬停或者降级到更便宜的合规模型，Merge、AWS Bedrock、Azure AI Foundry 也提供类似的自动路由。

省了多少钱，几乎没人答得上来。Promova 拿不出改动前后的成本对比，遥测只能显示 Opus 的百万 token 会话约占月支出的三分之一；SUSE 手里是轶事级证据，一个项目的依赖漏洞从数百个 CVE 降到零，代理自 5 月以来在 VEX 数据库分类了近 1 万个 CVE。Databricks 的早期数据显示，把样板代码生成、小修补这类日常任务转给便宜模型后，解决率没有出现可测的下降。Everlaw CTO Max Christoff 的判断是，未来一到两年 token 支出会被当成类似人力或者生产成本的科目来规划，部门负责人做年度预算时会同时对人员编制和 token 用量表态。

Uber 在文中仍是被点名的极端个案，各家高管对从哪下手也各执一词，Ramos 会先重建路由层，Spencer 主张从培训管理者起步；Christoff 和 Palaniichuk 把顺序放得更靠前，一个要先想清楚公司到底在优化什么，一个要先盯自己团队的遥测数据。这些分歧说明，企业 AI 支出这本账，行业才刚开始学着算。

MCP 最大改版被指新增三个攻击面，安全责任落到端点

这是什么：AI 应用连接外部工具的开放协议 MCP 在 7 月 28 日完成发布以来最大的一次改版，当天四个 Tier 1 SDK 全部跟进，Cloudflare 首日就绪，Sentry 和 Linear 已在用，新版已经跑在生产环境里。9 月 7 日 VentureBeat 刊出一篇工程分析，指改版把安全执行从协议层挪到使用者的端点，并归纳出三个新攻击面。文章给出的是风险分析，没有报告已发生的入侵。
🔥 为什么今天值得看：旧协议靠握手建立会话，安全检查可以挂在会话上做一次，新版把会话删掉，每个请求独立，检查只能逐请求重做，责任全落在使用者的网关和端点。状态改由字符串句柄传递，提示注入读到句柄就等于拿到有效凭证。界面渲染进 AI 客户端后，存储型 XSS 这类老牌网页漏洞跟着进入代理生态。这些活动都发生在网络防护视野之外，而协议体量巨大，Tier 1 SDK 每月下载接近 5 亿次，4 月底扫描发现 12520 个默认免认证的 MCP 服务暴露公网，影响面摆在那里。
展开正文

7 月 28 日，AI 应用连接外部工具的开放协议 MCP 完成发布以来最大的一次改版。当天四个 Tier 1 SDK 全部说上新版本，Cloudflare 的 Agents SDK 首日就绪，Sentry 和 Linear 等客户随即启用，这套新协议已经跑在生产环境里。改版带来无状态核心、原生 OAuth 授权和 MCP Apps 服务端渲染界面，配套新的 12 个月弃用政策，旧机制移除不早于 2027 年年中。

VentureBeat 9 月 7 日刊出首席工程师 Nik Kale 的分析，他过去两年一直在用 MCP 搭建连接企业工具的代理系统。他的判断是，这次改版同时重新划定了安全责任落在谁头上。协议删掉了标记会话的 Mcp-Session-Id 请求头和初始化握手流程，协议版本与客户端信息改为随每个请求内联携带，任何服务器实例都能处理任何请求。会话失去控制单元的地位之后，原先挂在会话层的安全检查没了挂靠点，必须逐个请求重新执行，落点从协议层挪到使用者自己的网关和端点。

结合安全公司 Backslash 与 Akamai 对新攻击面的标注和微软的工具投毒研究，文章归纳出三个新攻击面。第一个是 MCP Apps 的存储型 XSS，也就是把恶意脚本藏进服务器内容、别人查看时执行的老牌网页漏洞。服务器送出的网页界面在 AI 客户端的沙箱框架里渲染，攻击者把恶意 HTML 或 JavaScript 藏进某个 MCP 工具的内容，代理或另一个用户打开时脚本就会执行，沙箱限制了完全接管，但客户端脚下就是源代码、终端、文件系统和其它相连的 MCP 服务器。第二个是状态句柄劫持。会话状态改由一串字符串句柄显式传递，句柄只是对话里的一个字符串，能在对话里塞进或读到这串字符的人就握有一个有效凭证，埋在 Jira 工单或工具返回里的提示注入载荷可以不碰服务器就让句柄易手。提示注入指在数据里夹带指令诱骗 AI 照做。第三个是端点执行间隙。状态从传输层挪进应用层，威胁从网络可见性结束的边界外开始，网络层工具照不到。文中给出的是攻击面分析，没有报告已经得手的入侵。

应对按风险排序。先盘点哪些 MCP 服务器能向客户端或开发环境渲染 HTML，像审第三方脚本一样审这些界面。再把执行挪到请求级，采用 OAuth 2.1 加 PKCE、逐客户端同意、严格回调地址匹配和受众绑定令牌，为某一台服务器签发的令牌不能拿到另一台重放，身份感知网关挡在每台服务器前面，没有有效令牌的调用一律拒绝。句柄按不可信输入处理，校验出示者就是领用人，并在工具输出和检索文档里清理带指令色彩的内容，埋进去的句柄正是从这里到达。接下来给宿主进程、本地 MCP 服务器和客户端渲染建端点可见性，迁移后的服务器要用真实模型驱动真实代理回路来测，单元测试发现不了这类失效，重点盯跨实例泄漏的状态、跨作用域复用的句柄和意外的界面内容。roots、sampling、logging 和旧 HTTP+SSE 传输已进入弃用倒计时，12 个月的钟从 7 月 28 日开始走。

维护者做了一个有意识的选择，协议不替你执行安全，这件事由使用者在端点上承担。对企业级代理来说，跑在普通基础设施上的无状态协议是合理取舍，作者也认可这一点。账单的量级摆在那里，Tier 1 SDK 每月下载量接近 5 亿次，TypeScript 与 Python SDK 累计各破 10 亿，4 月底 Censys 扫描发现 12520 个 MCP 服务暴露公网且默认免认证，5 月 NSA 的 AI 安全中心专门发过指引，提醒协议普及速度超过了它安全模型的成熟速度。只当迁移来做的团队，会把有状态时代的防护原样带进新协议，那套防护对不上现在的威胁面。

前沿模型修代码普遍过度编辑,保留指令减26.6%新增复杂度

这是什么：一篇新论文研究了 AI 修代码时的过度编辑问题,也就是模型修 bug 时把代码改得超出必要范围。研究团队用 400 道 BigCodeBench 编程题搭建评估框架,往正确解答里注入受控的抽象语法树级损坏,让每个修复任务都有已知的最小补丁,再精确测量模型多改了多少。结果显示过度编辑在包括 GPT-5.5 在内的前沿模型中普遍存在。在提示里加一条保留原有代码的指令后,平均多余编辑距离从 0.195 降到 0.131,新增认知复杂度降 26.6%,Pass@1 反而升了 2.3 个百分点。
🔥 为什么今天值得看：对每天用 AI 改代码的人,测试通过只说明功能对了,改动越大,人要审查的内容越多,代码也离原来的实现越远。这篇论文把这种审查负担变成了可度量的指标,还给出两层解法,在提示里加一条保留指令就能明显缓解,训练层面强化学习比监督微调更能守住编辑保真度。编码代理批量进入生产环境,产出需要人审,这个判断现在有了量化证据。
展开正文

让 AI 修一个 bug,它把测试跑绿,顺手重写了半个文件,这种体验如今有了量化研究。一篇题为 When Models Edit Too Much 的论文把这类行为称作过度编辑,指模型在修复时把代码改到超出必要范围。论文的判断很直接,修得对和改得干净是代码修复的两个独立维度,只盯正确性,人审代码的成本就藏在了分数外面。

研究团队用 400 道 BigCodeBench 编程题搭起评估框架。他们对每道题的正确解答注入受控损坏,损坏发生在抽象语法树层面,也就是代码结构的树状表示上,相当于在健康代码里埋一个位置已知的病灶。这样每个修复任务都有一个已知的最小补丁,模型交卷后,多改的部分可以被精确量出来。量法有两种,多余 Levenshtein 编辑距离衡量改动超出的体量,新增认知复杂度衡量代码读起来费劲程度的涨幅。

结果对前沿模型不客气。过度编辑在各家前沿模型中普遍存在,GPT-5.5 这样的强模型也在其中。衡量一次通过测试比率的 Pass@1 可以很高,同时改动臃肿,两者并不冲突,人审这些改动的时间被无谓拉长。

最实用的发现在提示层面。在给模型的指令里加一条要求保留原有实现的说明,过度编辑明显收敛,平均多余 Levenshtein 编辑距离从 0.195 降到 0.131,新增认知复杂度减少 26.6%,Pass@1 还提升 2.3 个百分点。改得更克制,正确率同步上涨。论文同时发现,这些收益靠加大推理预算或换更大的模型换不来。

训练层面的比较给出更深的结论。监督微调,拿现成范例教模型照着做,会过拟合到见过的损坏模式,损坏换个写法就露馅。强化学习,让模型在试错中按奖励信号调整,在没见过的任务上拿到了编辑保真度与性能保持的最佳平衡。

论文最后把编辑保真度定位为代码修复质量的一个独立维度,可度量,可学习。对每天用 AI 改代码的人,这篇研究把一笔隐性账摆上台面,测试分覆盖不到的审查负担,如今有了单位,也有了一条加在提示里就能用的缓解手段。

9 月 7 日，Axis Robotics 联合 UC Berkeley、Georgia Tech、NTU 等机构发布机器人操作数据引擎 AXIS。机器人操控数据集的增长速度一直远远落后于模型本身，采集流程封闭且集中在实验室，专业操作员在硬件上录好演示、离线处理、发布一个固定基准，之后数据就不再生长。AXIS 把演示采集搬进网页浏览器，开销大的渲染和训练交给后端 GPU，数据集随社区贡献持续扩张。本次公开的快照包含 207 个任务、50,129 条经过验证的 Franka 轨迹、超过 60K 个任务或场景变体，覆盖 7 个场景类别，论文致谢了 7 万余名做出贡献的社区成员。 采集端的门槛被压到一台能开网页的设备。贡献者在 MuJoCo WebAssembly 前端用键盘、鼠标、虚拟摇杆或游戏手柄，遥操作一台带平行夹爪的 Franka Research 3 机械臂，物理步进和 Three.js 渲染跑在界面线程之外，记录下的状态和动作与模拟器保持对齐。渲染由 8x RTX 4090 完成，训练和评估由 8x A100 承担。任务由 TaskGen 从一条语言指令自动生成，布局监督器校验场景，物体摆放不合格就重摆或重新生成，每个任务附带结构化成功判定器，由后端复核，避免只信前端回报的成功标志。 数据清洗被当成生产线上的正式环节。关节变化低于 5e-3 的样本按静止剔除，窗口 15、阶数 3 的 Savitzky-Golay 滤波平滑连续动作，三次样条把网页端 6 到 8 Hz 的采样重采样到 20 Hz。论文的表格如实给出代价，平均加速度从 1.3539 降到 0.4885，平均急动度从 11.5899 降到 2.2243，重放成功率从 100% 降到 86.2%。清洗后的片段在 IsaacSim 里关闭物理步进重放，场景、相机、材质和光照围绕已验证轨迹随机化，输出 256×256 的光线追踪 RGB 图像。 训练对照给出了数据价值的关键证据。所有条件都从已发布的 π0.5 检查点出发，这个开源 VLA 基座的主干是 PaliGemma 的 Gemma-2B，动作专家为 Gemma-300M。全参数持续预训练 100,000 步，再用相同超参数在 LIBERO 上微调 30,000 步。LIBERO-Plus 总分上，π0.5 加 AXIS 全量数据达到 88.8，原始 π0.5 为 83.9，轨迹条数完全对齐的 RoboCasa365 对照组只有 57.5，单纯的数据量解释不了 31.3 分的差距。报道原文提醒，摘要里的 5.8% 和 37.3% 是按 83.9 基线归一化的相对值，4.9 和 31.3 的点差更适合直接比较。规模效应在总体上成立，25%、50%、100% 三档快照分别拿到 84.7、85.7、88.8。分轴看，Sensor Noise 和 Camera 增益最大，为 13.7 和 11.3，Light 和 Language 倒退 1.7 和 1.3，Camera 在半量数据时一度跌到 68.8，低于 72.5 的基线，全量时才恢复。 开放程度上，2.36 TB 的数据集在 Hugging Face 门控开放，仅限非商业学术用途，训练代码以 OpenPI 补丁层的形式开源，遥操作平台在浏览器里直接可用，策略检查点没有发布。

Trail of Bits 开源了 Coop，一个用 Rust 写的命令行工具，给 Claude Code 和 Codex 这类 AI 编程代理开一台用完即扔的虚拟机。在项目目录里输入 coop up 起虚拟机，再输入 coop claude 或 coop codex，对应的代理就在虚拟机里跑起来。代理在机器内拥有 Docker、git、编译器、包管理器的完整权限，环境被改乱也不影响主机，销毁重建的代价很低。平台方面，Linux 上走 Firecracker 加 KVM，macOS 上依赖 Lima，官方测试覆盖 Apple Silicon 的 macOS 和 x86_64 的 Linux。项目以 Apache-2.0 许可证开源，GitHub 仓库已积累 317 个提交、127 个 star，这是它第一次登上 Hacker News，拿到 49 分。

谷歌 9 月 3 日发布的论文 MaxKernel 把多智能体系统用到了 TPU 内核开发上。TPU 是谷歌自研的 AI 加速芯片，内核是贴着硬件执行计算的最底层代码，这类代码写得越好芯片跑得越快，过去要靠资深工程师凭硬件知识反复手调。MaxKernel 提供三种范式，人在回路模式让工程师和智能体逐步协作设计，全自主模式按性能指标和执行轨迹自动跑优化循环，图搜索模式扩展到整个设计空间做全局探索，三者共用一组负责规划、实现、自我调试、测试和硬件性能剖析的子智能体。团队在包含 50 个任务的 JaxBench 套件上评测，又叠加先进开源模型的真实负载，论文摘要写明生成的实现持续高度优化，性能追平专家手调基线。代码开源在 GitHub 的 AI-Hypercomputer/accelerator-agents 仓库。

浅层建索引深层再回答，流式视频延迟最高降 52.1 倍

这是什么：9 月 8 日 HuggingFace 论文页上出现一篇流式视频理解研究，提出名为 ShallowStream 的框架，目的是让多模态大模型看实时视频流时少烧算力。它让模型浅层网络边看边建一个常驻的轻量检索索引，用户提问时完整模型再按索引找出相关画面作答。论文称单帧预填充延迟最高降 52.1 倍，10 秒端到端延迟最高降 11.9 倍，代码开源在 GitHub。
🔥 为什么今天值得看：流式视频理解的痛点在算力账。画面一帧接一帧到来，模型每帧都要完整处理一遍，时间越长开销越大，监控预警、车载视觉这类全天候运行的应用部署成本因此降不下来。延迟降一到两个数量级后，同样的算力可能支撑更多路视频流，长时间挂机场景的账更容易算平。这篇论文还把优化变量引到模型深度上，给此前集中在 token 剪枝、量化等方向的研究添了一个新抓手。

让多模态大模型连续看视频流，算力开销并不小。每来一帧新画面，现有做法都要让模型在全部网络层上做一遍预填充，KV 缓存随视频时长一路膨胀，自动驾驶、工业监控、可穿戴助手这类需要一直盯着画面的应用最耗不起这份算力。此前省算力的方案多集中在视觉 token 剪枝、量化、按需取帧等方向。HuggingFace 论文页近日出现的 ShallowStream 框架，把优化视角转到了模型深度上。它让模型靠前的浅层网络在视频流过时同时完成帧编码和检索索引构建，维护一个常驻的轻量索引；用户提问时，完整深度的模型再依据索引挑出相关画面组织答案。论文报告的结果是，在性能与最强现有流式方法持平的前提下，单帧预填充延迟最高降至原先的 52.1 分之一，10 秒端到端延迟最高降 11.9 倍，两个数字均为最好情况下的上限。代码已在 GitHub 开源。
