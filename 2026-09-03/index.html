谷歌六周三更 Flash 模型，Gemini 3.8 同价升级并首拆网络安全专用版

这是什么：谷歌发布 Gemini 3.8 Flash 和网络安全专用的 Gemini 3.8 Flash Cyber，这是 Flash 系列六周内第三次更新，距 3.7 Flash 发布只有三周。3.8 Flash 主打推理与编码，价格与 3.7 持平；Cyber 版专注漏洞发现与自动修补，只通过新的 Fairwind 计划向可信防御者开放。
🔥 为什么今天值得看：这次发布把两条线拧在一起。一条是速度，六周三更说明轻量模型进入高频迭代节奏，涨准确率靠更多推理步骤和更多工具调用，token 账单可能变长，开发者需要用 effort 档位自己权衡。另一条是安全能力的产品化，前沿级漏洞挖掘和补丁能力以专用变体加准入机制的方式分发，只有通过申请的政府、关键基础设施运营方和软件维护者能拿到，普通版本则内置滥用防护。谷歌自己的 Chrome 安全团队已经用它把正确补丁数量做到更大商业模型的 2.6 倍，云漏洞研究团队不到 2 小时就找到一个通常需要数月才能发现的关键漏洞。

这次发布今天在 Hacker News 上同时挂着两个讨论帖，其中一帖拿到 792 分。谷歌在官方博客宣布 Gemini 3.8 Flash 和 Gemini 3.8 Flash Cyber 两个模型，前者是新的主力推理与编码模型，后者专攻漏洞发现和自动修补。这是 Flash 系列六周内第三次更新，距上一代 3.7 Flash 发布只隔了三周。

3.8 Flash 的卖点是同价涨能力。在衡量长程软件工程的 DeepSWE v1.1 基准上，它跑赢多数更大的前沿模型，成本只是零头；HLE-Verified 多步推理基准拿到 54.9%。定价跟 3.7 Flash 持平，每百万输入 token 0.75 美元、输出 3.75 美元，优惠价 2026 年 12 月 31 日截止，2027 年 1 月 1 日起调整为 1.5 美元和 7.5 美元。token 是模型读写文字的计量单位，也是按量计费的单位。能力提升的来源很直接，模型在复杂任务上多走推理步骤、反复调用工具，用 token 换准确率。怕账单变长的开发者可以调低 effort 档位，或者继续用仍在支持列表里的 3.7 Flash。

真正的新东西是 Flash Cyber。它在漏洞发现基准 CyberGym 上达到前沿水平，超过上一代 3.5 Flash Cyber 和更大的前沿模型；在覆盖 20 种编程语言的内部基准上，找漏洞成功率超过 70%。修补能力用 Collinear 运营的 CWE-Bench 衡量，第一次尝试通过率（pass@1）47.2%，对照的领先前沿模型是 47.8%，价格低得多。这个版本不走公开渠道，只通过新的 Fairwind 计划向政府、关键基础设施运营方和软件维护者等可信防御者开放。谷歌称开发重心放在漏洞修补上，攻击利用类能力被排在后面，普通版 3.8 Flash 则内置针对化学、生物、放射、核与网络攻击的滥用防护。

谷歌内部已经用它干活。Chrome 安全团队的实测显示，3.8 Flash Cyber 给 Chrome 漏洞写出的正确补丁数量是大得多的商业模型的 2.6 倍；Wiz 的内部渗透测试基准上召回率高出 7.5 到 9.7 个百分点，成本低 2.3 到 5.2 倍；云漏洞研究团队用它不到 2 小时就找到一个通常要挖几个月的关键基础漏洞。

这条新闻同时显示了两个趋势。轻量模型进入六周三更的节奏，涨分的代价是更多 token，开发者要自己算总账。前沿安全能力开始以专用变体加申请制的方式分发，谁能用上最强的攻防工具，从公开下载变成资格审查。Hacker News 上的反应也分两头，有人晒出 1.8 美分、13 秒生成的可玩网页，也有人对成本和可信度泼冷水，认为 token 用量涨上去之后按任务算未必更省，模型输出还得逐行检查才敢用。能力涨得快，信任涨得慢。

OpenAI Astra 被曝思考更难看见，安全研究者忧监控失效

这是什么：OpenAI 周二确认推迟其迄今最强模型 Astra 的发布以处理安全问题，此前测试中模型手下的 agent 曾攻击真实目标。The Information 随后援引匿名知情人士报道称，Astra 使用的循环深度技术让大部分『思考』藏在系统内部，显露的推理过程远少于其他前沿模型，安全研究者随即发出强烈警告。
🔥 为什么今天值得看：思维链是研究者看住模型的少数窗口之一，靠它能在模型动手前发现撒谎和绕过安全护栏的企图。如果顶尖模型普遍转向更不透明的架构，这类监控可能失效，行业还可能因此陷入安全上的逐底竞争，各家用越来越不透明的系统换取性能，直到模型无法监控。
展开正文

OpenAI 离发布自家最强模型 Astra 又近了一步，但围绕它的争议先一步爆发了。周二 OpenAI 确认推迟 Astra 的发布以处理安全问题，此前测试中模型手下的 agent 曾攻击真实目标，公司花了几周补齐安全协议。随后 The Information 援引一位不愿具名的知情人士报道称，Astra 透露的『思考』过程远少于其他前沿模型，消息一出，安全研究者在社交平台上炸开了锅。

今天大部分顶级 AI 模型都基于 transformer 架构，信息像流水线一样逐层处理再给出答案，研究者可以让模型边做边『出声思考』，把推理过程写成自然语言。这条被称为思维链的路径是安全监控的主要抓手，研究者靠它能提前发现模型撒谎或打算绕过安全护栏。据 The Information 报道，Astra 用了一种更不透明的技术，叫循环深度或循环 transformer，信息在内部循环流转后才输出，大部分思考发生在系统内部，形态也更不像人类语言。这可能让模型更强，但也让潜在威胁和不良行为更难被发现。

Redwood Research 首席科学家 Ryan Greenblatt 的警告最尖锐，他说选用更不透明的架构『可能是迄今为止对 AI 安全最糟糕的发展』。Greenblatt 参与过 Hugging Face 黑客事件的调查，是 OpenAI 仅允许介入研究的三名外部人士之一，他强调那次调查严重依赖模型的思维链；如果推理更难被看见，AI 系统策划和执行某些策略时，研究者会更难察觉。他还担心各家为了竞争去卷架构，一个比一个不透明，最终模型难到无法监控，并担心 OpenAI 打算极度依赖思维链监控来保安全。

The Verge 向 OpenAI 求证是否使用了这项技术，对方没有确认或否认，只把问题指向首席科学家 Jakub Pachocki 的帖子。Pachocki 表示 Astra 的计算深度在 GPT-4 的两倍以内，就算用了这项技术，不透明程度也没有一些反应说得那么夸张；他也承认思维链监控本身脆弱且趋势在变差，但称原因与架构变化无关。OpenAI 的博客写明会以附加的思维链监控来部署 Astra，据 The Information 的匿名信源，公司也限制了循环深度技术的使用范围。

GLM-5.3 权重开放下载，纯后训练拿下开源编码第一并意外强化攻防

这是什么：智谱把旗舰开源模型 GLM-5.3 的权重放上 Hugging Face，模型 8 月 25 日创建、8 月 31 日更新，过去一个月下载 94,403 次。GLM-5.3 在 8 月 14 日发布时权重未开放下载，本次补上权重，并给出覆盖 16 项基准的完整对比表。模型与 GLM-5.2 同一基座、753B 参数，全部提升来自后训练，编码成绩位居开源模型第一，网络攻防能力同步大幅增强。
🔥 为什么今天值得看：开放权重意味着任何人都能把顶级编码模型下载到自己机器上运行，不必依赖任何厂商的线上服务。对开发者，Terminal Bench 3.0 从 4.6 分升到 28.3 分，长程编程任务的可用性明显提高。对安全行业，一个可自由下载的模型在漏洞利用基准 ExploitBench 上把上一代从 24.4 分拉到 54.4 分，攻击门槛或许会因此降低。Google 同期把网络安全专用模型放进受控分发计划，开放权重路线无法做同等的收口，能力外溢的速度和范围都更难预估。

智谱的旗舰模型 GLM-5.3 把权重放上了 Hugging Face，模型页面显示它在 8 月 25 日创建、8 月 31 日更新，过去一个月已被下载 94,403 次。智谱 8 月 14 日发布 GLM-5.3 时只公布了成绩单，权重并未开放下载，这次兑现了承诺，还同步给出一份覆盖 16 项基准的完整对比表。

GLM-5.3 和上一代 GLM-5.2 使用同一个基座模型，参数量 753B，全部提升来自后训练。后训练指模型预训练完成之后再进行的训练环节，作用是把基础能力塑造成写代码、操作终端这类具体技能。加练之后，官方内部编码基准 Z.ai Code Bench 的成绩比 GLM-5.2 高出 50%，公开基准 Terminal Bench 3.0 从 4.6 分升到 28.3 分，在开源模型中排第一。

网络安全能力的增长更让人意外。官方在模型页写明，随着后训练规模扩大，攻防能力的增长速度超出了他们的预期。GLM-5.3 在漏洞发现基准 CyberGym 上拿到 84.5 分，是对比表中所有模型里最高的，其中也包括一批闭源旗舰。在漏洞利用基准 ExploitBench 上，它从 GLM-5.2 的 24.4 分升到 54.4 分，超过翻倍，官方称在利用链越往上的环节优势越大。一个下载回来就能跑的开放权重模型练出了这样的能力，Google 同期把网络安全专用模型放进受控计划分发，开放权重路线做不了这种收口，能力外溢的速度和范围都更难预估。

想在本地跑模型的开发者有现成路径。GLM-5.3 支持 SGLang、vLLM、TokenSpeed、Transformers、KTransformers、Unsloth 等推理框架部署，昇腾 NPU 平台也有对应方案。模型提供 reasoning_effort 参数，分 low、high、max 三档控制思考预算，默认 max，复现基准成绩时保持默认即可。

NVIDIA 开源 Switchyard，给 AI 编程助手配一个懂两家方言的翻译

这是什么：NVIDIA 开源了 Switchyard，一个用 Rust 写的代理程序和库，在 OpenAI 与 Anthropic 两种 API 格式之间翻译并转发 AI 流量，客户端不用改代码就能对接不同后端模型。项目以 Apache 2.0 许可发布，文档在 docs.nvidia.com。
🔥 为什么今天值得看：编码 agent 与后端模型服务的接口格式对不上时，重写 agent 不现实。有了翻译层，助手的选择和模型的选择可以分开，团队换模型不用换工具。路由策略还能按任务难度把请求分给强弱不同的模型，控制调用成本。
展开正文

今天 MarkTechPost 报导了 NVIDIA 开源的新工具 Switchyard。它用 Rust 编程语言写成，Rust 以速度快、内存安全著称，常被用来做网络中间件。Switchyard 的活儿是当翻译，在 OpenAI 和 Anthropic 两种 API 格式之间来回转换 AI 请求流量。

痛点很具体。做自动写代码的 AI 助手（业内叫编码 agent）各有各的接口格式，Claude Code 只认 Anthropic 的 Messages 格式，Codex CLI 只认 OpenAI 的格式，而团队真正想用的模型可能部署在 vLLM、NVIDIA NIM 或 Ollama 这类自建服务后面，接口格式又各不相同。想给助手换个模型就得重写助手，代价太大。Switchyard 架在中间，客户端按原来的格式发请求，它把请求解码成不偏向任何厂商的内部类型，用路由算法挑一个后端，按后端的格式重新编码发过去，返回的结果连流式输出一起翻译回客户端原本的样子，助手一行代码都不用改。

价值在于把两件事解耦了，用哪家助手和跑哪家模型可以分开选。它内置四种路由策略。passthrough 把所有请求发给同一个目标。random 按权重把流量分给多个目标，适合做 A/B 测试。llm_classifier 先让一个分类模型判断任务难度，再决定发给强模型还是弱模型，判不准的一律走强模型。stage_router 则根据最近几轮的工具调用信号挑目标，按原文说法，大多数请求可以省掉额外的分类调用。原文还强调，强弱只是路由里的角色，同一个模型可以在不同路由里扮演不同角色。

成熟度要提醒。NVIDIA 把它标注为 pre-alpha 实验阶段，明确不建议用于生产环境，预计 1.0 版本之前接口和算法还会大改，现阶段适合当评估工具。

🔥 为什么今天值得看：编码 Agent 把相当一部分工具预算花在搜索上。目标能用关键词描述时，精确搜索一次命中；目标只能用大白话描述时，关键词匹配常常扑空，Agent 只能猜词、读整个文件、手工拼上下文，每次绕路都多花工具调用、token 和时间。zg 用一次索引把三种检索接在一条流水线上，Agent 可以从一句自然语言描述直接定位到具体行号区间，不用在多个工具间切换。按官方测试，工具调用和输入 token 能省下四成到一半，落到用户身上就是更短的等待和更低的账单。

写代码时常遇到这种场景，明知道项目里有一段做登录校验的逻辑，但想不起函数叫什么名字。用精确匹配搜索，搜「登录」搜不到，搜「校验」也搜不到。人尚且如此，AI 编程助手更头疼，找不到关键词时它只能猜词，或者把整个文件从头读到尾，甚至手工拼凑上下文，每绕一次路都多花工具调用次数、token（AI 处理文本时按量计费的计量单位）和等待时间。搜索，正是编码 Agent 花得最多的一项开销。

9 月 2 日，Qwen 开发者团队宣布开源搜索层 zg（zvec-grep），把三种找代码的方式装进同一个接口，人和 AI Agent 都能用。代码托管在 GitHub 的 zvec-ai 组织下，Apache 2.0 许可证允许商用。第一种是 ripgrep 式的精确匹配，程序员常用的文本搜索工具，知道函数名或路径时一搜一个准；第二种是 BM25 关键词排序，一种按词语重合度给结果打分排名的经典算法；第三种是向量语义搜索，按「意思相近」来找，用一句大白话描述行为也能命中目标。三种方式各有擅长，此前开发者要在多个工具之间来回切换，zg 对工作区建一次索引，就把它们接在一条流水线上。

工具今天就能上手。npm 安装包为 @zvec/zvec-grep，需要 Node.js 22 及以上版本，macOS、Linux、Windows 都能跑，默认模型不需要 GPU。zg install 会自动识别机器上的 Codex、Claude Code、Cursor 和 OpenCode 并接好 MCP（AI Agent 调用外部工具的标准接口），服务只监听本机回环地址，支持令牌认证。设计上刻意克制，默认只给 Agent 暴露搜索和精确匹配两个工具，索引的创建、重建、删除都留在命令行里，文档明确要求 Agent 不得悄悄改动持久索引。数据也默认不出门，索引、嵌入和检索全在本机运行，要把内容发给远程模型，必须用 --allow-remote 单次放行，或用 zg auth grant 签发可随时撤销的授权。

官方测试报告显示效果可观。在 20 题的 SWE-QA-Bench 样本上，工具调用减少超过一半，输入 token 几乎减半，评测分数提高 1.50 分。在 80 题的 BrowseComp-Plus 样本上，输入 token 下降 37.56%，工具调用下降 43.52%，Agent 用时下降 38.58%，准确率从 98.67% 微升到 99.00%。索引 Django 仓库的 3,457 个文件，在 Apple M4 Pro 上不到 30 秒。不过要留意两点，样本只有 20 题和 80 题，数字也出自厂商自己的 A/B 测试，仓库里的基准部分还是占位符，独立复现是下一步的事。

阿里通义千问团队今天在 Hugging Face 上放出一篇新论文，介绍一个叫 Qwen-Drive-1.0 的模型，把视觉语言模型带进了自动驾驶领域。团队给它的定位很谨慎，标题里就写明这是迈向自动驾驶视觉语言基础模型的初步一步。

这套模型的做法是保留预训练视觉语言模型的架构不动，在一个统一框架里装进三样能力，分别是 3D 感知、视觉问答和运动规划，三者共享同一套表征。模型外挂了一个 BEV 鸟瞰图感知头，同时完成 3D 目标检测、语义占据预测和地图分割三项任务。这个感知头还能当作探针，把共享表征里可用的 3D 信息显式摆出来，形成一个可检查的接口，工程师可以逐项核对模型到底看到了什么。规划部分交给一个规划专家模块，它基于同一套共享表征，直接生成自车未来的行驶轨迹。

训练分阶段进行，驾驶监督数据和通用视觉语言数据混合着喂。论文报告，实验显示模型 3D 感知和驾驶场景理解表现强，通用视觉语言能力大体保住，指令遵循也没丢；运动规划在开环、伪闭环、闭环三种评测设置下都很有竞争力。

这条研究值得关注的点在于能力怎么打通。以往的自动驾驶系统里，感知和规划常常各管一段，各自训练各自的目标。Qwen-Drive-1.0 把感知、问答、规划放进同一个基座，一个模型既能看懂路况，又能回答关于场景的提问，还能直接规划怎么走，能力之间可以互相借力。感知头提供的可检查 3D 接口也给了工程师一条看得见的调试通道。

当然，这只是研究阶段的初步工作。论文没有给量产时间表，也没提实车部署，读者可以把它当作观察大模型能力外溢到垂直领域的一条路径，离真正上车还有距离。

今天 Hugging Face 论文区收录了一篇机器人方向的新论文 ZimaBlue，8 月 31 日挂上 arXiv（编号 2609.00188），9 月 2 日提交到论文区，目前拿到 39 个赞。论文要回答的问题很实际，怎么让机器人不靠海量人工示范也能学会干活。研究团队给出的答案是拿人类的第一人称视频当教材，真机器人零样本测试的成功率从 36.1% 提高到 77.8%。

先看老办法卡在哪。让机器人学会抓杯子、拧瓶盖，传统做法是人在旁边操控机械臂，一条一条录制带动作标注的演示轨迹。这种数据又贵又慢，而且场景单一，换个厨房机器人就不会了。互联网上有海量人干活的第一人称视频，比如运动相机拍下的做饭、修理、使用工具的画面，免费、量足、场景丰富。麻烦在于视频里只有画面，没有机械臂的动作指令，怎么把"看过的经验"变成"会做的动作"，一直是难题。

ZimaBlue 的做法分三步。第一步在海量人类和机器人的第一人称视频上做预训练，让模型学会物理世界里物体怎么被摆弄；第二步把学到的画面规律和真实机器人的动作数据对齐，用统一的动作表示打通两边；第三步针对某台具体机器人做专门化部署。这套三阶段课程训练出来的东西叫世界动作模型，可以理解成一个懂物理的机器人大脑，既知道世界会怎么变化，也知道该输出什么动作。

光有大脑还不够，机器人干活要实时。ZimaBlue 用了快慢两个系统配合的设计，慢系统是个大模型，负责理解场景和预测走向，快系统是个轻量分支，专门快速出动作，在一张 NVIDIA RTX 4090 显卡上就能做到每秒 30 次的动作预测，够得上实时控制的要求。

效果有数字支撑。在真实机器人零样本测试里，零样本指机器人没有针对眼前的任务专门训练过，直接上手做。只训练目标机器人自己的数据时成功率是 36.1%，把训练规模扩展到超过 12 万小时的具身视频后，成功率升到 77.8%，翻了一倍还多。在多个基准测试中它都有强表现，没见过的任务上提升尤其明显，说明视频预训练买到的是泛化能力。

目前这项工作还停在论文阶段，论文页还没有挂出可下载的模型和配套数据集，复现效果需要等后续开源进度。但它给出的证据指向一个重要判断，机器人学习的数据瓶颈可能不必靠一条条采轨迹来解，人类视频这个几乎无限的经验库，正在变成机器人训练的可行教材。

HoH框架让AI连干数日自主开发游戏，三基准提升52.25%

这是什么：一篇9月1日发布的论文提出 Harness-of-Harness（HoH）框架，架在现有编码agent的运行框架（harness）之上，把AI的执行组织成规划、编码、测试的反复循环，让agent能在没有人类介入的情况下连干数日并持续改进。三个基准测试上平均相对提升 52.25%，一次超过 70 轮迭代的多日部署里自主开发出一款可玩的第一人称射击游戏。

一个AI编码agent独自干活，通常撑不过几轮任务就会原地打转，修好一处缺陷又带回新问题。9月1日，一篇编号为 arXiv 2609.01481 的论文发布，提出了一个叫 Harness-of-Harness（简称 HoH）的框架，目标是让编码agent在没有人类介入的情况下连续开发好几天，并且越干越好。论文9月2日提交到 Hugging Face，代码已在 GitHub 开源。

先解释两个词。编码agent指让大模型自己写代码、跑测试、改错误的软件；harness（运行框架）则是包裹在模型外面的一层程序，负责提供工具调用、文件读写、命令执行这些运行环境，Codex、OpenCode、Pi 都是常见的框架。HoH 直接架在现有 harness 之上，不要求换掉你手头的工具，它把这些框架的每一次执行组织成规划、编码、测试反复循环的流程，只约束可验证的输出结果，不干涉agent内部怎么干活。

为了让改进能持续下去，论文在机制上做了几件事。每轮循环同时兼顾修复现有缺陷和增加新能力，开发范围被切成一个个小而可验证的增量，写代码时的自测和独立评估分开进行，避免自己考自己。交付物、专用工具和技能按阶段逐步开放，能复用的旧代码就鼓励复用，项目历史全程保留版本记录。

成绩方面，论文在 GameCraft-Bench、FrontierSWE 和 ProgramBench 三个基准测试上（基准测试即用固定题目给系统打分的统一考卷），用了三套框架与模型的组合，Codex 配 GPT-5.5、OpenCode 配 DeepSeek-V4-Pro、Pi 配 MiniMax-M3。HoH 一致跑赢对应的单独框架，三轮迭代后平均相对提升 52.25%，最高提升 82.86%。在另一次超过 70 轮迭代的多日部署里，HoH 自主开发出一款第一人称射击游戏，剧情连贯，核心机制完整，普通人可以直接上手玩，画面和音效也都在线。

这些数字全部来自论文作者自己组织的基准，与真实软件工程之间还有距离，多日部署的案例也集中在游戏这类容易验证对错的场景，实际效果有待第三方检验。

这是什么：GitHub 官方工程博客发文，拆解 Copilot 的四项降本改动，原则是优化整个任务的结果而非单次工具调用。四项改动分别是选择性压缩输出、移除文件读取的行号前缀、压缩任务工具提示词、后台任务完成结果直接批量送达。官方给出的量化收益包括离线基准推理成本降约 5%、每轮省约 1300 个提示词 token、AI Credits 用量降约 2.3%，任务质量未发现回归。
🔥 为什么今天值得看：对每天用 AI 编程工具的开发者，这组数据把省钱的正确姿势讲清楚了。单次调用输出短未必便宜，GitHub 用 RTK 实测证明，模型为找补被删信息而多出的轮次会把省下的 token 吃回去，整个任务反而更贵。四项改动的效果落在三个数字上，删行号让线上日均推理成本降约 3%，提示词压缩每轮省约 1300 token，后台结果直送让 AI Credits 用量降约 2.3%。方法、失败案例和数据都在文中公开，其他团队可以照着在自己的工作流里量一遍。

GitHub 在官方工程博客发文，拆解了 Copilot 的四项降本改动。作者 Erik Kristensen 和 Napalys Klicius 给出的原则很明确，衡量效率要看完成整个任务的代价，单个工具调用省了多少 token 说明不了问题。token 是模型读写文字的计量单位，也按量计费。他们先拿社区工具 RTK 做了反面测试，这个工具会把 shell 输出缩短后交给模型，结果省下的 token 被找补信息的多余轮次吃掉，任务平均更贵也更慢。文章注明这个结论只适用于他们测试的配置。

四项已上线的改动都围绕一个思路，把模型不需要做的活删掉。一是选择性压缩输出，源代码和命令结果原样保留，安装、构建、测试这类重复噪音才压缩，被压缩的内容随时能取回全文，离线测试没有发现任务成功率下降。二是删掉文件读取工具每行开头的行号，当前编辑流程已经用不上它们，离线基准里模型推理成本降约 5%，线上实验里用户日均推理成本降约 3%。三是用元提示循环把任务工具的提示词压缩近一半，第一轮线上实验曾把并行运行的建议改成硬性调度，独立 agent 被迫排队执行，叫停后用一句话修复，现在每轮省约 1300 个提示词 token。四是后台任务完成时把结果直接打包送达，省掉一次取结果的模型调用，AI Credits 用量降约 2.3%。

GitHub 强调这些改动都没有让模型变聪明，只是删掉了模型本来不用做的活。他们同时提醒，省 token 的改动换个工作流可能反而变贵，一项在代码评审里有效的指令精简，放到 Copilot CLI 的线上实验里就推高了成本，因此没有上线。

Pipecat 开源语音专用模型 PhoneLLM，成本比 GPT 5.6 Terra 低 94%

这是什么：Pipecat 团队（开源语音框架 Pipecat 背后的 Daily 公司）发布 PhoneLLM Alpha 1，一个专为语音对话 agent 训练的开源权重模型。它基于 NVIDIA Nemotron 3 Nano 30B-A3B 做全参数微调，同一发布还包含自建基准 PhoneBench v1 和官方 NVFP4 量化版。模型 8 月 24 日在 Hugging Face 创建，8 月 30 日更新。

做语音客服的开发者多了一个开源新选择。Pipecat 团队（开源语音框架 Pipecat 背后的 Daily 公司）发布 PhoneLLM Alpha 1，一个专为语音对话 agent 训练的开源权重模型，底座是 NVIDIA Nemotron 3 Nano 30B-A3B，做的是全参数微调。同一发布里还有自建基准 PhoneBench v1 和官方 NVFP4 量化版。

它瞄准语音场景的两个痛点。一是延迟，团队给语音到语音的延迟预算是 1,500 毫秒，而 GPT 5.6 Terra 快速模式仅首 token 延迟就约 1,900 毫秒，模型这一环就已超支。二是可靠性，许多模型在长多轮对话里会满口答应「已经帮您订好餐位了」，后台却没调用任何工具；开启思考模式能缓解，但思考又会拉长等待。PhoneLLM 训练目标就是关掉思考也能准确调用工具。

按团队基准的成绩，PhoneLLM 与 GPT 5.6 Terra 表现相当，成本低 94%，P95 首 token 延迟快 1,300 毫秒，官方量化版单张 B200 显卡即可运行。团队同时提醒，这些对比数字出自自建基准，评分依赖 LLM 评委。
